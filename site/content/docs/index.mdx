Streamsy is an Effect 4 implementation of the [Durable Streams](https://durablestreams.com/) protocol. Write application logic against typed stream services, then choose where streams live and how they are served by swapping Effect Layers:

- Declare typed byte, JSON, [Durable State](/docs/streams/durable-state), or [wake](/docs/streams/wake) streams with Effect `Schema`.
- Create, read, follow, fork, and conditionally append with typed Effect errors.
- Back streams with swappable storage Layers—in memory, SQLite (Bun, Node, Deno, or Cloudflare Durable Objects), Postgres, or MySQL.
- Derive state, tables, and output streams with checkpointed [Projections](/docs/projections) and incremental relational [Views](/docs/views).
- Serve the official Durable Streams HTTP protocol and read-only app routes on Bun, Node, Deno, or Cloudflare Workers, and consume them from Effect or browser clients.

## Quick start

Install `@streamsy/core` and Effect 4:

```sh
bun add @streamsy/core effect
```

Declare a typed stream, run an Effect program against it, and provide `MemoryStorage.layer`:

```ts
import { Effect, Schema, Stream } from "effect";
import { MemoryStorage, Streamsy } from "@streamsy/core";

class Notes extends Streamsy.json<Notes>()("App/Notes", "notes", {
  params: {},
  schema: Schema.Struct({ text: Schema.String }),
}) {}

const program = Effect.gen(function* () {
  const notes = yield* Notes;
  yield* notes.create({});
  yield* notes.append({}, [{ text: "hello" }]);
  return yield* notes.read({}).pipe(
    Stream.flatMap((batch) => Stream.fromIterable(batch.items)),
    Stream.runCollect,
  );
});

// Returns [{ text: "hello" }]
await Effect.runPromise(program.pipe(Effect.provide(MemoryStorage.layer(Streamsy.group(Notes)))));
```

`program` depends only on the `Notes` service. To persist to SQLite, Postgres, MySQL, or a Durable Object—or talk to a remote Streamsy server over HTTP—swap `MemoryStorage.layer(...)` for `BunStorage.layer`, `SqlStorage.layer`, `DurableObjectStorage.layer`, or `RemoteStreams.layer` without changing `program`. See [Choose storage](/docs/storage).

## How the pieces fit together

![Streamsy architecture. Application programs, HTTP routes, Projections, and Views depend on typed stream services from @streamsy/core. Those services are backed either by a local storage Layer (Memory, SQLite, Postgres, MySQL, or Cloudflare Durable Objects) or by RemoteStreams.layer over HTTP to a remote server. Runtime hosts from @streamsy/serve run the stack on Bun, Node, Deno, or Cloudflare Workers and Durable Objects.](/docs/overview-architecture.svg)

All five `@streamsy/*` packages share one version and require Effect 4:

| Package                                                      | What it gives you                                                                    |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------ |
| [`@streamsy/core`](/docs/reference#streamsycore)             | Protocol, typed stream classes, `MemoryStorage`, `Http.routes`, and `RemoteStreams`  |
| [`@streamsy/storage`](/docs/reference#streamsystorage)       | `SqlStorage` (SQLite, Postgres, MySQL), `BunStorage`, and `DurableObjectStorage`     |
| [`@streamsy/projection`](/docs/reference#streamsyprojection) | Checkpointed projections, `FoldByKey`, `StateTable`, and attached runners            |
| [`@streamsy/views`](/docs/reference/views)                   | Incremental relational `View.circuit` projections and in-memory `View.live` readers  |
| [`@streamsy/serve`](/docs/reference#streamsyserve)           | Application read routes, Bun/Node/Deno process hosts, and Cloudflare Durable Objects |
