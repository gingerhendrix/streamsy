A projection is a named, typed, checkpointed consumer of one or more input streams. It reads a slice of each input, runs an Effect handler over that unit, and commits a checkpoint so a restart resumes where it stopped. A fused handler can keep optional fold state through [`Projection.fold` and State](/docs/projections/projections#state), in the same owner transaction as the checkpoint.

The kernel is one pass, repeated: restore the checkpoint, read every input in declaration order, run the handler over one unit, commit the checkpoint. `@streamsy/projection` ships two forms of that pass.

- `Projection.make` is the fused form. The handler runs inside the checkpoint owner's transaction, so writes through that owner, a stream on the same storage or SQL through the shared client, commit or roll back together with the checkpoint.
- `Projection.stream` is the stream-output form. The handler returns items, the kernel pins the unit's input ranges in the checkpoint, then appends the items to an output stream under a producer tuple. A retry reproduces the pinned ranges and sends the same tuple, so the output sees each unit once even when the output lives on another backend.

## Inputs, unit, checkpoint

Inputs are a map of names to `StreamRef` values. `input: ref` is sugar for `inputs: { input: ref }`. Every pass hands the handler one slice per declared input, empty or not, and a `Unit` that names the projection and the non-empty ranges of this pass. The checkpoint stores the accepted offset per input, keyed by the same names, and for the stream form the pending pin and producer sequence.

## Fact streams and state streams

A fact stream records what happened. Each message is a domain event, appended once and never rewritten. It is the source of truth, and every other stream can be rebuilt from it. Declare it with `StreamRef.json` and an event schema.

A state stream carries the current value of keyed rows. Its items are Durable State change events, and a browser reads it with `@durable-streams/state`. Declare its ref with the row schema of the events the projection writes.

```json
{
  "type": "order",
  "key": "o-17",
  "value": { "orderId": "o-17", "sku": "A1", "status": "shipped" },
  "headers": { "operation": "upsert" }
}
```

A state stream is a projection of the facts. A rebuild from the facts writes a new generation of it. See [Durable State](https://durablestreams.com/durable-state).

## Serve

`Serve.stream`, `Serve.state` and `Serve.document` publish streams, Durable State changes and documents as route layers; see [Serve](/docs/projections/serve). `@streamsy/serve/action` delivers external effects.

## A minimal projection

```ts
import { Effect, Schema } from "effect";
import { StreamRef, Streams } from "@streamsy/core";
import { Projection } from "@streamsy/projection";

const numbers = StreamRef.json("numbers", { schema: Schema.Finite });
const doubled = StreamRef.json("doubled", { schema: Schema.Finite });

export const minimal = Effect.gen(function* () {
  yield* Streams.create(numbers);
  yield* Streams.create(doubled);
  yield* Streams.append(numbers, [1, 2, 3]);
  const projection = Projection.make({
    id: "doubled",
    input: numbers,
    process: (batch) =>
      Streams.append(
        doubled,
        batch.input.items.map((n) => n * 2),
      ),
  });
  return yield* Projection.run(projection, { limit: 10 });
});
```

One run over `layerMemory()` from `@streamsy/projection/memory` yields `[2, 4, 6]` on `doubled`. Compiled source: `packages/projection/src/examples/minimal.ts`.
