`@streamsy/views` declares keyed relations as data. Declarations and engine steps do no I/O.

| Entry                                | Contents                                    |
| ------------------------------------ | ------------------------------------------- |
| `@streamsy/views`                    | Relation declarations and the plan compiler |
| `@streamsy/views/ir`                 | JSON plan, expression, and row change types |
| `@streamsy/views/engine`             | Incremental maintenance                     |
| `@streamsy/views/engine/conformance` | A full-recompute reference for engine tests |

## Declare a source

```ts
import { Schema } from "effect";
import { selectors, source } from "@streamsy/views";

export const OrderRow = Schema.Struct({
  orderId: Schema.String,
  customerId: Schema.String,
  total: Schema.Finite,
  status: Schema.Literals(["placed", "shipped"]),
});
export type OrderRow = typeof OrderRow.Type;

const x = selectors<OrderRow>();

export const orders = source("shop.orders", {
  schema: OrderRow,
  schemaRef: { name: "shop.OrderRow", version: 1 },
  key: "orderId",
  mode: "state",
  partitionBy: x.row.customerId,
});
```

| Option        | Value                                                  |
| ------------- | ------------------------------------------------------ |
| `schemaRef`   | The row schema name and version. The plan carries it   |
| `key`         | The row key                                            |
| `mode`        | `facts` for events, `state` for keyed rows             |
| `partitionBy` | The field that keeps rows together for `top` and joins |

## Build a relation

```ts
import { from, view } from "@streamsy/views";

export const openOrders = view(
  "shop.open-orders",
  { schema: OrderRow, schemaRef: { name: "shop.OrderRow", version: 1 }, key: "orderId" },
  from(orders)
    .where(x.row.status.eq("placed"))
    .top({ by: [x.row.total.desc(), x.row.orderId.asc()], limit: 50 }),
);
```

| Operator                        | Does                                                   |
| ------------------------------- | ------------------------------------------------------ |
| `from(source)`                  | Starts a relation                                      |
| `where`                         | Filters rows                                           |
| `select`                        | Maps rows                                              |
| `join`, `leftJoin`              | Joins two relations                                    |
| `groupBy().aggregate()`         | Groups and aggregates                                  |
| `top`                           | Keeps the first rows. The last sort term must be a key |
| `reduceByKey({ key, reducer })` | Folds a fact source into one row for each key          |

Expressions come from `selectors<Row>()`.

## Define a view with parameters

```ts
import { defineView, parameter } from "@streamsy/views";

export const ordersForCustomer = defineView({
  name: "shop.orders-for-customer",
  params: {
    customerId: parameter("customerId", Schema.String),
    limit: parameter("limit", Schema.Int, { maximum: 100 }),
  },
  schema: OrderRow,
  schemaRef: { name: "shop.OrderRow", version: 1 },
  key: "orderId",
  query: (params) =>
    from(orders)
      .where(x.row.customerId.eq(params.customerId))
      .top({ by: [x.row.total.desc(), x.row.orderId.asc()], limit: params.limit }),
});
```

`changes(relation)` declares the change stream of a relation. The host writes it to a stream and publishes it with [`Serve.stream`](/docs/http/serve).

## Check the plan

```ts
import { Effect } from "effect";
import { checkPlan, planHash } from "@streamsy/views";

const checked = Effect.gen(function* () {
  const { plan, hash } = yield* checkPlan(openOrders);
  return { plan, hash, sameHash: hash === planHash(openOrders.plan) };
});
```

`checkPlan` reports every issue it can find before anything runs. `planHash` identifies the canonical plan, for change detection. It is not a security digest.

## Maintain the view

```ts
import { maintainGraph } from "@streamsy/views/engine";
import type { Change } from "@streamsy/views/ir";

const incoming: Change<OrderRow>[] = [
  {
    kind: "enter",
    key: "o-17",
    after: { orderId: "o-17", customerId: "c-1", total: 25, status: "placed" },
  },
];
const result = maintainGraph({
  plan: openOrders.plan,
  inputs: [{ sourceId: orders.name, changes: incoming }],
});
// result.state, result.changes, result.rows
```

`maintainGraph` takes the plan, the previous operator state, and one batch of source changes. It gives the new `state`, the row `changes`, and the current `rows`. Pass `result.state` to the next call.

The engine accepts complete-row `enter`, `update`, and `exit` changes. The application converts domain events into these changes.

## Persistence

The host stores operator state and rows. For rows, use application tables in a [`Projection.atomic`](/docs/projections/define#atomic-projections) handler, so the writes commit with the checkpoint. When a plan change needs a rebuild, use a new projection generation.
