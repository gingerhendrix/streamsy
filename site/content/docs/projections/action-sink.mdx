---
title: Action sink
description: Deliver external effects at least once through the durable outbox.
---

`@streamsy/serve/action` is unchanged by the route-layer API. `defineActionSink` declares the observed relation, payload codec, handler identity, idempotency key, partition and bounded retry policy. An action delivers an external effect; it does not publish a read route.

`draftsFor` from `@streamsy/serve/action/runtime` creates durable drafts. Enqueue them through `OutboxStore` from `/action/outbox` in the same transaction as the fact that caused them. `createSqliteOutboxBacking` from `/action/sqlite` uses the supplied SqlClient, so enqueue participates in that client's transaction. `migrateOutbox` can create the tables before first use.

Bind the delivery function with `actionSinkHandler`, then run `drain` from `/action/runtime`. A drain walks due entries serially in enqueue order. Handler failures retry on the declared schedule or become dead letters. `/action/errors` owns the typed storage and delivery failures.

Run one drain per lane at a time. The host owns scheduling: a scoped task beside the Bun listener, or an object alarm. There is no scheduler, external queue or cross-process lease. Delivery is at least once; the external recipient must absorb repeat idempotency keys.
