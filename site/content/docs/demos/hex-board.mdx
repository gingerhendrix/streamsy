---
title: Hex board
description: A complete board folded into transactional state, with SQLite restart evidence.
---

The slim `examples/hex-board` package proves persisted fold state. It replays
canonical game events into a board and a move ordinal. `Projection.fold` saves
one state row in the same transaction as the checkpoint; a restarted runtime
reads both and resumes from that cut.

```ts
const boardProjection = (gameId: string) =>
  Projection.make({
    id: "hex-board",
    params: { gameId },
    input: StreamRef.json(`games/${gameId}/events`, { schema: GameEvent }),
    process: Projection.fold(BoardState, initialBoard(gameId), (state, { item }, unit) =>
      stepBoard(state, item, unit.ranges.input.nextOffset),
    ),
  });

const current = Projection.loadState(boardProjection("game"), BoardState);
```

`BoardState` contains the next move ordinal and the schema-typed board. Every
event in a unit shares its source watermark, while move ids use distinct
ordinals that survive restart. The recent-move feed is capped at 40 entries.
The package has no output stream, metadata row, server or UI.

Run the evidence from the repository root:

```sh
bun run build
bun run --cwd examples/hex-board test
```

The SQLite tests cover the 12-event victory game, split after 5 events, and
the 450-event four-player game, split after 400 events. Both reopen the same
file and check zero new items, identical state and a checkpoint at the input
tail, then resume and match a pure fold. The long case checks the exact 40 move
ids and ordinal after restart. A contradictory resolution saves neither state
nor checkpoint. Memory, aggregate-equivalence and schema round-trip tests run
alongside them.

State-size measurement (Bun 1.4.2, file-backed WAL, 3,005 generated events): encoded row
21,599 B final / 22,944 B maximum; state-upsert transaction mean FULL/NORMAL
0.549/0.046 ms at one event per unit, 0.581/0.049 ms at 32 events per unit.
A separate local split measured checkpoint-only commits at 0.4258/0.0098 ms
FULL/NORMAL and checkpoint plus state at 0.5280/0.0597 ms: the marginal state-row
cost is about 0.1022/0.0499 ms. At FULL most of the commit cost is the WAL fsync
that every checkpoint commit pays.
The state-upsert-only timings exclude encoding and checkpoint writes; the full
projection transaction means were 1.340/0.760 ms and 7.547/5.462 ms respectively.

See [projection state](/docs/projections/projections#state) for ownership,
transaction and generation rules. Application row sets belong in application
tables through the shared SQL client; this demo deliberately measures a whole
board stored as one fold value.
