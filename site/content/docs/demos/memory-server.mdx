title: Memory server
description: Try the Durable Streams HTTP protocol against the smallest Streamsy host.
---

This demo serves the protocol from Bun with one process-local memory store. It
is a compact way to inspect create, append, catch-up, conditional read,
long-poll, and server-sent event responses with `curl`.

## Run locally

From the repository root:

```bash
bun install --frozen-lockfile
bun run build
bun run --cwd examples/memory-server start
```

`PORT` defaults to `1337`. The edge mounts streams below `/`; the commands here
use `http://localhost:1337/walkthrough/demo`.

## Curl walkthrough

Create a JSON stream and append an item:

```bash
curl -i -X PUT http://localhost:1337/walkthrough/demo -H 'Content-Type: application/json'
curl -i -X POST http://localhost:1337/walkthrough/demo -H 'Content-Type: application/json' --data '{"type":"hello","n":1}'
```

Catch up from the beginning, then copy the response's `ETag` into a conditional
request:

```bash
curl -i 'http://localhost:1337/walkthrough/demo?offset=-1'
curl -i 'http://localhost:1337/walkthrough/demo?offset=-1' -H 'If-None-Match: <etag>'
```

Wait for an append after the returned offset, or follow with SSE:

```bash
curl -i 'http://localhost:1337/walkthrough/demo?offset=<next-offset>&live=long-poll'
curl -N 'http://localhost:1337/walkthrough/demo?offset=-1&live=sse'
```

The full [example README](https://github.com/gingerhendrix/streamsy/tree/effect/examples/memory-server)
shows the expected status, headers, and body for every step. The
[HTTP runtime guide](/docs/runtime/http) explains the wire contract.

## How it works

The server declares one group, `Streamsy.group(Streamsy.Wildcard)`, so it owns every
stream id. `HttpRouter.serve(Http.routes(streams, { access: "full" }))` runs over
`Memory.layer({}, streams)` and a scoped Bun listener. Lines marked `// ...` are left out.

```ts title="src/index.ts"
const streams = Streamsy.group(Streamsy.Wildcard);
// ...
const runtime = ManagedRuntime.make(
  HttpRouter.serve(Http.routes(streams, { access: "full" }), {
    disableLogger: true,
    disableListenLog: true,
  }).pipe(
    drainOnShutdown(),
    Layer.provide(Memory.layer({}, streams)),
    Layer.provideMerge(
      listener({ port, hostname: "::", idleTimeout: 60, gracefulShutdownTimeout: 1000 }),
    ),
  ),
);
```

Full access allows the create and append steps of the walkthrough. The 60-second idle
timeout allows a 30-second protocol long poll to complete. On shutdown, `drainOnShutdown()`
first answers each parked long poll with 204, as a long-poll timeout does, and ends each
SSE body after its last batch. Clients then reconnect from their last offset. After that,
the runtime closes the store and the listener. The example README also has an offline
smoke test that runs all six flows against a child process.

See [HTTP runtime](/docs/runtime/http) and [Memory](/docs/runtime/storage#memory).

## Limits

- The memory store is process-local. A restart starts with an empty store.
- The server gives full access to every stream id, with no authentication. Use it only on
  your own machine.
- The demo has no persistent storage and no hosted deployment.
