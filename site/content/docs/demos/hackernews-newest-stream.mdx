---
title: Hacker News newest
description: Follow a declared rows output through Serve.state and a Durable Streams browser client.
---

The server polls Hacker News into a JSON source stream. `Projection.outputs`
produces one `Output.rows`, and `Serve.state` publishes it at `/state/newest`.
The React browser reads from `-1` into TanStack DB through `createStreamDB`, then
follows live upserts and key-only deletes.

## Run locally

From the repository root:

```bash
bun install --frozen-lockfile
bun run build
bun run --cwd examples/hackernews-newest-stream dev
```

Open http://localhost:1339. `dev` builds the browser; `dev:api` runs the server
with any existing browser build. `PORT` selects another port. `HN_DB` defaults
to `.data/hackernews.sqlite`; `memory` selects a process-local host.
`HN_NEWEST_LIMIT` defaults to 50, `HN_POLL_INTERVAL_MS` to 60000, and
`HN_PROJECTION_LIMIT` to 10 checkpoint transactions per pass.

`HttpRouter.serve` hosts the page, State route, raw `/streams` protocol routes,
and status/poll API on one scoped Bun listener. They share an origin and need
no CORS middleware. `GET /api/status` reports poll counters, projection health
and checkpoint progress. `POST /api/poll` only polls; the change watcher projects
its source append.

```bash
curl -i 'http://localhost:1339/state/newest?offset=-1'
bun run smoke:hackernews
```

The offline smoke uses the actual browser collection factory with local HN
fixtures. It checks live existing-key upserts, key-only deletes, fresh-session
replay, and checkpoint/output continuity across a SQLite restart. Its newest
membership stays fixed during downtime.

## The projection

The output declaration is:

```ts
outputs: {
  "hn-story": Output.rows(HackerNewsStory, { key: "id", stream: targetStreamId }),
},
```

The raw handler returns an Effect of `{ "hn-story": [...] }`, containing
`Output.upsert(story)` and `Output.remove(key)`. The kernel encodes and pins the
changes. The served route is:

```ts
Serve.state(hackerNewsStoryIndex.outputs["hn-story"], "/state/newest");
```

Source, rows output, checkpoint and `Projection.State` share one Bun SQLite
host. The application creates only the input; a nonempty projection output
creates the target. Before that, an initial State read answers 404 without
creating data. `Projection.onChange` and the poller have scoped lifetimes.

## Replay figure

Batch D2 measured Bun 1.4.2 on Linux x64, SQLite and warm loopback HTTP. Every
poll changed all 50 stories: a worst-case workload, not typical HN traffic.
Each milestone used five fresh sessions and retained 50 current rows. Bytes
are uncompressed JSON bodies across all pages; timings are medians.

| Polls | Retained changes | Pages | Body bytes | Raw replay | TanStack preload |
| ----- | ---------------- | ----- | ---------- | ---------- | ---------------- |
| 100   | 5,000            | 5     | 1,219,205  | 20.7 ms    | 20.8 ms          |
| 1,000 | 50,000           | 50    | 12,289,350 | 137.1 ms   | 120.3 ms         |

Raw replay includes HTTP, decoding and Map application. TanStack preload runs
on Bun; these are not browser or WAN latency figures. At one poll per minute,
1,000 polls span about 16 hours 40 minutes. The same worst case is about 17.7 MB
of replay after one day. Server-side snapshots remain a follow-up; the proposed
trigger is before a rows route runs for about a day without reset, or retains
more than about 100 changes per current row. That scope decision remains open.

## Limits

There is no snapshot. New sessions replay all retained changes, and history
must remain available. A retention cap alone loses rows. After a server reset,
reload the page to open a fresh collection from `-1`; automatic reopening is
not implemented.

The `@durable-streams/state` 0.3.1 binding merges an upsert on a known key. Fields
omitted by a later row keep their old browser values, live and on replay.

The poller's newest-set cache is in memory. A restart publishes fresh upserts
for current stories. A previously emitted story that leaves the set during
downtime stays in the served rows and on the page for good. Poller membership
recovery is a separate follow-up; the restart smoke does not prove it.

Use a fresh database for the phase-5 declaration: earlier checkpoint/output
formats are not migrated. `HN_DB=memory` starts fresh after every restart.
The demo has no hosted deployment; see [Cloudflare](/docs/runtime/cloudflare)
for the host path.
