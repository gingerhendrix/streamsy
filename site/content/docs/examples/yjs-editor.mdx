title: Yjs editor
description: A collaborative ProseMirror editor on Streamsy and Cloudflare Durable Objects, pairing append-only Yjs update logs with expiring awareness streams and alarm-driven snapshot compaction.
---

Open the [live Yjs editor](https://yjs-editor.streamsy.dev) and join the same room in two browser windows. Text, selections, cursors, and display names sync as you edit. The rooms are public, so don't enter private data. Keep editing until a snapshot is built, then open a third window: instead of replaying every stored edit, it fetches one compacted snapshot and catches up with the updates after it. Each room also links to its raw update stream under `/v1/stream`, which you can inspect directly with `curl`.

The full example lives in [`examples/yjs-editor`](https://github.com/gingerhendrix/streamsy/tree/main/examples/yjs-editor), paired with Streamsy's private fork of the Durable Streams Yjs browser client in [`packages/y-durable-streams`](https://github.com/gingerhendrix/streamsy/tree/main/packages/y-durable-streams).

## Two windows editing, then a third joining

![Concept diagram. Peer A posts each Yjs update to the document's .updates stream, and peer B follows that stream with long-polling. Both peers exchange presence through an awareness stream with a one-hour TTL, followed with server-sent events. A compaction fold follows .updates and merges the document into a snapshot after every mebibyte of new updates. A new peer loads the snapshot, then reads only the tail of .updates after it.](/docs/examples/yjs-editor-concept.svg)

Each document uses four kinds of Streamsy stream under `/v1/stream/yjs/:service/docs/:docPath/`: `.updates`, `.snapshots/<offset>_snapshot`, `.awareness/<name>`, and `.awareness-index`.

**Windows one and two sync through `.updates` and `.awareness`.** Each browser runs ProseMirror with `y-prosemirror` and `YjsProvider` from `@streamsy/y-durable-streams`. Local edits produce binary Yjs CRDT updates, which the provider `POST`s to `/v1/yjs/:service/docs/:docPath`. The server appends them to `.updates` as lib0 length-prefixed frames; a producer batch can carry several frames. The other window follows `.updates` with long-polling (`live=true`) and applies each update as it arrives. Because Yjs updates commute, the server never resolves edit conflicts on write.

Cursors, selections, and names travel separately as lib0-framed updates on `.awareness/<name>`, followed over SSE (`live=true`). Awareness streams carry `Stream-TTL: 3600`: an idle stream expires after an hour, and the next `POST` recreates it idempotently. Joining windows do not replay old cursors. Named awareness streams are listed in `.awareness-index` as `{ name, createdAt }` JSON entries so deleting a document removes its updates, snapshot, awareness streams, and fold checkpoint in one transaction.

**Window three joins after a snapshot.** Replaying `.updates` from `-1` gets slower as edits accumulate. Once a background fold has compacted the document, the third window requests `GET ?offset=snapshot`, receives a `307` redirect to `<offset>_snapshot` (or `-1` before any snapshot exists) with `Cache-Control: private, max-age=5`, and reads the merged `Y.encodeStateAsUpdate` payload along with `stream-next-offset`. From there, it tails only the updates after that offset.

Compaction does not prune `.updates`. Update history remains intact for lagging readers, so snapshots reduce transfer and load time for new peers rather than disk usage.

## Background folding, snapshot discovery, and the provider fork

Snapshot creation and snapshot discovery are intentionally decoupled.

**Background folding runs on an alarm.** [`worker/compaction.ts`](https://github.com/gingerhendrix/streamsy/tree/main/examples/yjs-editor/worker/compaction.ts) defines `compaction`, a `@streamsy/projection` fold (`Projection.fold`) over `Updates`. Its `FoldState` keeps only three small values: total folded `bytes`, `pending` bytes since the last snapshot, and the latest `snapshot` offset. When a write commits to `.updates`, a commit hook records a durable pending mark in the same SQLite transaction, and the Durable Object alarm runs the fold off the write request path through `ProjectionWakeup.attach(compaction)`.

When the alarm runs under `Commit.transaction` and `pending` reaches `COMPACTION_THRESHOLD` (code default `1024 * 1024`, or 1 MiB), `publishSnapshot` loads the prior snapshot into a `Y.Doc`, side-reads `.updates` to the log's tail, writes the merged bytes in 1 MiB `SNAPSHOT_CHUNK` messages, removes the previous snapshot, and commits the new snapshot and fold state together. Updates already covered by `state.snapshot` still add to `bytes` but not `pending`, preventing repeated merges across a backlog. Compaction failures leave the committed update intact. The fold is configured for up to five attempts with backoff.

**Discovery reads the checkpoint at request time.** `GET ?offset=snapshot` in [`worker/document.ts`](https://github.com/gingerhendrix/streamsy/tree/main/examples/yjs-editor/worker/document.ts) does no Yjs merging; it reads `snapshot` straight from the fold checkpoint and returns the `307`.

**Why the browser client was forked.** Upstream `@durable-streams/y-durable-streams` 0.2.9 probes `?offset=snapshot` with `redirect: "manual"` and inspects the `Location` header. Browsers return an opaque response (status `0`, no readable headers) for manual redirects, so browser clients silently fell back to replaying `.updates` from `-1`. `@streamsy/y-durable-streams` follows the redirect instead and extracts the offset from the final URL without changing the wire protocol.

## Deployment and implementation entry points

On Cloudflare, [`alchemy.run.ts`](https://github.com/gingerhendrix/streamsy/tree/main/examples/yjs-editor/alchemy.run.ts) deploys one Worker, static assets, and a SQLite Durable Object namespace (`DocumentObject`). Each document ID (`yjs/<service>/docs/<path>`) maps to its own `DocumentObject`, keeping the streams and fold checkpoint together so compaction and document deletion stay transactional.

![Architecture diagram. The browser runs the ProseMirror editor and the YjsProvider from @streamsy/y-durable-streams, and links the raw update stream. A Cloudflare Worker sends /v1/yjs document requests to the DocumentObject named after the document, and /v1/stream reads through router(placement). In the object, the Yjs routes forward to the .updates and .awareness streams and read the compaction fold's state for snapshot discovery and the size budget. Http.routes serves all four streams read-only. The object's alarm runs the compaction fold, which keeps a checkpoint of byte counts and the snapshot offset and publishes a .snapshots stream stored as 1 MiB messages.](/docs/examples/yjs-editor-architecture.svg)

Six files explain the backend:

- [`worker/index.ts`](https://github.com/gingerhendrix/streamsy/tree/main/examples/yjs-editor/worker/index.ts) routes `/v1/yjs/...` requests through `parseDocumentRoute` and `documentId` to the document's `DocumentObject`, forwards `/v1/stream/...` through Streamsy's `router`, and falls back to `env.ASSETS`.
- [`worker/streams.ts`](https://github.com/gingerhendrix/streamsy/tree/main/examples/yjs-editor/worker/streams.ts) and [`worker/placement.ts`](https://github.com/gingerhendrix/streamsy/tree/main/examples/yjs-editor/worker/placement.ts) declare `Updates`, `Snapshots`, `Awareness`, and `AwarenessIndex` and bind all four to the document owner with `Placement.byRoute`.
- [`worker/document.ts`](https://github.com/gingerhendrix/streamsy/tree/main/examples/yjs-editor/worker/document.ts) and [`worker/awareness.ts`](https://github.com/gingerhendrix/streamsy/tree/main/examples/yjs-editor/worker/awareness.ts) wire the Yjs routes onto Streamsy's `Http.app` stream protocol, stripping non-producer headers such as `Stream-Closed` on append so a disconnecting peer cannot close the shared document.
- [`worker/objects.ts`](https://github.com/gingerhendrix/streamsy/tree/main/examples/yjs-editor/worker/objects.ts) assembles `DocumentObject` around `StreamsyObject`, `ProjectionWakeup.attach(compaction)`, and read-only `Http.routes`.

## Limits and upstream differences

- **SQLite and memory bounds.** Durable Object SQLite rejects values above 2 MB, so update appends over 1.5 MiB return `413` and snapshots are split into 1 MiB messages. Compaction also loads the whole `Y.Doc` into the object's 128 MB memory limit. The write budget keeps the demo below the document sizes that exhausted the object during earlier tests.
- **Approximate 8 MiB write budget.** Document `POST` returns `413` (`DOCUMENT_TOO_LARGE`) once folded `bytes` exceeds 8 MiB; reads keep working. Because the budget reads the alarm-updated fold checkpoint rather than the live log tail, writes can land past 8 MiB (a check on the current demo accepted about 8.4 MB before rejecting).
- **Upstream conformance and reconnect behavior.** Against upstream `yjs-conformance.test.ts` (commit `461b4026`, run on local `workerd` with a 1,500-byte threshold), 59 of 68 tests pass, 3 Node-server tests are skipped, and 6 fail. Four expect a `__ds` snapshot subscription API (`404`). The other two use raw writes to simulate TTL expiry or seed a legacy awareness index. The read-only mount refuses those writes (`405`). The forked provider also inherits upstream 0.2.9 [issue #413](https://github.com/durable-streams/durable-streams/issues/413) (producer epoch reuse on reconnect can lose edits), so the UI pauses editing when disconnected until you reload. The demo has no authentication, offline persistence, or room registry; the UI fixes three rooms, though the API accepts other paths.

## Run it locally

Build the workspace packages from the repository root, then run the Worker on local Miniflare/`workerd` (no Cloudflare account required):

```bash
bun install
bun run build
bun run --cwd examples/yjs-editor dev:worker
```

Open `http://127.0.0.1:1340` in two windows, type in either, and inspect the room's linked stream. For local runs, `PORT` (default `1340`) and `YJS_WORKER_STATE` (default `examples/yjs-editor/.scratch/worker`) override the listener and state directory. To reach a snapshot with fewer edits, restart the local worker with `COMPACTION_THRESHOLD=1500 bun run --cwd examples/yjs-editor dev:worker`. Make enough edits to cross 1,500 bytes of updates before opening the third window. The Cloudflare deployment sets its own threshold to 1 MiB in `alchemy.run.ts`. Run the `workerd` integration suite with `bun run --cwd examples/yjs-editor test:worker`.
