---
title: Fold agent
description: A CLI AI agent backed by a Streamsy JSON session log that resumes across crashes and fences competing writers with expectedOffset.
---

When an AI agent runs multi-turn tool loops, keeping conversation history only in memory loses the session on a crash—and letting two processes resume the same session at once corrupts the log with interleaved turns.

Fold agent pairs [Fold Core](https://www.npmjs.com/package/@humanlayer/fold-core) with a Streamsy JSON stream as its durable session log. Any process can inspect or resume a session from SQLite after a crash, and every append passes the writer's last-seen offset as `expectedOffset`—acting as a **fencing token** so a stale process can never keep writing after another process resumes the session.

The full source lives in [`examples/fold-agent`](https://github.com/gingerhendrix/streamsy/tree/effect/examples/fold-agent).

## Run it

From the repository root:

```bash
bun install --frozen-lockfile
bun run build
bun run --cwd examples/fold-agent start "How long is 'hello'?"
```

`start` uses an OpenAI or Anthropic API key, writes the session to `examples/fold-agent/.data/agent.sqlite` (override with `FOLD_AGENT_DB`), and prints the session's stream ID. Resume or inspect a session from a new process:

```bash
bun run --cwd examples/fold-agent resume <stream-id> "What happened?"
bun run --cwd examples/fold-agent inspect <stream-id>
```

To run the cross-process SQLite fencing and CLI tests offline (using the built-in scripted model, no API key needed):

```bash
bun run --cwd examples/fold-agent test:unit
```

## Fencing competing writers with `expectedOffset`

![Architecture diagram. In process A and process B, a Fold session writes through a Streamsy event log. Both event logs append to one session stream with expectedOffset set to the tail they read. The stream is stored in memory or Bun SQLite. When process B appends first, the next append from process A fails and process A is fenced.](/docs/examples/fold-agent-architecture.svg)

Rather than adding distributed locks, the stream's offset check enforces single-writer ownership across processes:

1. **One stream per session.** Each session lives at `fold/sessions/:session/events`, validated by Fold's `SessionId` schema so `Sessions.parse` rejects malformed IDs on `resume` and `inspect`.
2. **Open at the tail.** When `makeEventLog` opens a session (`create` or `resume`), it reads the full log, verifies Fold's sequence numbers, and remembers the stream's tail offset and `nextEntrySeq`.
3. **Conditional appends fence stale writers.** Every append is serialized locally by a `Semaphore(1)` and passes the stored tail as `expectedOffset`. If another process resumed the session and appended first, Streamsy rejects the stale write with [`OffsetMismatch`](/docs/streams/write#conditional-writes). The adapter marks the writer permanently `fenced` before every append and clears it only on success—so after any failed append, the stale writer refuses further writes until the caller opens a fresh writer from the durable log.

## Inside the agent log

Snippet paths below are relative to `examples/fold-agent`. `// ...` marks omitted lines.

### Session stream and swappable storage

`Sessions` binds one JSON stream per `SessionId`, and `storeLayer` swaps transparently between in-memory and Bun SQLite storage:

```ts title="src/session-log.ts"
export class Sessions extends Streamsy.json<Sessions>()(
  "Fold/Sessions",
  "fold/sessions/:session/events",
  { params: { session: SessionId }, schema: Schema.Json },
) {}
```

```ts title="src/storage.ts"
export const storeLayer = (options: StoreOptions = {}): Layer.Layer<Sessions, StorageFault> => {
  const filename = options.filename;

  return filename === undefined || filename === ":memory:"
    ? memoryLayer(options)
    : sqliteLayer(filename, options);
};
```

See [Declare streams](/docs/streams/declare) and [Choose storage](/docs/storage).

### Opening the writer at the tail

The CLI hands `streamsyEventLog` to Fold's `startSession` (or `resumeSession` on `resume`). Opening the log reads the stream to its tail and initializes the local sequence counter, semaphore, and `fenced` flag:

```ts title="src/cli.ts"
const start = Command.make("start", { prompt: promptArgument }, ({ prompt }) =>
  Effect.gen(function* () {
    const model = yield* configuredModel;
    const session = SessionId.create();

    return yield* withStore(
      Effect.scoped(
        Effect.gen(function* () {
          const fold = yield* startSession({
            agent: exampleAgent(model),
            log: yield* streamsyEventLog({ session, mode: "create" }),
            sessionId: session,
            cwd: process.cwd(),
          });

          yield* fold.send(prompt);
    // ...
```

```ts title="src/streamsy-event-log.ts"
export const makeEventLog = (options: StreamsyEventLogOptions) =>
  Effect.gen(function* () {
    const sessions = yield* Sessions;
    // ...
    const history = yield* readHistory(params);
    const decoded = yield* decodeLog(history.items);

    if (options.mode === "resume" && decoded.length === 0)
      return yield* unavailable("Cannot resume a log with no Fold entries");

    let tail = history.offset;
    let nextEntrySeq = decoded.length;
    const lock = yield* Semaphore.make(1);
    let fenced = false;
```

### Fenced appends

Setting `fenced = true` _before_ calling `sessions.append(..., { expectedOffset: tail })` ensures that any failure—whether an `OffsetMismatch` from another process or an unexpected storage error—leaves the writer fenced until a fresh writer reads the committed log:

```ts title="src/streamsy-event-log.ts"
    const append = Effect.fn("Fold.EventLog.append")((input: LogEntryInput) =>
      lock.withPermit(
        Effect.gen(function* () {
          if (fenced) return yield* unavailable("This writer is fenced; resume from the log");
          // ...
          fenced = true;

          const result = yield* sessions
            .append(params, [json], { expectedOffset: tail })
            .pipe(
              Effect.catchTag("OffsetMismatch", () =>
                unavailable("Fenced: another writer advanced the log"),
              ),
            );

          tail = result.offset;
          nextEntrySeq++;
          fenced = false;

          return entry;
```

### Cross-process fencing test

`test/sqlite-restart.test.ts` spawns real worker processes against the same SQLite file to verify that a second process resuming a session fences the first writer on its very next append:

```ts title="test/sqlite-restart.test.ts"
it.effect(
  "a second process that resumes the same session fences the first on its next append",
  () =>
    withTempDir((dir) =>
      Effect.gen(function* () {
        const path = yield* Path.Path;
        const filename = path.join(dir, "agent.sqlite");
        const session = SessionId.create();
        expect((yield* runWorker(["create", filename, session])).exitCode).toBe(0);
        const store = yield* Layer.build(sqliteLayer(filename));

        const first = yield* Effect.scoped(makeEventLog({ session, mode: "resume" })).pipe(
          Effect.provideContext(store),
        );

        const second = yield* runWorker(["append", filename, session, "second process"]);
        expect(second.exitCode).toBe(0);
        // ...
        expect(failure.message).toContain("Fenced: another writer advanced the log");
        expect(
          Array.map(
            yield* readFoldLog(session).pipe(Effect.provideContext(store)),
            (row) => row.seq,
          ),
        ).toEqual([0, 1]);
```

## Going further

### Production notes

- **Full-log replay on open.** Opening a writer reads the entire session stream from the start with no snapshots or retention; long-running agent sessions benefit from checkpointed summaries or compaction.
- **In-flight model calls.** If the process stops after invoking an LLM provider and before committing the turn to the stream, resuming re-runs that turn—in-flight provider calls are not recovered.
- **Strict fencing by design.** A fenced writer never auto-retries or merges; callers explicitly resume from the durable log to take ownership cleanly.
- **Local SQLite only.** This example has no HTTP surface, though the same `Sessions` stream can be hosted remotely over [`RemoteStreams`](/docs/servers/remote) with the exact same `expectedOffset` fencing semantics.
