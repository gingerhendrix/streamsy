---
title: Hex board
description: Fold a strategy game's event stream into a complete board stored inside the projection checkpoint, with SQLite restart recovery and typed integrity checks.
---

Some domain state—a board game with territories, turn order, active combat, and a capped move feed—is rich and structured, yet bounded in size. Rather than designing and migrating application tables for it, you can fold the event stream into a single schema-encoded value persisted directly inside the [projection checkpoint](/docs/projections/state#fold-a-value).

Hex board demonstrates this pattern end to end through its test suite (there is no HTTP server or browser UI). A [`Projection.fold`](/docs/projections/state) replays recorded hex strategy games into a complete `BoardState`, commits the board and input offsets together in one SQLite record, resumes across simulated process restarts, and rolls back cleanly if a contradictory event appears in the log.

The full source lives in [`examples/hex-board`](https://github.com/gingerhendrix/streamsy/tree/effect/examples/hex-board).

## Run it

From the repository root:

```bash
bun install --frozen-lockfile
bun run build
bun run --cwd examples/hex-board test
```

The test suite runs against temporary SQLite files (to exercise real restarts) as well as in-memory storage, replaying both a 12-event victory game and a 450-event four-player game.

## One board, one checkpoint record

![Architecture diagram. A test runtime appends game events to the GameEvents stream. The board projection folds each event with stepBoard. The SQLite file holds state and offsets in one checkpoint record. Projection.read returns the board to the test. A restarted runtime on the same file finds no new items and resumes.](/docs/examples/hex-board-architecture.svg)

Each game lives in one parameterized JSON stream (`games/:gameId/events`), and `board` (`Projection.fold`) folds that stream into `{ ordinal, board }`:

- **No application tables.** With the default [`Commit.checkpoint`](/docs/projections/commits#checkpoint), `CheckpointStore.layer` encodes `BoardState` alongside the input offsets in one row of `streamsy_owner_records`. A restarted process loads that record via `Projection.read` and resumes from the saved offset without replaying earlier events.
- **Deterministic move IDs across restarts.** Every event in a projection unit shares the unit's end offset (`unit.ranges.input.nextOffset`), so offsets alone cannot distinguish individual moves within a batch. Storing `ordinal` inside `BoardState` gives each move a stable, monotonic ID across batch boundaries and restarts.
- **Typed domain rollbacks.** The pure reducer returns `Result<BoardState, ProjectionIntegrityError>`. Lifting that into the Effect error channel with `Effect.fromResult` makes `Projection.run` fail with `ProjectionIntegrityError` on contradictory events—leaving both the saved board and checkpoint offset untouched.

## Inside the fold and restart tests

Snippet paths below are relative to `examples/hex-board`. `// ...` marks omitted lines.

### Stream and fold projection

`GameEvents` declares one JSON event stream per `gameId`, and `board` wraps `stepBoard` in `Projection.fold`:

```ts title="src/board/fold.ts"
/** The next move ordinal survives restart independently of page boundaries. */
export const BoardState = Schema.Struct({
  ordinal: Schema.Int.check(Schema.isGreaterThanOrEqualTo(0)),
  board: ProjectionStateSchema,
});

export type BoardState = typeof BoardState.Type;

export const initialBoard = ({ gameId }: { readonly gameId: string }): BoardState => ({
  ordinal: 0,
  board: initialProjection(gameId),
});

export const stepBoard = (
  state: BoardState,
  event: GameEvent,
  through: string,
): Result.Result<BoardState, ProjectionIntegrityError> =>
  Result.map(projectEvent(state.board, event, through, state.ordinal), (board) => ({
    ordinal: state.ordinal + 1,
    board,
  }));

export class GameEvents extends Streamsy.json<GameEvents>()(
  "HexBoard/GameEvents",
  "games/:gameId/events",
  { params: { gameId: Schema.String }, schema: GameEvent },
) {}

export const board = Projection.fold({
  id: "hex-board",
  params: { gameId: Schema.String },
  inputs: { input: GameEvents },
  state: { schema: BoardState, initial: initialBoard },
  fold: (state, { item }, unit) =>
    Effect.fromResult(stepBoard(state, item, unit.ranges.input.nextOffset)),
});
```

Because `board` has a single input and empty reads never invoke the handler, `unit.ranges.input` is always present. See [Declare streams](/docs/streams/declare) and [State and checkpoints](/docs/projections/state).

### SQLite storage and reading the checkpoint

The test host puts `GameEvents` and `CheckpointStore` in the same Bun SQLite file. `seed` appends the first slice of a game and runs the projection to the tail; `snapshot` reads the materialized state with `Projection.read` and inspects the raw checkpoint record:

```ts title="test/restart.test.ts"
const sqlite = (filename: string) =>
  CheckpointStore.layer.pipe(
    Layer.provideMerge(BunStorage.layer(Streamsy.group(GameEvents), { client: { filename } })),
  );
// ...
const seed = (events: readonly GameEvent[] = fullGame, cut = split) =>
  Effect.gen(function* () {
    yield* (yield* GameEvents).create(params);
    yield* (yield* GameEvents).append(params, nonEmpty(events.slice(0, cut)));
    expect((yield* Projection.run(board)).items).toBe(cut);
  });

const snapshot = Effect.gen(function* () {
  const { state, offsets } = yield* Projection.read(board);
  const checkpoint = yield* (yield* CheckpointStore).load(board);

  return {
    state,
    offsets,
    checkpoint,
    encoded: Option.flatMap(checkpoint.record, (record) => Option.fromUndefinedOr(record.state)),
  };
});
```

See [Use SQLite](/docs/storage/sqlite#bun) and [Running projections](/docs/projections/run).

### Simulating restarts and integrity failures

`asProcess` builds a storage layer inside `Effect.scoped`, runs one program, and tears it down. Calling `asProcess(sqlite(file))` twice on the same SQLite path simulates a full process restart:

```ts title="test/restart.test.ts"
const asProcess =
  <ROut, LE>(fixture: Layer.Layer<ROut, LE>) =>
  <A, E, R>(program: Effect.Effect<A, E, R>) =>
    Effect.scoped(
      Effect.gen(function* () {
        const services = yield* Layer.build(fixture);

        return yield* program.pipe(Effect.provideContext(services));
      }),
    );
```

```ts title="test/restart.test.ts"
baseIt.effect(`SQLite restart retains state and checkpoint, then resumes: ${name}`, () =>
  Effect.gen(function* () {
    const file = yield* tempFile("hex-board-");
    const before = yield* seed(events, cut).pipe(Effect.andThen(read), asProcess(sqlite(file)));
    // ...
    yield* Effect.gen(function* () {
      expect((yield* Projection.run(board)).items).toBe(0);
      expect(yield* read).toEqual(before);
      yield* advance(before, events, cut);
    }).pipe(asProcess(sqlite(file)));
  }),
);
```

The restarted process sees `0` new items and the exact `before` state, then appends the remaining events, catches up, and asserts equality with a pure in-memory fold of the entire log (including all 40 capped move IDs and the final ordinal). A companion test appends a contradictory `AttackResolved` event and verifies that `Projection.run(board)` fails with `ProjectionIntegrityError` without advancing the checkpoint.

## Going further

### Production notes

- **Keep checkpoint values bounded.** Every unit decodes, folds, re-encodes, and rewrites the whole `BoardState`. With the move feed capped at 40 entries, the encoded board stayed bounded at `21,599 B` after 3,005 generated events (`22,944 B` peak)—well suited to single-value checkpoint state. Unbounded collections that grow with history belong in application SQL tables updated through `Projection.process` and `Commit.transaction`. See [State size](/docs/projections/state#size).
- **Schema changes require a new generation.** Because `BoardState` is schema-encoded inside the checkpoint record, incompatible schema changes need a new projection generation. See [Checkpoints and generations](/docs/projections/checkpoints#generations).
- **Fixed offline fixtures.** The suite replays two pre-generated deterministic game logs (`full.json` and `long.json`); the [example README](https://github.com/gingerhendrix/streamsy/tree/effect/examples/hex-board) documents how they were produced.
