title: Folder sync
description: A multi-client file workspace on Bun and Cloudflare Durable Objects, pairing Durable State streams, SHA-256 blobs, wake-driven FTS5 search, a disk mirror CLI, and an agent filesystem.
---

Folder sync is a collaborative file workspace that runs the **same Streamsy application on two hosts**: Bun (SQLite + local disk blobs) and Cloudflare Workers (Durable Objects + R2). Three kinds of clients follow the exact same folder streams:

- A **browser UI** (React + TanStack DB) for live folder browsing, text editing, full-text search, and viewing earlier file versions.
- A **sync CLI** that mirrors selected folders bidirectionally to local disk and resumes queued writes across restarts.
- An **agent filesystem** exposing synced folders to `just-bash` and Better FS Tools, including index-backed `grep --search`.

Instead of locking files or rejecting stale edits, every write records the version it started from as its `parent`. Concurrent edits both land cleanly—the latest append becomes the head, and the folder's stream retains the full branching history.

The full source lives in [`examples/folder-sync`](https://github.com/gingerhendrix/streamsy/tree/effect/examples/folder-sync). Its README covers the complete HTTP contract, environment settings, and Bun vs. `workerd` measurements.

## Run it

From the repository root, start the Bun server with a writer token and SQLite path:

```bash
bun install --frozen-lockfile
bun run build
FOLDER_SYNC_WRITER_TOKEN=local-demo-token FOLDER_SYNC_DB=./folder-sync.sqlite \
  bun run --cwd examples/folder-sync start
```

Or run the Cloudflare Worker locally on Miniflare/`workerd` (persisting Durable Objects and R2 under `.scratch/worker/`, no Cloudflare account required):

```bash
FOLDER_SYNC_WRITER_TOKEN=local-demo-token bun run --cwd examples/folder-sync dev:worker
```

Open `http://localhost:1339` and paste `local-demo-token` into **Writer token** (reads are public; writes require the bearer token). In another terminal, seed the docs folders and start two writable disk mirrors:

```bash
FOLDER_SYNC_WRITER_TOKEN=local-demo-token bun run --cwd examples/folder-sync seed

FOLDER_SYNC_WRITER_TOKEN=local-demo-token bun run --cwd examples/folder-sync sync \
  --server http://localhost:1339 --dir "$PWD/examples/folder-sync/mirror-a" --write docs/root

FOLDER_SYNC_WRITER_TOKEN=local-demo-token bun run --cwd examples/folder-sync sync \
  --server http://localhost:1339 --dir "$PWD/examples/folder-sync/mirror-b" --write docs/root
```

Edit `docs/root/tutorial.mdx` in the browser or either mirror to watch all clients sync live. Leave a browser draft open while a mirror edits the same file, then save the draft—your save lands as the new head, and file history shows both edits sharing the same parent version.

## Streams, versioned blobs, and dual-host search

### Streams

| Stream       | Kind             | Public URL                           | Collection / Key            | Role                                                         |
| ------------ | ---------------- | ------------------------------------ | --------------------------- | ------------------------------------------------------------ |
| `Folders`    | `Streamsy.state` | `/streams/folders`                   | `folder` / `folderId`       | Registry of folder IDs and titles                            |
| `Files`      | `Streamsy.state` | `/streams/folders/<folderKey>/files` | `file` / `path`             | Per-folder versioned file metadata and delete tombstones     |
| `FolderWake` | `Streamsy.wake`  | `/streams/wake`                      | `stream` / source stream ID | Single wake stream indexing the tail of every `Files` stream |

Folder IDs can contain slashes (like `docs/root`), so `Files` encodes `:folderId` as hex UTF-8 (`FolderKey`) in stream URLs while API paths percent-encode the ID as one segment. All three stream routes are served read-only (`405` on direct writes).

### Blob-first writes with parent history

File bytes stay out of the stream logs so replays stay light:

1. **Upload content-addressed blobs first.** Clients upload bytes (up to 64 MiB) to `PUT /api/blobs/<sha256>`. Bun writes and syncs blobs to `<db>.blobs/`; Cloudflare streams directly to R2 with SHA-256 verification.
2. **Commit metadata through `Projection.decide`.** Clients send `PUT` or `DELETE` to `/api/folders/<id>/files/<path>` with `{ txid, author, parent, hash, size }`. `FolderStore` folds `folderView` via `Projection.decide`, verifies the blob exists, checks its 1,024-entry `txid` retry memory (making retries idempotent), skips unchanged hashes, and appends a new monotonic folder `version` (or tombstone upsert with `deleted: true`). `expectedOffset` only serializes appends—it never rejects a stale `parent`.

### Wake-driven FTS5 search across hosts

Search (`/api/search` and `/api/ls`) is powered by a single `Projection.process` (`search`) backed by SQLite FTS5:

- **Two-phase indexing (`prepare` + `process`).** `prepare` streams at most 1 MiB of text per changed blob into a staging table _outside_ the checkpoint transaction so large blobs never bloat transaction hold times or JS memory. `process` then moves the staged text into FTS5 and updates the manifest table atomically under [`Commit.transaction`](/docs/projections/commits#transaction).
- **Bun vs. Cloudflare wiring.** On Bun, `search` and `filesWake` attach directly to local `Files` commits (`Projection.attach(..., { durable: true })`). On Cloudflare, each folder lives in its own Durable Object (`FOLDERS`) while the registry, `FolderWake`, and FTS5 index live in one `IndexObject` (`INDEX`). Folder objects push wake rows to `IndexObject` over an internal `ObjectLink` (`/__wake`), and `IndexObject` attaches `search` with `triggers: [FolderWake]`—reading `Files` back through a read-only `/__files` link so each failing folder backs off independently. See [Trigger streams](/docs/projections/run#trigger-streams) and [Durable Objects](/docs/servers/cloudflare/objects).

## Inside the workspace

Snippet paths below are relative to `examples/folder-sync`. `// ...` marks omitted lines.

### Streams and wake projection

`server/streams.ts` declares the registry, hex-keyed per-folder file streams, and shared wake stream. `server/wake.ts` publishes every folder commit into `FolderWake`:

```ts title="server/streams.ts"
/** Hex UTF-8 is an injective, canonical stream-id segment for opaque folder ids. */
export const FolderKey = Schema.StringFromHex.check(Schema.makeFilter(Schema.is(FolderId)));

export const Folder = Schema.Struct({ folderId: FolderId, title: Identifier });

export type Folder = typeof Folder.Type;

export class Folders extends Streamsy.state<Folders>()("FolderSync/Folders", "folders", {
  params: {},
  collections: { folder: { schema: Folder, key: "folderId" } },
}) {}

export class Files extends Streamsy.state<Files>()("FolderSync/Files", "folders/:folderId/files", {
  params: { folderId: FolderKey },
  collections: { file: { schema: FileValue, key: "path" } },
}) {}

/** One row for each folder `Files` stream: its id and tail. Projections write it; clients read. */
export class FolderWake extends Streamsy.wake<FolderWake>()("FolderSync/FolderWake", "wake", {
  params: {},
}) {}
```

```ts title="server/wake.ts"
/** Each folder's `Files` writes give one upsert in the deployment's one wake stream. */
export const filesWake = Projection.wake({
  id: "files-wake",
  params: { folderId: FolderKey },
  input: Files,
  output: FolderWake,
});
```

### Versioned writes with `Projection.decide`

`FolderStore` wraps `Projection.decide` over `folderView` to assign monotonic folder versions and periodically checkpoints every `CHECKPOINT_EVERY` (32) landed writes so folds stay fast without checkpointing on every single edit:

```ts title="server/folder-store.ts"
const decide = <A, E>(
  folderId: string,
  decision: (view: FolderView) => Effect.Effect<{ value: A; items: Array<FileChangeItem> }, E>,
) =>
  Projection.decide(folderView.at({ folderId }), {
    input: "files",
    decide: ({ state, offsets }) =>
      decision(state).pipe(
        Effect.map(({ value, items }) => ({
          value,
          items:
            items.length === 0
              ? []
              : DurableState.changes(Files.at({ folderId }), { offset: offsets.files }, items),
        })),
      ),
  }).pipe(
    Effect.catchTag("OffsetMismatch", () => Effect.fail(new WriteConflict({ folderId }))),
    Effect.tap(({ appended }) => (appended ? checkpoint(folderId) : Effect.void)),
    Effect.map(({ value }) => value),
    Effect.provideContext(context),
  );
```

### Staging blobs in `prepare` for FTS5 search

`search` uses `prepare` to stream blob prefixes before the transaction opens, and `process` commits FTS5 rows, manifest rows, and the folder's cursor together:

```ts title="server/search-index.ts"
/** Each folder's SQL rows and input cursor commit together on the index owner. */
export const search = Projection.process({
  id: "folder-index",
  params: { folderId: FolderKey },
  inputs: { input: Files },
  commit: Commit.transaction,
  prepare: (batch, unit) => prepareIndexChanges(unit.params.folderId, batch.input.items),
  process: (batch, unit, { prepared }) =>
    batch.input.gone
      ? clearIndexFolder(unit.params.folderId)
      : applyIndexChanges(unit.params.folderId, prepared),
});
```

### Linking Durable Objects on Cloudflare

On Cloudflare, `ObjectLink.make` defines narrow cross-object permissions under `/__` prefixes (blocked with `404` at the public Worker edge), and `IndexObject` wakes `search` from `FolderWake`:

```ts title="worker/links.ts"
/** Folder objects append wake rows to the index object, which owns the wake stream. */
export const wakeLink = ObjectLink.make({
  group: Streamsy.group(FolderWake),
  prefix: "/__wake",
  placement: Placement.byKey(() => "index"),
  // The index object creates the one wake stream at start.
  access: "append",
});

/** Internal protocol reads preserve missing/gone outcomes for the projection kernel. */
export const filesLink = ObjectLink.make({
  group: Streamsy.group(Files),
  prefix: "/__files",
  placement,
  access: "read",
});
```

```ts title="worker/index-object.ts"
export class IndexObject extends StreamsyObject.make<
  Env,
  Layer.Success<ReturnType<typeof indexLayer>>,
  Files
>({
  app: IndexApp,
  layer: indexLayer,
  links: (env) => [filesLink.client(env.FOLDERS)],
  wakeups: [ProjectionWakeup.attach(search, { triggers: [FolderWake] })],
}) {}
```

### Browser and sync CLI

The browser opens one `createStreamDB` for `Folders` and one for the active `Files` stream (adapting tombstone upserts into State deletes for live TanStack DB collections). Edits show optimistically, upload their blob, commit with their base `parent`, and await the returned `txid`:

```ts title="src/db.ts"
mutationFn: async ({ file, base, txid, bytes, onAccepted }: EditFile) => {
  const head = await saveFile(folderId, file, base, txid, transport, bytes);
  await db.utils.awaitTxId(head.txid);
  onAccepted?.(head);
},
```

File history simply replays the folder's stream filtered by `path` and fetches earlier blobs by hash.

The **sync CLI** bootstraps each selected folder, then holds a single live connection to `/streams/wake` instead of one connection per folder. Whenever `FolderWake` marks a folder dirty, the CLI pulls that folder's changes and persists the folder cursor _before_ advancing its wake cursor—so restarts safely replay any unfinished work. Local SQLite tables track remote/local hashes and pending uploads under `.folder-sync/content/<hash>`, resuming interrupted writes on restart and stopping with `HistoryRewound` if a server tail ever moves backward.

The **agent filesystem** (`createAgentFileSystem` in `agent/index.ts`) builds on the same stream readers to mount `/<folderId>/<path>` for `just-bash` and Better FS Tools, adding FTS5-backed `grep --search`.

## Going further

### Production notes

- **No State compaction or blob garbage collection.** Bootstrap and history replay every retained folder event, and failed/abandoned uploads can leave orphan blobs with no quota enforcement.
- **Cross-object folder creation on Cloudflare.** `IndexObject` creates the folder's `Files` stream in `FOLDERS` before registering it in `Folders`; a crash between the two leaves an unlisted empty stream that a retry cleanly registers.
- **Eventual search consistency.** Search reads lag folder writes by one projection pass; a missing blob keeps file metadata without search text until a later write or rebuild.
- **Mirror state and auth.** Local mirror SQLite files have no schema migration (use fresh directories when upgrading), and authentication is a single shared bearer token for writes with public reads. See the [example README](https://github.com/gingerhendrix/streamsy/tree/effect/examples/folder-sync) for full contract details and local Bun vs. `workerd` timings.
