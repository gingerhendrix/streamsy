This example keeps a live list of the 50 newest Hacker News stories in the browser without page reloads. As scores, titles, or comment counts change—or as stories fall out of the top 50—rows update and disappear automatically.

A Bun server polls the Hacker News API, folds its [Durable State stream](/docs/streams/durable-state) to diff against the latest 50 stories, appends only the changes with `Projection.decide`, and serves the stream read-only to a React + TanStack DB client.

![The Hacker News newest example page. A header shows the row count, the changed count, the poll interval and the poller state. Below it is a list of the newest stories with points, author, age and comment count.](/docs/examples/hackernews-newest.png)

The full source lives in [`examples/hackernews-newest-stream`](https://github.com/gingerhendrix/streamsy/tree/effect/examples/hackernews-newest-stream). Its README documents environment variables, the status/poll API, and the offline smoke test.

## Run it

From the repository root:

```bash
bun install --frozen-lockfile
bun run build
bun run --cwd examples/hackernews-newest-stream dev
```

Open `http://localhost:1339`. Streams persist in `.data/hackernews.sqlite` by default; set `HN_DB=memory` to run in memory. You can also inspect the raw Durable State stream with `curl`:

```bash
curl -i 'http://localhost:1339/state/newest?offset=-1'
```

## Polling, diffing, and live sync

![Architecture diagram. In the Bun server, the poller fetches the HN API and appends to the stream hackernews/newest. The newestRows projection folds the stream into rows. The poller folds the projection in memory before each append, and retries on OffsetMismatch. Serve.mount publishes the stream at /state/newest. In the browser, createStreamDB replays the stream into TanStack DB and React renders it with useLiveQuery. The stream and the checkpoint record containing state share one Bun SQLite file.](/docs/examples/hackernews-architecture.svg)

This app is the working reference for the [read, decide, append](/docs/projections/state#read-decide-append) pattern over a Durable State stream:

1. **Fetch once, reconcile via `Projection.decide`.** On each poll pass, the server fetches the 50 newest stories from Hacker News once, then runs `Projection.decide` over `newestRows` (an unattached `Projection.fold` of `HackerNewsStories`). `diffNewest` compares the folded rows with the fetched stories and produces only the needed upserts and deletes—appending nothing when nothing changed.
2. **Retry conflicts without re-fetching.** If another writer moved `hackernews/newest` before the append landed, `Projection.decide` catches `OffsetMismatch`, refolds the updated tail, re-diffs against the same `fetched` snapshot, and retries up to three times via a custom `Schedule`.
3. **Serve read-only and tail in the browser.** [`Serve.mount`](/docs/servers/serve#mount-a-stream) publishes `HackerNewsStories` read-only at `/state/newest` on the same origin as the UI (so no CORS middleware is needed). The browser opens it with `createStreamDB` from `@durable-streams/state` over long polling and renders directly from TanStack DB's `useLiveQuery`.

## Inside the poller and browser

Snippet paths below are relative to `examples/hackernews-newest-stream`. `// ...` marks omitted lines.

### Stream declaration and storage

`HackerNewsStories` is a single fixed-address `Streamsy.state` stream with one `hn-story` collection keyed by `id`. `createStoriesLayer` creates the stream at boot so clients reading before the first poll receive `200 []` instead of `404`, and `host` switches cleanly between SQLite and memory:

```ts title="src/server/stories.ts"
export class HackerNewsStories extends Streamsy.state<HackerNewsStories>()(
  "HackerNews/Stories",
  "hackernews/newest",
  { params: {}, collections: { "hn-story": { schema: HackerNewsStory, key: "id" } } },
) {}

export const storiesAddress = HackerNewsStories.at({});
```

```ts title="src/server/streams.ts"
const streams = Streamsy.group(HackerNewsStories);

/** Create before HTTP starts, so a fresh State replay is 200 and empty. */
export const createStoriesLayer = Layer.effectDiscard(
  Effect.flatMap(HackerNewsStories, (stories) => stories.create({})),
);

const storage = (databasePath: string, options: { readonly readLimit?: number } = {}) =>
  databasePath === "memory"
    ? MemoryStorage.layer(streams, options)
    : BunStorage.layer(streams, { ...options, client: { filename: databasePath } });

type HostLayer = Layer.Layer<Streamsy.Host<typeof streams> | CheckpointStore, StorageFault>;

/** The checkpoints join the owner of the stream: one SQLite file, or memory. */
export const host = (
  databasePath: string,
  options: { readonly readLimit?: number } = {},
): HostLayer => CheckpointStore.layer.pipe(Layer.provideMerge(storage(databasePath, options)));
```

See [Declare streams](/docs/streams/declare) and [Choose storage](/docs/storage).

### Folding and reconciling diffs with `Projection.decide`

Because the active set is capped at ~50 stories, `newestRows` folds `HackerNewsStories` into a single `Record<string, HackerNewsStory>` value in memory (with no background follower or output stream):

```ts title="src/server/newest-rows.ts"
export const StoryRows = Schema.Record(Schema.String, HackerNewsStory);
// ...
export const newestRows = Projection.fold({
  id: "hn-newest-rows",
  params: {},
  inputs: { input: storiesAddress },
  state: { schema: StoryRows, initial: {} },
  fold: (rows, { item }) => applyChange(rows, item),
}).at({});
```

`reconcileNewest` wraps `diffNewest` inside `Projection.decide`, stamping `offsets.input` onto `DurableState.changes`. When `changes` is empty, `items` is empty so Streamsy skips the append altogether:

```ts title="src/server/poller/reconcile.ts"
export const reconcileNewest = (
  fetched: FetchResult,
  retry: Schedule.Schedule<unknown, OffsetMismatch>,
) =>
  Projection.decide(newestRows, {
    input: "input",
    decide: ({ state: rows, offsets }) => {
      const changes = diffNewest(rows, fetched);
      // No change gives no events: `decide` then appends nothing and does not check the tail.
      const events = DurableState.changes(storiesAddress, { offset: offsets.input }, changes);

      return Effect.succeed({
        value: { rows: Array.reduce(events, rows, applyChange), changes },
        items: events,
      });
    },
    retry,
  }).pipe(
    Effect.map(({ value, offset }) => ({ ...value, offset })),
    Effect.withSpan("NewestStoriesPoller.reconcile"),
  );
```

The poller passes a `Schedule.recurs(3)` schedule that also increments a retry counter in status metrics:

```ts title="src/server/poller/poller.ts"
// Up to three retries after `OffsetMismatch`, so at most four appends per pass.
const conflictRetries = Schedule.recurs(3).pipe(
  Schedule.tap(() =>
    Ref.update(countersRef, (counters) => ({
      ...counters,
      totalConflictsRetried: counters.totalConflictsRetried + 1,
    })),
  ),
);
```

### Serving the stream and following in React

`Serve.mount` exposes `HackerNewsStories` read-only at `/state/newest`, and `Serve.layer` + `Serve.teardown` handle clean shutdown of parked long polls:

```ts title="src/server/http.ts"
export const stateRoute = Serve.mount(HackerNewsStories, streamPath);

/** The page and State route share an origin, so no CORS middleware is needed. */
export const app = Layer.mergeAll(
  stateRoute,
  // ... the status and poll API, and the static page ...
);
```

```ts title="src/server/index.ts"
const serverLayer = Serve.layer(app).pipe(
  Layer.provide(pollerLayer.pipe(Layer.provideMerge(demoHostLayer))),
  Layer.provide(listenerLayer),
);

BunRuntime.runMain(Layer.launch(serverLayer), { teardown: Serve.teardown });
```

On the browser side, `createStateSchema` reuses the Effect `HackerNewsStory` schema, `createStreamDB` tails `/state/newest` over long polling, and React reads live updates with `useLiveQuery`—no custom polling or fetch code needed:

```ts title="src/state-schema.ts"
export const hackerNewsState = createStateSchema({
  stories: {
    schema: Schema.toStandardSchemaV1(HackerNewsStory),
    type: "hn-story",
    primaryKey: "id",
  },
});
```

```ts title="src/client/db.ts"
export function createHnDb(origin: string) {
  return createStreamDB({
    streamOptions: {
      url: new URL("/state/newest", origin).toString(),
      contentType: "application/json",
      headers: { [STATE_VERSION_HEADER]: "1" },
      warnOnHttp: false,
    },
    live: "long-poll",
    state: hackerNewsState,
  });
}
```

## Going further

### Production notes

- **No snapshots or checkpoints yet.** Because `newestRows` has no background follower, each `Projection.decide` folds from the start of the stream, and fresh browser loads replay every retained event from `-1`. Adding a background checkpoint (via `Projection.attach`) bounds poller folds, and State snapshots avoid unbounded browser replay.
- **Compaction vs. retention.** Trimming old events without writing a snapshot would drop active stories; pair any retention limit with periodic snapshots.
- **Multiple pollers and freshness.** `expectedOffset` prevents conflicting writes from corrupting the stream, but it does not order fetches from two independent poller processes by recency. Keep a single leader poller in production.
- **Server reset handling.** After a stream `reset`, reload the page to reopen the collection from `-1`; automatic reopening is not wired up here. Note also that `@durable-streams/state` 0.3.1 merges upserts onto existing keys, so omitted fields retain prior browser values.
