Every Streamsy program is an Effect that needs a Layer. The application builds that Layer once, runs the program, and disposes the runtime at shutdown.

```ts
import { ManagedRuntime } from "effect";
import { Memory, Streamsy } from "@streamsy/core";
import { shop } from "./streams.ts";
import { write } from "./write.ts";

const runtime = ManagedRuntime.make(Memory.layer({}, shop));
try {
  await runtime.runPromise(write);
} finally {
  await runtime.dispose();
}
```

## Two shapes

A script or a test uses `ManagedRuntime`, as above. A server uses `Layer.launch` under `BunRuntime.runMain`, where the listener, a projection, and an outbox drain are Layers in one graph. The launched scope owns every fiber and every subscription, and closing it is the shutdown. See [HTTP](/docs/runtime/http).

## How the services fit

`Storage` is the backend. A storage Layer builds the protocol over its `Storage` and binds the streams that you pass to it, so a program sees only stream services. It also provides a `Streamsy.ChangeFeed` key for each stream, which `Projection.watch` needs. `Http.routes` serves a group of streams with one access rule per stream. `Fetch.layer` provides the same stream services from a remote host, without `Streamsy.ChangeFeed` keys.

| Layer                                        | Persists              | Use                 | Page                                   |
| -------------------------------------------- | --------------------- | ------------------- | -------------------------------------- |
| `Memory.layer({}, group)`                    | no                    | one process, tests  | [Storage](/docs/runtime/storage)       |
| `BunStorage.layer(options, group)`           | SQLite file           | Bun host            | [Storage](/docs/runtime/storage)       |
| `DurableObjectStorage.layer(options, group)` | Durable Object SQLite | Cloudflare          | [Cloudflare](/docs/runtime/cloudflare) |
| `Fetch.layer({ baseUrl }, group)`            | remote                | any conformant host | [HTTP](/docs/runtime/http)             |

Each Layer takes a group from `Streamsy.group`.

The generic `StreamsReader` and `StreamsWriter` services, `Protocol.layer`, and the `Streams` functions are on the `@streamsy/core/protocol` subpath. The SQLite storage modules and the fetch module also export `layerProtocol(options)`, which provides that generic pair without streams; for memory it is `Streams.layerMemory()` on the protocol subpath. `Protocol.bind(graph, group)` from `@streamsy/core/protocol` binds streams to such a graph. These are for storage adapters, protocol tests, and HTTP internals.

## Testing

Application tests provide `Memory.layer({}, group)` and run the same program. `@streamsy/core/testing` has protocol-tier tools. `layerTest` and `StreamsTest` provide the generic services over a fresh memory store and let a test observe change subscriptions; bind streams to them with `Protocol.bind(layerTest(), group)`. `StorageContract.run` exercises a storage adapter against the contract; see [Writing a storage adapter](/docs/advanced/storage-adapter).

## Several backends

A stream lives on the storage Layer that binds it. To put streams on different backends, merge one Layer per backend:

```ts
import { Layer } from "effect";
import { Memory, Streamsy } from "@streamsy/core";
import * as BunStorage from "@streamsy/storage/bun";
import { Drafts, Journal } from "./streams.ts";

export const layer = Layer.merge(
  Memory.layer({}, Streamsy.group(Drafts)),
  BunStorage.layer({ client: { filename: "./journal.sqlite" } }, Streamsy.group(Journal)),
);
```

A program that needs `Drafts` and `Journal` runs over the merged Layer. A missing stream is a type error at the edge.

A group checks only the streams it contains: two templates that can match one id fail at `Streamsy.group`. Put every served stream in one group for `Http.routes`, so the check covers all of them. An id that no stream owns answers 404 over HTTP. To own every other id, put `Streamsy.Wildcard` last in a group. A fork stays inside one stream, so it never crosses backends. A fetch Layer keeps its own `capabilities`, so set the flags on that Layer.

Projections have one more rule: `Checkpoints`, atomic stream writes, and declared outputs must share one storage owner. See [Projections](/docs/projections/projections#several-backends).
