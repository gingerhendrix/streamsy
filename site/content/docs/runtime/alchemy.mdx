---
title: Alchemy
description: Compose an Effect-native Durable Object application in its instance scope.
---

Alchemy separates construction from runtime. The outer generator declares resources; storage acquisition belongs to the inner instance runtime. `objectHandlers` builds the same router application as the Cloudflare class host, through Effect's native `HttpRouter.toHttpEffect`.

```ts
import * as Cloudflare from "alchemy/Cloudflare";
import { Effect, Layer } from "effect";
import { Streamsy, Http } from "@streamsy/core";
import * as Host from "@streamsy/serve/alchemy";
import * as DurableObjectStorage from "@streamsy/storage/durable-object";

const streams = Streamsy.group(Streamsy.Wildcard);

export class Streams extends Cloudflare.DurableObject<Streams>()(
  "Streams",
  Effect.gen(function* () {
    const state = yield* Cloudflare.DurableObjectState;
    return Effect.suspend(() =>
      Host.objectHandlers({
        app: Http.routes(streams, { prefix: "/streams", access: "full" }),
        layer: Layer.mergeAll(
          DurableObjectStorage.layer({ client: { storage: state.raw.storage } }, streams),
          Host.alarmLayer(state.raw.storage),
        ),
      }),
    );
  }),
) {}
```

This object serves any id with full access, as the hosted conformance fixture does. An application passes its own group and access rule to both `Http.routes` and the storage Layer.

The helper shares one successful acquisition across fetch and alarm, closes failed attempts before retry, and releases the context when the instance scope closes. It installs mutation reconciliation and defect mapping through the common object middleware. Alarms retain failures for platform retry. The native helper installs no request logger.

The Worker yields `Streams` during construction to obtain its namespace handle. Its fetch uses `Host.router({ objects, prefix: "/streams", placement: Host.Placement.byKey(...) })`. That router is an HttpEffect, so authentication can precede it without Web conversion helpers. The hosted source fixture in this repository proves the complete composition.

The placement helper routes protocol paths only. An application hosting Serve URLs inside an object must supply their Worker routing. Forks and transactional writes stay inside one object. See [Cloudflare](/docs/runtime/cloudflare) for placement and lifecycle details, and [Serve](/docs/projections/serve) for route composition and auth.

A remote client uses `@streamsy/core/fetch` with the Worker's protocol prefix as `baseUrl`. The pinned Alchemy version is `2.0.0-beta.79`. Stack declaration and local checks do not deploy anything.
