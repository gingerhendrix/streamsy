Every Streamsy program is an Effect that needs a Layer. The application builds that Layer once, runs the program, and disposes the runtime at shutdown.

```ts
import { ManagedRuntime } from "effect";
import { Memory } from "@streamsy/core";
import { shop } from "./streams.ts";
import { write } from "./write.ts";

const runtime = ManagedRuntime.make(Memory.layer({}, shop));
try {
  await runtime.runPromise(write);
} finally {
  await runtime.dispose();
}
```

## Two shapes

A script or a test uses `ManagedRuntime`, as above. A server uses `Layer.launch` under `BunRuntime.runMain`, where the listener, a projection, and an outbox drain are Layers in one graph. The launched scope owns every fiber and every subscription, and closing it is the shutdown. See [HTTP](/docs/runtime/http).

## How the services fit

`Storage` is the backend. A storage Layer builds the protocol over its `Storage` and binds the families that you pass to it, so a program sees only family services. It also provides a `Changes` key for each family, which `Projection.onChange` needs. `Http.routes` serves a group of families with one access rule per family. `Fetch.layer` provides the same family services from a remote host, without `Changes` keys.

| Layer                                        | Persists              | Use                 | Page                                   |
| -------------------------------------------- | --------------------- | ------------------- | -------------------------------------- |
| `Memory.layer({}, group)`                    | no                    | one process, tests  | [Storage](/docs/runtime/storage)       |
| `BunStorage.layer(options, group)`           | SQLite file           | Bun host            | [Storage](/docs/runtime/storage)       |
| `DurableObjectStorage.layer(options, group)` | Durable Object SQLite | Cloudflare          | [Cloudflare](/docs/runtime/cloudflare) |
| `Fetch.layer({ baseUrl }, group)`            | remote                | any conformant host | [HTTP](/docs/runtime/http)             |

Each Layer takes a group from `StreamGroup.make`, or the family classes directly.

The generic `StreamsReader` and `StreamsWriter` services, `Protocol.layer`, and the `Streams` functions are on the `@streamsy/core/protocol` subpath. The SQLite storage modules and the fetch module also export `layerProtocol(options)`, which provides that generic pair without families; for memory it is `Streams.layerMemory()` on the protocol subpath. `provides(graph, group)` from `@streamsy/core` binds families to such a graph. These are for storage adapters, protocol tests, and HTTP internals.

## Testing

Application tests provide `Memory.layer({}, group)` and run the same program. `@streamsy/core/testing` has protocol-tier tools. `layerTest` and `StreamsTest` provide the generic services over a fresh memory store and let a test observe change subscriptions; bind families to them with `provides(layerTest(), group)`. `StorageContract.run` exercises a storage adapter against the contract; see [Writing a storage adapter](/docs/advanced/storage-adapter).

## Several backends

A family lives on the storage Layer that binds it. To put families on different backends, merge one Layer per backend:

```ts
import { Layer } from "effect";
import { Memory } from "@streamsy/core";
import * as BunStorage from "@streamsy/storage/bun";
import { Drafts, Journal } from "./streams.ts";

export const layer = Layer.merge(
  Memory.layer({}, Drafts),
  BunStorage.layer({ client: { filename: "./journal.sqlite" } }, Journal),
);
```

A program that needs `Drafts` and `Journal` runs over the merged Layer. A missing family is a type error at the edge.

A group checks only the families it contains: two templates that can match one id fail at `StreamGroup.make`. Put every served family in one group for `Http.routes`, so the check covers all of them. An id that no family owns answers 404 over HTTP. To own every other id, put `AnyStream` last in a group. A fork stays inside one family, so it never crosses backends. A fetch Layer keeps its own `capabilities`, so set the flags on that Layer.

Projections have one more rule: `Checkpoints`, fused family writes, and declared outputs must share one storage owner. See [Projections](/docs/projections/projections#several-backends).
