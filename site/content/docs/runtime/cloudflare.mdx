On Cloudflare a Worker routes each stream path to a Durable Object, and the object owns the protocol, the HTTP program, and SQLite storage for every stream placed on it.

The Worker strips the path prefix, gives the stream path to a `Placement`, and forwards the request to the object that placement names. The object builds one Layer for its lifetime and answers every request for its streams from its own SQLite.

## Router

```ts
import { Placement, router } from "@streamsy/serve/cloudflare";

interface Env {
  readonly STREAMS: DurableObjectNamespace;
}

export default router<Env>({
  pathPrefix: "/streams",
  placement: Placement.byStream(),
  namespace: (env) => env.STREAMS,
});
```

An empty placement key answers `400 Invalid placement key`. A placement function that throws answers `500`.

## Placement

`Placement.byStream()` is the default and gives every stream its own object. `Placement.byKey(fn)` groups streams by a key such as the first path segment. `Placement.byRoute(rules)` names the object from `StreamRoute` parameters.

```ts
import { Placement, rule } from "@streamsy/serve/cloudflare";
import { orderEvents, orderIndex } from "./routes.ts";

export const placement = Placement.byRoute([
  rule({ route: orderEvents, owner: ({ orderId }) => `order:${orderId}` }),
  rule({ route: orderIndex, owner: ({ orderId }) => `order:${orderId}` }),
]);
```

The first matching rule names the object. A path that no rule matches yields an empty key and the `400` above.

Placement decides atomicity and forks. One object is one owner with one transaction scope. Keep the mapping stable, because stored data lives under the object name the function returned when it was written.

## The object

The host is two effects and a Layer: `fetch(options)`, `alarm`, and `alarmLayer(state)`. `StreamsyObject` wraps them as a class for wrangler.

```ts
import type { Layer } from "effect";
import type { Storage, StorageFault, StreamsReader, StreamsWriter } from "@streamsy/core";
import { StreamsyObject, type ObjectOptions } from "@streamsy/serve/cloudflare";
import { layerProtocol } from "@streamsy/storage/durable-object";

export class StreamsObject extends StreamsyObject<Env> {
  override layer(): Layer.Layer<StreamsReader | StreamsWriter | Storage, StorageFault> {
    return layerProtocol({ client: { storage: this.ctx.storage } });
  }

  override options(): ObjectOptions {
    return { pathPrefix: "/streams" };
  }
}
```

Each in-memory object builds its Layer once and shares it between `fetch` and `alarm`. If the build fails, the object answers `503` with `retry-after: 1` and tries again on the next request. The `alarm` effect runs the expiry sweep. A missed alarm is repaired by the next access.

Defaults: the long-poll timeout is 25 s, an SSE connection ends after 60 s, and the request body limit is 1 MiB. `ObjectOptions` is the same options type as `Http.app`.

## Forks

A source and its child must share an object. Use `byKey` or `byRoute` so a fork family lands on one object. A source in another object is not found.

## Projections in the object

Compose the projection SQLite Layer over the same storage Layer, and keep one runtime for the object lifetime. Run a pass from the `alarm` effect.

```ts
import { Layer } from "effect";
import { Protocol } from "@streamsy/core";
import * as DurableObjectStorage from "@streamsy/storage/durable-object";
import * as ProjectionSqlite from "@streamsy/projection/sqlite";

const objectLayer = (
  storage: DurableObjectStorage.DurableObjectStorageOptions["client"]["storage"],
) =>
  Layer.merge(Protocol.layer(), ProjectionSqlite.layer).pipe(
    Layer.provideMerge(DurableObjectStorage.layer({ client: { storage } })),
  );
```

A fused handler's `Streams.append` and SQL through the object's client commit with the checkpoint, because all three go through the one `CommitBoundary` the storage Layer owns.

A long-lived `follow` fiber is the wrong shape for a Durable Object; use request-triggered `run` plus an alarm-triggered `run`. `Placement.byRoute` with the same owner for every route in a projection family keeps its inputs, output, and checkpoint in one object.

## Local run

`alchemy dev` runs the Worker and the object on your machine. See [Alchemy](/docs/runtime/alchemy). Miniflare remains the runner for the conformance harness in the repository.

## Which form

| Form     | Entry                        | Use                                                           |
| -------- | ---------------------------- | ------------------------------------------------------------- |
| Alchemy  | `@streamsy/serve/alchemy`    | an Alchemy stack; the object and the Worker are Effect values |
| wrangler | `@streamsy/serve/cloudflare` | `StreamsyObject` as a class plus the `ExportedHandler` router |

The upstream [`server-cloudflare`](https://github.com/durable-streams/durable-streams/tree/main/packages/server-cloudflare) package hosts the same protocol on Durable Objects without Effect.

Neither form carries authorization. Authenticate in the Worker before the router, and derive the stream path from the authenticated identity.
