---
title: Read
description: Read stored batches after an offset, follow a stream for new messages, and fold a stream into a value.
---

A read starts after an offset and gives batches of decoded items.

```ts
interface Batch<A> {
  readonly items: ReadonlyArray<A>;
  readonly nextOffset: string;
  readonly upToDate: boolean;
  readonly closed: boolean;
}
```

Reads do not include the message at the given offset. Omit the offset to read from the start. Keep `nextOffset` to continue later.

| Method                                  | Ends                              |
| --------------------------------------- | --------------------------------- |
| `read(params, { offset?, limit? })`     | At the current tail               |
| `collect(params, { offset? })`          | At the current tail               |
| `fold(params, initial, f, { offset? })` | At the current tail               |
| `follow(params, { offset? })`           | When the stream closes            |
| `session(params, { offset, cursor? })`  | After one long-poll wait          |
| `head(params)`                          | Returns the tail with no messages |

`head` does not restart a TTL.

## Read

```ts
// @filename: streams.ts
export * from "./notes-streams.ts";
// @filename: index.ts
// ---cut---
import { Effect, Stream } from "effect";
import { Notes } from "./streams.ts";

const sizes = Effect.flatMap(Notes, (notes) =>
  notes.read({}).pipe(
    Stream.map((batch) => batch.items.length),
    Stream.runCollect,
  ),
);

const everything = Effect.flatMap(Notes, (notes) => notes.collect({}));
// ---cut-after---
// A memory host for the Notes group provides everything that the reads need.
import { MemoryStorage, Streamsy } from "@streamsy/core";
const provided: Effect.Effect<unknown, unknown, never> = Effect.all([sizes, everything]).pipe(
  Effect.provide(MemoryStorage.layer(Streamsy.group(Notes))),
);
```

`read` is an Effect `Stream` of batches. It does nothing until a sink runs it. `limit` sets the maximum number of stored messages in one batch.

`collect` reads to the current tail and returns `{ items, offset }`. `offset` is the tail it read up to. Pass it as `expectedOffset` for a [conditional write](/docs/streams/write#conditional-writes), or as `offset` to read on from there.

## Follow

```ts
// @filename: streams.ts
export * from "./notes-streams.ts";
// @filename: index.ts
// ---cut---
import { Effect, Stream } from "effect";
import { Notes } from "./streams.ts";

const live = Effect.flatMap(Notes, (notes) =>
  notes.follow({}).pipe(
    Stream.flatMap((batch) => Stream.fromIterable(batch.items)),
    Stream.runForEach((note) => Effect.log(note.text)),
  ),
);

const consumer = Effect.gen(function* () {
  const fiber = yield* live.pipe(Effect.forkScoped);
  return fiber;
});
```

`follow` catches up, then waits. It does not give empty batches. A closed batch ends the stream. Interrupt the fiber to release a parked wait. Use `Stream.take` to stop after a number of batches.

## Session

```ts
// @filename: streams.ts
export * from "./notes-streams.ts";
// @filename: index.ts
// ---cut---
import { Effect } from "effect";
import { Notes } from "./streams.ts";

const once = (offset: string) => Effect.flatMap(Notes, (notes) => notes.session({}, { offset }));
```

`session` is one long-poll wait, for an application with its own poll loop. The result has raw `messages`, `nextOffset`, `cursor`, `upToDate`, `closed`, and `timedOut`. The messages are not decoded.

## Fold

```ts
// @filename: streams.ts
export * from "./notes-streams.ts";
// @filename: index.ts
// ---cut---
import { Effect } from "effect";
import { Notes } from "./streams.ts";

const count = Effect.flatMap(Notes, (notes) =>
  notes.fold(
    {},
    () => 0,
    (total) => total + 1,
  ),
);
```

`fold` reads to the current tail and returns `{ state, offset }`, like `collect`. The initial value is a function, so each fold starts from a new value and a mutable accumulator is safe. To fold only new items, pass the earlier `offset` and start from the earlier `state`.

To keep folding while the stream grows, fold over `follow`:

```ts
// @filename: streams.ts
export * from "./notes-streams.ts";
// @filename: index.ts
// ---cut---
import { Effect, Stream } from "effect";
import { Notes } from "./streams.ts";

const live = Effect.flatMap(Notes, (notes) =>
  notes.follow({}).pipe(
    Stream.flatMap((batch) => Stream.fromIterable(batch.items)),
    Stream.runFold(
      () => 0,
      (total) => total + 1,
    ),
  ),
);
```

A fold over `follow` completes when the stream closes.

## Errors

`read`, `fold`, and `collect` use `ReadFailure`. `follow` uses `FollowFailure`, which also includes `NotSupported`. `head` uses `HeadFailure`. Import these types from `@streamsy/core`.

`follow` retries only a `StreamsFault` with `retryable: true`, from the same offset. A failed transport request, HTTP 429, or HTTP 5xx is retryable. Other failures end the stream. The default retry is exponential from 200 ms, jittered and capped at 30 s; `retry` sets another schedule.

| Error            | When                               |
| ---------------- | ---------------------------------- |
| `StreamNotFound` | The stream does not exist          |
| `StreamGone`     | The stream was removed             |
| `DecodeFault`    | A message does not match the codec |

A `DecodeFault` stops the read. The application selects the offset to continue from.

A Durable State read gives `insert` and `update` operations from other producers as `upsert`.

A Durable State read also gives the control messages that the stream holds. A control has `headers.control` set to `snapshot-start`, `snapshot-end` or `reset`, and it has no `type` or `key`. A reader that folds rows should clear them at a `reset` and apply the items after it. `StreamAddress.isControl` and `StreamAddress.isChange` narrow an item.

## Over HTTP

`GET` on the stream path with `offset` reads one batch. Add `live=long-poll` or `live=sse` to follow. All access rules allow reads. See [Protocol routes](/docs/http/routes).
