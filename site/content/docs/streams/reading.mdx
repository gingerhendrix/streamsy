---
title: Reading
description: Read stored batches after an offset, follow a stream for new messages, and fold it into a value.
---

A read starts after an offset and returns batches of decoded items. `follow` keeps reading after catch-up until the stream closes.

```ts
interface Batch<A> {
  readonly items: ReadonlyArray<A>;
  readonly nextOffset: string;
  readonly upToDate: boolean;
  readonly closed: boolean;
}
```

Reads are after-exclusive. The message at the given offset is not included. Omit the offset to read from the start. Store `nextOffset` when you have to resume later.

`head(params)` returns the tail and the configuration without messages. It does not renew a TTL.

## Read

`read(params, { offset?, limit? })` is an Effect `Stream` of batches. Nothing runs until a sink such as `Stream.runCollect` runs it. It ends when a batch reports `upToDate`.

```ts
import { Effect, Stream } from "effect";
import { Notes } from "./streams.ts";

const everything = Effect.flatMap(Notes, (notes) =>
  notes.read({}).pipe(
    Stream.flatMap((batch) => Stream.fromIterable(batch.items)),
    Stream.runCollect,
  ),
);

const tail = Effect.flatMap(Notes, (notes) =>
  notes.read({}).pipe(
    Stream.map((batch) => batch.nextOffset),
    Stream.runLast,
  ),
);
```

`Stream.flatMap` with `Stream.fromIterable` flattens batches into items. Keep the batches when `nextOffset` or `closed` matter. `limit` bounds one batch to that many stored messages.

## Follow

`follow(params, options?)` catches up, then waits for more. One wait ends on a new message, on a close, or on the long-poll timeout. Empty batches that are not closed are filtered, whether from a timed-out wait or a catch-up read of an empty stream, and the follow waits again; a closed batch is always yielded and ends the stream. Use `session` directly when an application needs to observe empty waits as liveness signals.

```ts
import { Effect, Stream } from "effect";
import { Notes } from "./streams.ts";

const live = Effect.flatMap(Notes, (notes) =>
  notes.follow({}).pipe(
    Stream.flatMap((batch) => Stream.fromIterable(batch.items)),
    Stream.runForEach((note) => Effect.log(note.text)),
  ),
);

const consumer = Effect.gen(function* () {
  const fiber = yield* live.pipe(Effect.forkScoped);
  return fiber;
});
```

The scope owns the wait. Interrupting the fiber releases a parked wait, so run a live consumer inside a scope with an explicit shutdown. `Stream.take` bounds a follow so a program terminates.

## Session

`session(params, { offset, cursor? })` is one raw long-poll wait for an application that owns its own polling loop. It returns the protocol result, with raw `messages`, `nextOffset`, `cursor`, `upToDate`, `closed`, and `timedOut`. The messages are not decoded.

```ts
import { Effect } from "effect";
import { Notes } from "./streams.ts";

const once = (offset: string) => Effect.flatMap(Notes, (notes) => notes.session({}, { offset }));
```

## Fold

A fold over `follow` reduces a stream into a value. It completes when the stream closes. Fold over `read` instead to stop at the current tail.

```ts
import { Effect, Stream } from "effect";
import { Notes } from "./streams.ts";

const count = Effect.flatMap(Notes, (notes) =>
  notes.follow({}).pipe(
    Stream.flatMap((batch) => Stream.fromIterable(batch.items)),
    Stream.runFold(
      () => 0,
      (total) => total + 1,
    ),
  ),
);
```

## Errors

A read fails with `StreamNotFound` or `StreamGone` when the stream is absent or removed, and with `DecodeFault` when a message does not match the stream codec. A decode failure stops that read. The application picks the offset to restart from.

A Durable State reader accepts `insert` and `update` operations from other producers and reports both as `upsert`.

## Over HTTP

`GET` on the stream path with `offset` reads a batch. Add `live=long-poll` or `live=sse` to follow. Every access rule allows reads. See [HTTP](/docs/runtime/http) and [PROTOCOL.md sections 5.6 to 5.8](https://github.com/durable-streams/durable-streams/blob/main/PROTOCOL.md#56-read-stream---catch-up).
