---
title: DurableState
description: Reference for the DurableState namespace in @streamsy/core. It builds the change events of a Durable State stream.
---

```ts
import { DurableState, StreamAddress } from "@streamsy/core";
import type { Array } from "effect";
```

`DurableState` builds the items that you append to a `Streamsy.state` stream. `upsert` and `remove` each describe one change. `changes` turns a list of changes into change events: it adds the key and the headers, and the compiler checks each change against the collections of the address. For a worked example, see [Durable State changes](/docs/streams/write#durable-state-changes).

## `DurableState.upsert`

```ts
// ---cut-start---
import { DurableState } from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
declare function upsert<const Type extends string, A>(
  type: Type,
  value: A,
  options?: { readonly headers?: DurableState.ChangeHeaders },
): DurableState.Upsert<A, Type>;
// ---cut-after---
same<typeof upsert, typeof DurableState.upsert>(true);
```

`upsert` describes an insert or an update of `value` in the collection `type`. It takes no key, because `changes` reads the key from the key field of `value`.

## `DurableState.remove`

```ts
// ---cut-start---
import { DurableState } from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
declare function remove<const Type extends string, A = never>(
  type: Type,
  key: string | number,
  options?: { readonly oldValue?: A; readonly headers?: DurableState.ChangeHeaders },
): DurableState.Delete<NoInfer<A>, Type>;
// ---cut-after---
same<typeof remove, typeof DurableState.remove>(true);
```

`remove` describes the delete of the row `key` from the collection `type`. To also write the deleted row to the event as `old_value`, pass it as `oldValue`.

## `DurableState.changes`

```ts
// ---cut-start---
import { DurableState, StreamAddress } from "@streamsy/core";
import type { Array } from "effect";
import { same } from "./reference-check.ts";
// ---cut-end---
declare function changes<C extends StreamAddress.Collections, RD, RE>(
  address: StreamAddress.StateAddress<C, RD, RE>,
  options: { readonly offset?: string },
  entries: Array.NonEmptyReadonlyArray<DurableState.Entry<C>>,
): Array.NonEmptyReadonlyArray<StreamAddress.CollectionsEvent<C>>;
declare function changes<C extends StreamAddress.Collections, RD, RE>(
  address: StreamAddress.StateAddress<C, RD, RE>,
  options: { readonly offset?: string },
  entries: ReadonlyArray<DurableState.Entry<C>>,
): ReadonlyArray<StreamAddress.CollectionsEvent<C>>;
// ---cut-after---
same<typeof changes, typeof DurableState.changes>(true);
```

`changes` turns `entries` into the events that you append to `address`, in the same order. When `entries` is a non-empty array, the result type is a non-empty array too.

For each change, `changes` does four things:

- It sets `key` from the key field of an upserted value, or from the key passed to `remove`.
- It sets `headers.offset` to `options.offset`, when you pass one.
- It sets `headers.txid` to `${offset}:${index}`, unless the change sets its own `txid`. Without `options.offset`, the event has no default `txid`.
- It copies `timestamp` and `from` from the headers of the change.

A control message in `entries`, such as `StreamAddress.reset()`, passes through unchanged, except that it gets `options.offset` when it has no offset of its own.

A change to a collection that the address does not declare does not compile. At run time, `changes` throws a `TypeError` when a key is `null`, `undefined`, or empty.

## `DurableState.materialized`

```ts
// ---cut-start---
import { DurableState, StreamAddress } from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
declare function materialized<C extends StreamAddress.Collections>(address: {
  readonly collections: C;
}): DurableState.Materialized<C>;
// ---cut-after---
same<typeof materialized, typeof DurableState.materialized>(true);
```

`materialized` returns the empty state for the collections of `address`: one empty map for each collection, and no open snapshot. Pass a State address or a State stream class, because both have `collections`. Start a `materialize` fold from this value.

## `DurableState.materialize`

```ts
// ---cut-start---
import { DurableState, StreamAddress } from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
declare function materialize<C extends StreamAddress.Collections>(
  state: DurableState.Materialized<C>,
  events: Iterable<StreamAddress.CollectionsEvent<C>>,
): DurableState.Materialized<C>;
// ---cut-after---
same<typeof materialize, typeof DurableState.materialize>(true);
```

`materialize` folds `events` into `state` and returns the new state. It applies the rules of the [Durable State protocol](https://durablestreams.com/durable-state):

- An upsert sets the row of its key, and a delete removes it.
- A `reset` control message clears every collection and closes an open snapshot.
- A `snapshot-start` control message opens a snapshot. The `snapshot-end` control message that closes it removes each row that no upsert named since `snapshot-start`.

A snapshot can span several calls, because the returned `snapshot` carries it to the next call. A `snapshot-end` with no open snapshot changes nothing. `materialize` drops a change to a collection that `state.rows` does not hold.

`materialize` does not change `state`. It copies only the maps of the collections that `events` change, and the returned state shares every other map with `state`.

```ts
// @filename: streams.ts
export * from "./notes-streams.ts";
// @filename: index.ts
// ---cut---
import { Effect } from "effect";
import { DurableState } from "@streamsy/core";
import { Workspace } from "./streams.ts";

const issues = Effect.gen(function* () {
  const workspace = yield* Workspace;
  const { items } = yield* workspace.collect({ workspaceId: "w1" });
  return DurableState.materialize(DurableState.materialized(Workspace), items).rows.issue;
});
```

## `DurableState.ChangeHeaders`

```ts
// ---cut-start---
import { DurableState } from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
interface ChangeHeaders {
  readonly txid?: string;
  readonly timestamp?: string;
  readonly from?: string;
}
// ---cut-after---
same<ChangeHeaders, DurableState.ChangeHeaders>(true);
```

`ChangeHeaders` holds the headers that a change can set for itself. `changes` sets `operation` and `offset`, and a change cannot override them.

## `DurableState.Upsert`

```ts

type Upsert<A, Type extends string = string> = {
  readonly _tag: "Upsert";

```

`upsert` returns an `Upsert`. Pass it to `changes`, which adds the key and the headers.

## `DurableState.Change`

```ts
// ---cut-start---
import { DurableState, StreamAddress } from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
type Change<C extends StreamAddress.Collections> = {
  [K in keyof C & string]:
    DurableState.Upsert<C[K]["schema"]["Type"], K> | DurableState.Delete<C[K]["schema"]["Type"], K>;
}[keyof C & string];
// ---cut-after---
type Issue = { readonly id: string; readonly title: string };
type Project = { readonly id: number; readonly name: string };
type Tracker = {
  issue: StreamAddress.Collection<Issue, Issue, never, never, "id">;
  project: StreamAddress.Collection<Project, Project, never, never, "id">;
};
same<Change<Tracker>, DurableState.Change<Tracker>>(true);
```

`Change<C>` is an `Upsert` or a `Delete` for any collection of `C`. The union pairs each collection type with the value type of its schema, so an upsert must carry a value of the collection that it names.


`Entry<C>` is one item of the `entries` list of `changes`: a change, or a State control message.

## `DurableState.Materialized`

```ts
// ---cut-start---
import { DurableState, StreamAddress } from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
interface Materialized<C extends StreamAddress.Collections> {
  readonly rows: DurableState.Rows<C>;
  readonly snapshot: ReadonlySet<string> | undefined;
}
// ---cut-after---
type Issue = { readonly id: string; readonly title: string };
type Project = { readonly id: number; readonly name: string };
type Tracker = {
  issue: StreamAddress.Collection<Issue, Issue, never, never, "id">;
  project: StreamAddress.Collection<Project, Project, never, never, "id">;
};
same<Materialized<Tracker>, DurableState.Materialized<Tracker>>(true);
```

`Materialized<C>` is the state that `materialized` returns and `materialize` folds: the latest row for each key of each collection of `C`. `snapshot` holds the rows that upserts named since an open `snapshot-start`, and is `undefined` when no snapshot is open. Treat `snapshot` as opaque, and pass it on unchanged.

## `DurableState.Rows`

```ts
// ---cut-start---
import { DurableState, StreamAddress } from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
type Rows<C extends StreamAddress.Collections> = {
  readonly [K in keyof C & string]: ReadonlyMap<string, C[K]["schema"]["Type"]>;
};
// ---cut-after---
type Issue = { readonly id: string; readonly title: string };
type Project = { readonly id: number; readonly name: string };
type Tracker = {
  issue: StreamAddress.Collection<Issue, Issue, never, never, "id">;
  project: StreamAddress.Collection<Project, Project, never, never, "id">;
};
same<Rows<Tracker>, DurableState.Rows<Tracker>>(true);
```

`Rows<C>` holds one map for each collection of `C`, from the State key to the value of the row. A State key is a `string`, so a row with the number key `7` is under `"7"`.
