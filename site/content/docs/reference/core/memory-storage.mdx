---
title: MemoryStorage
description: Reference for the MemoryStorage namespace in @streamsy/core. It keeps streams in the process, for development and tests.
---

```ts
import { MemoryStorage, Streamsy, type CommitBoundary, type Storage } from "@streamsy/core";
import type { StreamsReader, StreamsWriter } from "@streamsy/core/protocol";
import type { Layer } from "effect";
```

`MemoryStorage` keeps streams in the memory of the process, and the data is gone when the scope of the Layer closes. Each mutation copies the whole store, so the time of an append grows with the size of the store. Use it for development and tests. See [Memory](/docs/storage#memory).

## `MemoryStorage.layer`

```ts
// ---cut-start---
import type { Context, Effect, Layer, Option } from "effect";
import {
  MemoryStorage,
  Streamsy,
  type CommitBoundary,
  type Storage,
  type StorageFault,
} from "@streamsy/core";
import type { CommitHooks, OwnerRecords, ProjectionMarks } from "@streamsy/core/internal";
import { same } from "./reference-check.ts";
// ---cut-end---
declare function layer<const Keys extends ReadonlyArray<Streamsy.Any>>(
  group: Streamsy.Group<Keys>,
  options?: MemoryStorage.Options,
): Layer.Layer<
  | Storage
  | CommitBoundary
  | OwnerRecords
  | CommitHooks
  | ProjectionMarks
  | Streamsy.Host<Streamsy.Group<Keys>>
>;

// OwnerRecords, CommitHooks, and ProjectionMarks have no exported name in a
// public entry point. See "Types with no exported name" at the end of this page.
// ---cut-after---
same<typeof layer, typeof MemoryStorage.layer>(true);
```

`layer` returns a Layer that provides the stream services of `group`, over one memory store. The Layer also provides [`Storage`](/docs/reference/core/storage#storage), [`CommitBoundary`](/docs/reference/core/storage#commitboundary), and the [internal services](#types-with-no-exported-name) `OwnerRecords`, `CommitHooks`, and `ProjectionMarks`. With them, the projection checkpoint store and the pending marks of a durable attached projection run on the same store. Each build of the Layer starts with an empty store.

```ts
// @filename: streams.ts
export * from "./shop-streams.ts";
// @filename: index.ts
// ---cut---
import { ManagedRuntime } from "effect";
import { MemoryStorage } from "@streamsy/core";
import { shop } from "./streams.ts";

const runtime = ManagedRuntime.make(MemoryStorage.layer(shop));
```

## `MemoryStorage.layerProtocol`

```ts
// ---cut-start---
import type { Context, Effect, Layer, Option } from "effect";
import {
  MemoryStorage,
  type CommitBoundary,
  type Storage,
  type StorageFault,
} from "@streamsy/core";
import type { StreamsReader, StreamsWriter } from "@streamsy/core/protocol";
import type { CommitHooks, OwnerRecords, ProjectionMarks } from "@streamsy/core/internal";
import { same } from "./reference-check.ts";
// ---cut-end---
declare function layerProtocol(
  options?: MemoryStorage.Options,
): Layer.Layer<
  | CommitBoundary
  | CommitHooks
  | OwnerRecords
  | ProjectionMarks
  | Storage
  | StreamsReader
  | StreamsWriter
>;

// OwnerRecords, CommitHooks, and ProjectionMarks have no exported name in a
// public entry point. See "Types with no exported name" at the end of this page.
// ---cut-after---
same<typeof layerProtocol, typeof MemoryStorage.layerProtocol>(true);
```

`layerProtocol` returns a Layer with the generic protocol reader and writer over a memory store, and no stream classes. [`StreamsReader`](/docs/reference/core/protocol#streamsreader) and [`StreamsWriter`](/docs/reference/core/protocol#streamswriter) read and write any stream id. Protocol tools and tests use `layerProtocol`, for example to write raw messages that a typed service does not write.

## `MemoryStorage.Options`

```ts
// ---cut-start---
import { MemoryStorage } from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
interface Options {
  readonly constrained?: boolean;
  readonly pollIntervalMs?: number;
  readonly readLimit?: number;
  readonly longPollTimeoutMs?: number;
}
// ---cut-after---
same<Options, MemoryStorage.Options>(true);
```

`Options` holds the options of `layer` and `layerProtocol`.

| Option              | Meaning                                                                                                                            |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `constrained`       | When `true`, the store has the smallest capabilities: `copy` forks, `stream` atomic scope, `poll` wakes, and a `lazy` expiry index |
| `pollIntervalMs`    | The poll interval of `changes` in constrained mode. The default is 25 ms                                                           |
| `readLimit`         | The largest number of messages in one catch-up page. The default is 1000                                                           |
| `longPollTimeoutMs` | The longest wait of a long-poll read. The default is 30 s                                                                          |

Without `constrained`, the store has `chain` forks, `store` atomic scope, `push` wakes, and an `indexed` expiry index. Use `constrained: true` in tests to check that a program does not depend on these capabilities.

Building the Layer dies with a `RangeError` when `pollIntervalMs` or `longPollTimeoutMs` is not a positive finite number, or when `readLimit` is not a positive safe integer.

## Types with no exported name

The Layer signatures name three services from `@streamsy/core/internal`. They connect a storage host to `@streamsy/projection`, and no public entry point exports them.

```ts
// ---cut-start---
import type { Context, Effect, Option, Scope } from "effect";
import type { SqlError } from "effect/sql";
import type { StorageFault, StreamId } from "@streamsy/core";
import type * as Internal from "@streamsy/core/internal";
import { same } from "./reference-check.ts";
// ---cut-end---
interface OwnerRecords extends Context.ServiceClass.Shape<
  "@streamsy/core/internal/OwnerRecords",
  {
    readonly read: (key: string) => Effect.Effect<Option.Option<string>, StorageFault>;
    readonly write: (key: string, encoded: string) => Effect.Effect<void, StorageFault>;
    readonly remove: (key: string) => Effect.Effect<void, StorageFault>;
  }
> {}

interface CommitHooks extends Context.ServiceClass.Shape<
  "@streamsy/core/internal/CommitHooks",
  {
    readonly beforeCommit: (
      hook: (ids: ReadonlySet<StreamId>) => Effect.Effect<void, SqlError.SqlError>,
    ) => Effect.Effect<void, never, Scope.Scope>;
  }
> {}

interface ProjectionMarks extends Context.ServiceClass.Shape<
  "@streamsy/core/internal/ProjectionMarks",
  {
    readonly mark: (
      projection: string,
      params: ReadonlyArray<string>,
    ) => Effect.Effect<void, SqlError.SqlError>;
    readonly nextDue: (projection: string) => Effect.Effect<Option.Option<number>, StorageFault>;
    readonly due: (
      projection: string,
      now: number,
      limit: number,
    ) => Effect.Effect<ReadonlyArray<PendingMark>, StorageFault>;
    readonly read: (
      projection: string,
      params: ReadonlyArray<string>,
    ) => Effect.Effect<ReadonlyMap<string, PendingMark>, StorageFault>;
    readonly clear: (
      projection: string,
      params: string,
      seq: number,
    ) => Effect.Effect<void, StorageFault>;
    readonly remove: (projection: string, params: string) => Effect.Effect<void, StorageFault>;
    readonly defer: (
      projection: string,
      params: string,
      attempts: number,
      dueAt: number,
    ) => Effect.Effect<void, StorageFault>;
    readonly deferred: (projection: string) => Effect.Effect<number, StorageFault>;
  }
> {}

// One pending mark: a binding whose input has commits that may not have run yet.
interface PendingMark {
  readonly params: string;
  readonly seq: number;
  readonly attempts: number;
  readonly dueAt: number;
}
// ---cut-after---
same<OwnerRecords, Internal.OwnerRecords>(true);
same<CommitHooks, Internal.CommitHooks>(true);
same<ProjectionMarks, Internal.ProjectionMarks>(true);
same<PendingMark, Internal.PendingMark>(true);
```

`@streamsy/projection` uses each service for one job:

- `OwnerRecords` holds the encoded records of the projection checkpoint store
- `CommitHooks` runs each hook that `beforeCommit` registers inside every later owned transaction that writes at least one stream id. The hook runs after the body and before the commit, and receives the ids that the transaction created, appended to, or deleted. Its writes commit or roll back with the transaction. The memory store turns a hook failure into a defect. Closing the scope of `beforeCommit` removes the hook
- `ProjectionMarks` holds the pending marks of durable attached projections, keyed by projection id and params. The memory store keeps them with the streams, so they are gone when the scope of the Layer closes. See [`AttachOptions`](/docs/reference/projection/units#attachoptions)
