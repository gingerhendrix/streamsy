---
title: Options and results
description: Reference for the protocol options and results in @streamsy/core. The stream methods take these options and succeed with these results.
---

```ts
import {
  AppendResult,
  CreateResult,
  type AppendCallOptions,
  type AppendOptions,
  type CreateOptions,
  type HeadResult,
  type ProducerOptions,
  type ReadMessage,
  type ReadNextOptions,
  type ReadNextResult,
  type ReadOptions,
  type ReadResult,
} from "@streamsy/core";
```

The methods of a stream class take these options and succeed with these results. `CreateResult` and `AppendResult` are also values, with a constructor and a matcher for each case. For the failures, see [Toolkit types](/docs/reference/core/toolkit) and [Errors](/docs/reference/core/errors).

## Create

### `CreateOptions`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
interface CreateOptions {
  readonly contentType?: string;
  readonly ttlSeconds?: number;
  readonly expiresAt?: string;
  readonly closed?: boolean;
  readonly forkedFrom?: string;
  readonly forkOffset?: string;
  readonly forkSubOffset?: number;
  readonly initialData?: Uint8Array;
}
// ---cut-after---
same<CreateOptions, Core.CreateOptions>(true);
```

| Option          | Meaning                                                                                                          |
| --------------- | ---------------------------------------------------------------------------------------------------------------- |
| `contentType`   | The content type of the stream. A stream class sets it from the address                                          |
| `ttlSeconds`    | The time to live, in seconds. Each append and each read restarts it                                              |
| `expiresAt`     | A fixed expiry time                                                                                              |
| `closed`        | `true` to create the stream already closed                                                                       |
| `forkedFrom`    | The id of the source stream of a fork. `fork` sets it from `source`                                              |
| `forkOffset`    | The fork copies every source message up to and including this offset                                             |
| `forkSubOffset` | The fork also copies the start of the next source message. For a JSON stream it counts messages, otherwise bytes |
| `initialData`   | The first messages, written in the same operation as the create                                                  |

Set `ttlSeconds` or `expiresAt`, not both. A fork that sets neither keeps the expiry of its source.

When a stream with the id already exists, `create` succeeds with `Exists` if the options match that stream. If they do not match, `create` fails with `CreateConflict`. See [Create and fork](/docs/streams/create).

### `CreateResult`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
type CreateResult =
  | {
      readonly _tag: "Created";
      readonly nextOffset: string;
      readonly contentType: string;
      readonly closed: boolean;
    }
  | {
      readonly _tag: "Exists";
      readonly nextOffset: string;
      readonly contentType: string;
      readonly closed: boolean;
    };
// ---cut-after---
same<CreateResult, Core.CreateResult>(true);
```

`create` returns `Created` when it made a new stream, and `Exists` when a stream with the same id and options was already there. In both cases `nextOffset` is the tail of the stream.

The value `CreateResult` is an Effect `Data.taggedEnum`. To handle both cases, call its matcher:

```ts
import { CreateResult } from "@streamsy/core";

declare const result: CreateResult;

const isNew = CreateResult.$match(result, {
  Created: () => true,
  Exists: () => false,
});
```

## Append

### `AppendCallOptions`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import type { AppendOptions } from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
type AppendCallOptions = Omit<AppendOptions, "data" | "contentType">;
// ---cut-after---
same<AppendCallOptions, Core.AppendCallOptions>(true);
```

`AppendCallOptions` is the `options` argument of `append` on a stream class. It has `seq`, `producer`, `close`, and `expectedOffset`. The stream class encodes the body and takes the content type from the address, so it omits `data` and `contentType`.

### `AppendOptions`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import type { ProducerOptions } from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
interface AppendOptions {
  readonly data: Uint8Array;
  readonly contentType: string;
  readonly seq?: string;
  readonly producer?: ProducerOptions;
  readonly close?: boolean;
  readonly expectedOffset?: string;
}
// ---cut-after---
same<AppendOptions, Core.AppendOptions>(true);
```

`AppendOptions` holds the options of one append on the protocol writer.

| Option           | Meaning                                                                                             |
| ---------------- | --------------------------------------------------------------------------------------------------- |
| `data`           | The encoded body                                                                                    |
| `contentType`    | The content type of the body. It must match the content type of the stream                          |
| `seq`            | The `Stream-Seq` of the writer. Each `seq` must sort after the previous one, compared as strings    |
| `producer`       | The producer position. The server accepts each position once                                        |
| `close`          | `true` to close the stream after this append. With an empty body, the append only closes the stream |
| `expectedOffset` | The append succeeds only when the tail is this offset                                               |

The append fails with `AppendConflict` when the content type differs from the stream, or when `seq` does not sort after the previous one. When `expectedOffset` differs from the tail, the append fails with `OffsetMismatch` and changes nothing: it writes no messages, does not close the stream, and does not update the producer state. `expectedOffset` is a Streamsy extension to the Durable Streams protocol. See [Conditional writes](/docs/streams/write#conditional-writes).

### `ProducerOptions`

```ts
// ---cut-start---

interface ProducerOptions {
  readonly producerId: string;
  readonly producerEpoch: number;

// ---cut-after---

```

`ProducerOptions` has the same fields as [`Producer.Position`](/docs/reference/core/producer#producerposition), and that page gives the rules for each field.

### `AppendResult`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
type AppendResult =
  | {
      readonly _tag: "Appended";
      readonly offset: string;
      readonly producerEpoch?: number;
      readonly producerSeq?: number;
      readonly closed: boolean;
    }
  | {
      readonly _tag: "Duplicate";
      readonly offset: string;
      readonly producerEpoch: number;
      readonly producerSeq: number;
      readonly closed: boolean;
    };
// ---cut-after---
same<AppendResult, Core.AppendResult>(true);
```

| Case        | When                                                   | `offset`                                      |
| ----------- | ------------------------------------------------------ | --------------------------------------------- |
| `Appended`  | The append wrote its items                             | The tail after this append                    |
| `Duplicate` | The server had already accepted this producer position | The current tail, at or after the first write |

`Appended` has `producerEpoch` and `producerSeq` when the append sent a `producer`. `Duplicate` has the current epoch of the producer and the last sequence number that the server accepted. In both cases `closed` is `true` when the stream is closed after the call.

Like `CreateResult`, the value `AppendResult` is a `Data.taggedEnum` with `$is` and `$match`.

## Read

### `ReadOptions`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
interface ReadOptions {
  offset?: string;
}
// ---cut-after---
same<ReadOptions, Core.ReadOptions>(true);
```

A read starts after `offset`, so the first message it returns is the one after `offset`.

| `offset`         | Reads from                    |
| ---------------- | ----------------------------- |
| Not set, or `-1` | The start of the stream       |
| `now`            | The current tail              |
| An offset        | The message after this offset |

A read with any other value fails with `InvalidReadRequest`.

### `ReadNextOptions`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
interface ReadNextOptions {
  offset: string;
  cursor?: string;
}
// ---cut-after---
same<ReadNextOptions, Core.ReadNextOptions>(true);
```

`ReadNextOptions` holds the options of one long-poll wait, which `session` makes. `offset` takes the same values as in `ReadOptions`. Set `cursor` to the `cursor` of the previous `ReadNextResult`. The cursor lets a CDN collapse the waits of many readers into one request to the origin. See [Session](/docs/streams/read#session).

### `ReadResult`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import type { ReadMessage } from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
interface ReadResult {
  readonly contentType: string;
  readonly messages: ReadonlyArray<ReadMessage>;
  readonly nextOffset: string;
  readonly upToDate: boolean;
  readonly closed: boolean;
}
// ---cut-after---
same<ReadResult, Core.ReadResult>(true);
```

`ReadResult` is one batch from the protocol reader, before the codec decodes it.

| Field        | Meaning                                                                                                                 |
| ------------ | ----------------------------------------------------------------------------------------------------------------------- |
| `messages`   | The stored messages after the read offset                                                                               |
| `nextOffset` | The offset of the last message in the batch, or the tail when the batch is empty. The next read starts from this offset |
| `upToDate`   | `true` when `nextOffset` is the tail of the stream                                                                      |
| `closed`     | `true` when the stream is closed and this batch reached the tail                                                        |

A stream class decodes each `ReadResult` into a [`Batch`](/docs/reference/core/toolkit#batch).

### `ReadNextResult`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import type { ReadResult } from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
interface ReadNextResult extends ReadResult {
  readonly cursor: string;
  readonly timedOut: boolean;
}
// ---cut-after---
same<ReadNextResult, Core.ReadNextResult>(true);
```

`ReadNextResult` is the result of one long-poll wait. `timedOut` is `true` when the wait ended without new messages. Pass `cursor` in the next `ReadNextOptions`.

### `ReadMessage`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
interface ReadMessage {
  readonly data: Uint8Array;
}
// ---cut-after---
same<ReadMessage, Core.ReadMessage>(true);
```

`ReadMessage` is one stored message, as bytes. Storage also keeps the offset and the write time of each message, but a read does not return them.

### `HeadResult`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
interface HeadResult {
  readonly contentType: string;
  readonly nextOffset: string;
  readonly ttlSeconds?: number;
  readonly expiresAt?: string;
  readonly closed: boolean;
}
// ---cut-after---
same<HeadResult, Core.HeadResult>(true);
```

`head` returns a `HeadResult`: the tail of the stream as `nextOffset`, and its configuration, without any messages. Unlike a read, a `head` does not restart the time to live.
