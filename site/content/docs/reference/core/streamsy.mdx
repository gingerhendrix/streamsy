---
title: Streamsy
description: Reference for the Streamsy namespace in @streamsy/core. It declares stream classes and groups them for a host.
---

```ts
import { Streamsy, StreamAddress } from "@streamsy/core";
import type {
  AppendCallOptions,
  AppendResult,
  CreateOptions,
  CreateResult,
  DecodeFault,
  HeadResult,
  ReadNextOptions,
  ReadNextResult,
  ReadOptions,
  StreamsFault,
} from "@streamsy/core";
import type { Reader, StreamRoute, Streams, Writer } from "@streamsy/core/protocol";
import type { Context, Effect, Function, Option, Schema, Stream } from "effect";
```

A stream class declares a set of streams with a service name, an id template, and a codec. A group lists the stream classes that one host stores and serves. For a worked example, see [Declare streams](/docs/streams/declare).

The root of `@streamsy/core` also exports each member of `Streamsy` under its own name, for example `json` and `group`. `json` and `Streamsy.json` are the same function.

The signatures use `StreamRoute` from `@streamsy/core/protocol`. `StreamRoute.ParamCodecs` is a record with one `Schema.Codec<unknown, string>` for each template param. `StreamRoute.Params<C>` is the record of decoded params. `StreamRoute.ExactTemplateParams` makes the compiler check that the template and the record name the same params.

## `Streamsy.json`

```ts
// ---cut-start---
import type { Schema } from "effect";
import { Streamsy } from "@streamsy/core";
import type { StreamRoute } from "@streamsy/core/protocol";
import { same } from "./reference-check.ts";
// ---cut-end---
declare function json<Self>(): <
  const Name extends string,
  const Template extends string,
  Codecs extends StreamRoute.ParamCodecs,
  A,
  I,
  RD,
  RE,
>(
  name: Name,
  template: Template,
  options: {
    readonly params: Codecs & StreamRoute.ExactTemplateParams<Template, Codecs>;
    readonly schema: Schema.Codec<A, I, RD, RE>;
  },
) => Streamsy.JsonClass<Self, Name, Template, Codecs, A, I, RD, RE>;
// ---cut-after---
same<typeof json, typeof Streamsy.json>(true);
```

`json` declares a stream class whose items are values of `schema`, stored as JSON with the content type `application/json`. The server stores each item of an append as a separate message.

`json` takes the class type first and the arguments second. Call it twice and extend the result:

```ts
import { Schema } from "effect";
import { Streamsy } from "@streamsy/core";

const Note = Schema.Struct({ id: Schema.String, text: Schema.String });

class Drafts extends Streamsy.json<Drafts>()("Notes/Drafts", "drafts/:draftId", {
  params: { draftId: Schema.String },
  schema: Note,
}) {}
```

Each argument has its own rules:

- `name` is the global name of the service, and the service key is `@streamsy/core/Stream/<name>`. Two classes with the same name are the same service, so prefix each name with an application namespace, as in `Notes/Drafts`. The name `Wildcard` is reserved.
- `template` is a relative path in which a `:name` segment is a param, for example `drafts/:draftId`.
- `params` has one codec for each `:name` in the template, and no other codec. The compiler checks this when `template` is a string literal. The call also checks it at run time and throws a `RangeError` on a mismatch, which catches a `template` typed as a plain `string`.

## `Streamsy.bytes`

```ts
// ---cut-start---
import { Streamsy } from "@streamsy/core";
import type { StreamRoute } from "@streamsy/core/protocol";
import { same } from "./reference-check.ts";
// ---cut-end---
declare function bytes<Self>(): <
  const Name extends string,
  const Template extends string,
  Codecs extends StreamRoute.ParamCodecs,
>(
  name: Name,
  template: Template,
  options: {
    readonly params: Codecs & StreamRoute.ExactTemplateParams<Template, Codecs>;
    readonly contentType?: string;
  },
) => Streamsy.BytesClass<Self, Name, Template, Codecs>;
// ---cut-after---
same<typeof bytes, typeof Streamsy.bytes>(true);
```

`bytes` declares a stream class whose items are `Uint8Array` values. An append concatenates its items into one request body, and the server stores that body as one message. The default content type is `application/octet-stream`.

The rules for `name`, `template`, and `params` are the same as for [`Streamsy.json`](#streamsyjson). An append with an empty `Uint8Array` item dies with a `RangeError`.

## `Streamsy.state`

```ts
// ---cut-start---
import { Streamsy, StreamAddress } from "@streamsy/core";
import type { StreamRoute } from "@streamsy/core/protocol";
import { same } from "./reference-check.ts";
// ---cut-end---
declare function state<Self>(): <
  const Name extends string,
  const Template extends string,
  Codecs extends StreamRoute.ParamCodecs,
  const Collections extends StreamAddress.Collections,
>(
  name: Name,
  template: Template,
  options: {
    readonly params: Codecs & StreamRoute.ExactTemplateParams<Template, Codecs>;
    readonly collections: Collections & StreamAddress.ValidCollections<Collections>;
  },
) => Streamsy.StateClass<Self, Name, Template, Codecs, Collections>;
// ---cut-after---
same<typeof state, typeof Streamsy.state>(true);
```

`state` declares a Durable State stream class. Each key of `collections` is the `type` of one collection on the wire. Each entry gives the value schema of the collection and the value field that becomes the `key` of each change. The items are [`StreamAddress.CollectionsEvent`](/docs/reference/core/stream-address#streamaddresscollectionsevent) values, which are changes to any collection and State control messages.

The rules for `name`, `template`, and `params` are the same as for [`Streamsy.json`](#streamsyjson). Each `key` must name a `string` or `number` field of its own collection, and the compiler reports a wrong `key` on that collection. To build changes, see [`DurableState`](/docs/reference/core/durable-state).

## `Streamsy.custom`

```ts
// ---cut-start---
import type { Option } from "effect";
import { Streamsy, StreamAddress } from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
declare function custom<Self>(): <const Name extends string, P, A, RD, RE>(
  name: Name,
  options: {
    readonly parse: (id: string) => Option.Option<P>;
    readonly address: (params: P) => StreamAddress.StreamAddress<A, RD, RE>;
  },
) => Streamsy.CustomClass<Self, Name, P, A, RD, RE>;
// ---cut-after---
same<typeof custom, typeof Streamsy.custom>(true);
```

`custom` declares a stream class for an id grammar that a template cannot express. `parse` returns the params of an id that the class owns, or `None` for any other id. `address` builds the address for a set of params. `parse(address(params).id)` must return `Some(params)`, and Streamsy does not check this.

A custom class has an empty `template`, so a group cannot check it for overlap with other classes. When two classes match an id, the first of them in the group owns the id.

## `Streamsy.group`

```ts
// ---cut-start---
import { Streamsy } from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
declare function group<const Keys extends ReadonlyArray<Streamsy.Any>>(
  ...keys: Keys
): Streamsy.Group<Keys>;
// ---cut-after---
same<typeof group, typeof Streamsy.group>(true);
```

`group` lists the stream classes that one host stores and serves. The storage Layers, `Http.routes`, and `RemoteStreams.layer` take a group. `group` freezes the group object and its list.

`group` throws a `RangeError` in each of these cases:

- two classes have the same name
- two classes have the same template
- two templates can match the same id
- `Streamsy.Wildcard` is not the last class

See [Groups](/docs/streams/declare#groups).

## `Streamsy.Wildcard`

```ts
// ---cut-start---
import { Option } from "effect";
import { Streamsy, StreamAddress } from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
class Wildcard extends Streamsy.custom<Wildcard>()("Wildcard", {
  parse: (id: string) => Option.some({ id }),
  address: ({ id }: { readonly id: string }) => StreamAddress.bytes(id),
}) {}
// ---cut-after---
same<typeof Wildcard, typeof Streamsy.Wildcard>(true);
same<Wildcard, Streamsy.Wildcard>(true);
```

`Wildcard` is a custom stream class that owns every id. Its items are bytes with the content type `application/octet-stream`. To store and serve the ids that no other class owns, put `Wildcard` last in a group.

## `Streamsy.Class`

```ts
// ---cut-start---
import type { Context, Schema } from "effect";
import { Streamsy } from "@streamsy/core";
import type { StreamRoute } from "@streamsy/core/protocol";
import { same } from "./reference-check.ts";
// ---cut-end---
type Class<
  Self,
  Name extends string,
  P,
  A,
  RD,
  RE,
  R extends StreamRoute.StreamRoute<P, A, RD, RE>,
> = Context.ServiceClass<Self, `@streamsy/core/Stream/${Name}`, Streamsy.Api<P, A, RD, RE>> &
  R & {
    readonly at: (params: P) => ReturnType<R["address"]> & Streamsy.Address<A, Self, RD, RE>;
  };
// ---cut-after---
interface Self {
  readonly self: unique symbol;
}
interface Item {
  readonly id: string;
}
interface Decoding {
  readonly decoding: unique symbol;
}
type P = { readonly noteId: string };
type R = StreamRoute.StreamRoute<P, Item>;
same<
  Class<Self, "Notes", P, Item, never, never, R>,
  Streamsy.Class<Self, "Notes", P, Item, never, never, R>
>(true);
type RD = StreamRoute.StreamRoute<P, Item, Decoding>;
same<
  Class<Self, "Notes", P, Item, Decoding, never, RD>,
  Streamsy.Class<Self, "Notes", P, Item, Decoding, never, RD>
>(true);
```

`Class` is the type of every stream class. A stream class has three parts:

| Part              | Gives                                                                          |
| ----------------- | ------------------------------------------------------------------------------ |
| An Effect service | `yield* Notes` returns the [`Streamsy.Api`](#streamsyapi) of the class `Notes` |
| The route `R`     | `template`, `match(id)`, and `parse(id)`                                       |
| `at(params)`      | The address of one stream, with the `stream` key of the class                  |

`at` throws a `RangeError` when a param does not encode to a valid id segment. [Templates and addresses](/docs/streams/declare#templates-and-addresses) lists the id rules.

`RD` is the set of services that the codec needs to decode, and `RE` is the set of services that it needs to encode. Both are `never` for most schemas.

## `Streamsy.Api`

```ts
// ---cut-start---
import type { Effect, Function, Stream } from "effect";
import type {
  AppendCallOptions,
  AppendResult,
  CreateOptions,
  CreateResult,
  DecodeFault,
  HeadResult,
  ReadNextOptions,
  ReadNextResult,
  ReadOptions,
  StreamsFault,
} from "@streamsy/core";
import { Streamsy } from "@streamsy/core";
import type { Reader, StreamRoute, Streams, Writer } from "@streamsy/core/protocol";
import { same } from "./reference-check.ts";
// ---cut-end---
interface Api<P, A, RD = never, RE = never> {
  readonly owner: object;
  readonly route: StreamRoute.StreamRoute<P, A, RD, RE>;
  readonly wire: Reader<StreamsFault> & Writer<StreamsFault>;
  readonly create: (
    params: P,
    options?: Omit<CreateOptions, "contentType">,
  ) => Effect.Effect<CreateResult, Streams.CreateFailure>;
  readonly append: <const O extends AppendCallOptions = {}>(
    params: P,
    items: Streams.AppendItems<A, O>,
    options?: O,
  ) => Effect.Effect<AppendResult, Streams.AppendFailure<O>, RE>;
  readonly read: (
    params: P,
    options?: ReadOptions,
  ) => Stream.Stream<Streams.Batch<A>, Streams.ReadFailure, RD>;
  readonly fold: <S>(
    params: P,
    initial: Function.LazyArg<S>,
    f: (state: S, item: A) => S,
    options?: ReadOptions,
  ) => Effect.Effect<Streams.Folded<S>, Streams.ReadFailure, RD>;
  readonly collect: (
    params: P,
    options?: ReadOptions,
  ) => Effect.Effect<Streams.Collected<A>, Streams.ReadFailure, RD>;
  readonly decide: <S, B, E, R>(
    params: P,
    spec: Streams.DecideSpec<A, S, B, E, R>,
  ) => Effect.Effect<
    Streams.Decided<B>,
    Streams.ReadFailure | Streams.AppendFailure<{ expectedOffset: string }> | E,
    RD | RE | R
  >;
  readonly follow: (
    params: P,
    options?: Streams.FollowOptions,
  ) => Stream.Stream<Streams.Batch<A>, Streams.FollowFailure, RD>;
  readonly session: (
    params: P,
    options: ReadNextOptions,
  ) => Effect.Effect<ReadNextResult, Exclude<Streams.FollowFailure, DecodeFault>>;
  readonly head: (params: P) => Effect.Effect<HeadResult, Streams.HeadFailure>;
  readonly remove: (params: P) => Effect.Effect<void, Streams.RemoveFailure>;
  readonly fork: (
    params: P,
    source: P,
    options?: Omit<CreateOptions, "contentType" | "forkedFrom">,
  ) => Effect.Effect<CreateResult, Streams.CreateFailure>;
}
// ---cut-after---
interface Item {
  readonly id: string;
}
interface Decoding {
  readonly decoding: unique symbol;
}
interface Encoding {
  readonly encoding: unique symbol;
}
type P = { readonly noteId: string };
same<Api<P, Item>, Streamsy.Api<P, Item>>(true);
same<Api<P, Item, Decoding, Encoding>, Streamsy.Api<P, Item, Decoding, Encoding>>(true);
```

`Api` is the service of a stream class. Each method takes the params of one stream as its first argument, and it can reach only the ids of its own class. A call with an id outside the class dies with a `RangeError`.

| Method    | Does                                                                               | Guide                                                      |
| --------- | ---------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| `create`  | Creates the stream, with the content type of the address                           | [Create](/docs/streams/create#create)                      |
| `fork`    | Creates a child stream from a `source` of the same class                           | [Fork](/docs/streams/create#fork)                          |
| `remove`  | Deletes the stream                                                                 | [Remove](/docs/streams/create#remove)                      |
| `append`  | Encodes the items and writes them as one atomic append                             | [Append](/docs/streams/write#append)                       |
| `read`    | Reads the stored batches after `offset`, up to the current tail                    | [Read](/docs/streams/read#read)                            |
| `collect` | Reads to the current tail and returns every item                                   | [Read](/docs/streams/read#read)                            |
| `fold`    | Reads to the current tail and folds every item into one value                      | [Fold](/docs/streams/read#fold)                            |
| `decide`  | Folds the stream, calls your `decide` function, then appends with `expectedOffset` | [Read, fold, append](/docs/streams/write#read-fold-append) |
| `follow`  | Reads to the tail, then waits for new batches until the stream closes              | [Follow](/docs/streams/read#follow)                        |
| `session` | Makes one raw long-poll wait                                                       | [Session](/docs/streams/read#session)                      |
| `head`    | Returns the tail and the configuration, without messages                           | [Read](/docs/streams/read)                                 |

`append` takes a non-empty list of items, unless `options` has `close: true`. Its error type lists only the rejections that `options` make possible. See [`AppendErrorFor`](/docs/reference/core/errors#appenderrorfor).

`fork` fails with `ForkSourceNotFound` when `source` is outside the class. `session`, `head`, and `remove` do not decode items, so their error types have no `DecodeFault`.

Projection, Serve, and the storage hosts use `owner`, `route`, and `wire`. An application uses only the methods.

## `Streamsy.Address`

```ts
// ---cut-start---
import type { Context } from "effect";
import { Streamsy, StreamAddress, type StreamsFault } from "@streamsy/core";
import type { Reader, Writer } from "@streamsy/core/protocol";
import { same } from "./reference-check.ts";
// ---cut-end---
type Address<A, R, RD = never, RE = never> = StreamAddress.StreamAddress<A, RD, RE> & {
  readonly stream: Context.Key<
    R,
    { readonly owner: object; readonly wire: Reader<StreamsFault> & Writer<StreamsFault> }
  >;
};
// ---cut-after---
interface Self {
  readonly self: unique symbol;
}
interface Decoding {
  readonly decoding: unique symbol;
}
same<Address<string, Self>, Streamsy.Address<string, Self>>(true);
same<Address<string, Self, Decoding>, Streamsy.Address<string, Self, Decoding>>(true);
```

`at(params)` returns an `Address`: a [`StreamAddress.StreamAddress`](/docs/reference/core/stream-address#streamaddressstreamaddress) with the service key of its class as `stream`. An address names one stream. It holds no stream data, and it is not an Effect `Ref`. Projection inputs, `DurableState.changes`, and Serve routes take addresses.


`Any` matches any stream class. It keeps only the parts that a host needs: the service key, `template`, and `match`. A group and a storage Layer take a list of `Any`.

```ts

import { Streamsy } from "@streamsy/core";
```
