title: Toolkit types
description: Reference for the toolkit types in @streamsy/core. The methods of a stream class succeed with these batches and fold results, and fail with these failure unions.
---

```ts
import type {
  AppendFailure,
  Batch,
  Collected,
  CreateFailure,
  DecideSpec,
  Decided,
  Decision,
  Folded,
  FollowFailure,
  HeadFailure,
  OffsetMismatch,
  ReadFailure,
  RemoveFailure,
} from "@streamsy/core";
import type { Effect, Function, Schedule } from "effect";
```

The methods of a stream class return decoded items and fold results in these types, and they fail with the failure unions at the end of this page. The [`Streamsy.Api`](/docs/reference/core/streamsy#streamsyapi) section lists the methods. The protocol options and results are on [Options and results](/docs/reference/core/options-and-results).

## Results

### `Batch`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
interface Batch<A> {
  readonly items: ReadonlyArray<A>;
  readonly nextOffset: string;
  readonly upToDate: boolean;
  readonly closed: boolean;
}
// ---cut-after---
same<Batch<string>, Core.Batch<string>>(true);
```

A `Batch` holds decoded items and the read position after them. `read` and `follow` return a stream of batches. `nextOffset`, `upToDate`, and `closed` mean the same as in [`ReadResult`](/docs/reference/core/options-and-results#readresult). To continue reading later, pass `nextOffset` as the `offset` of the next read.

`follow` emits no empty batches, with one exception: the last batch of a closed stream can be empty.

### `Collected`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
interface Collected<A> {
  readonly items: ReadonlyArray<A>;
  readonly offset: string;
}
// ---cut-after---
same<Collected<string>, Core.Collected<string>>(true);
```

`collect` returns a `Collected`: every item up to the tail, and the tail that the read reached as `offset`. Pass `offset` as `expectedOffset` to make a [conditional write](/docs/streams/write#conditional-writes), or as the `offset` of a later read.

### `Folded`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
interface Folded<S> {
  readonly state: S;
  readonly offset: string;
}
// ---cut-after---
same<Folded<number>, Core.Folded<number>>(true);
```

`fold` returns a `Folded`: the folded value as `state`, and the tail that the read reached as `offset`. To continue the fold later, pass `state` as `initial` and `offset` as `offset` in the options of the next `fold`. See [Fold](/docs/streams/read#fold).

### `DecideSpec`

```ts
// ---cut-start---
import type { Effect, Function, Schedule } from "effect";
import type * as Core from "@streamsy/core";
import type { Decision, OffsetMismatch } from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
interface DecideSpec<A, S, B, E, R> {
  readonly initial: Function.LazyArg<S>;
  readonly fold: (state: S, item: A) => S;
  readonly decide: (
    state: S,
    at: { readonly offset: string },
  ) => Effect.Effect<Decision<B, NoInfer<A>>, E, R>;
  readonly retry?: Schedule.Schedule<unknown, OffsetMismatch>;
}
// ---cut-after---
interface Fail {
  readonly fail: unique symbol;
}
interface Service {
  readonly service: unique symbol;
}
same<
  DecideSpec<string, number, boolean, Fail, Service>,
  Core.DecideSpec<string, number, boolean, Fail, Service>
>(true);
```

A `DecideSpec` is the input of the `decide` method. The method folds the stream into a state, calls your `decide` function on that state, and appends the items that it returns.

| Field     | Meaning                                                                                          |
| --------- | ------------------------------------------------------------------------------------------------ |
| `initial` | Returns the start value of the fold. Each call of the method calls `initial` once                |
| `fold`    | Returns the state after one more item                                                            |
| `decide`  | Returns a value and the items to append. `at.offset` is the tail that `state` includes           |
| `retry`   | The schedule for retries after another writer appends first. The default is `Schedule.recurs(3)` |

Your `decide` function must not write to the stream, and it must not mutate `state`. After a lost race, the method passes the state that it already has to `fold` together with the new items.

The append sets `expectedOffset` to the tail that the fold reached. When another writer appended first, the append fails with `OffsetMismatch`. The method then reads the new items, folds them, and calls `decide` again, for as long as `retry` allows. When `retry` stops, the method fails with the last `OffsetMismatch`. With the default schedule, one call makes at most four appends.

The method does not retry a fault, because a lost reply can hide an append that was written. See [Read, fold, append](/docs/streams/write#read-fold-append).

### `Decision`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
interface Decision<B, A> {
  readonly value: B;
  readonly items: ReadonlyArray<A>;
}
// ---cut-after---
same<Decision<number, string>, Core.Decision<number, string>>(true);
```

Your `decide` function returns a `Decision`. The method returns `value` to its caller and appends `items`. When `items` is empty, the method returns without an append and without a check of the tail.

### `Decided`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
interface Decided<B> {
  readonly value: B;
  readonly offset: string;
  readonly appended: boolean;
}
// ---cut-after---
same<Decided<number>, Core.Decided<number>>(true);
```

The `decide` method returns a `Decided`. `appended` is `true` when the method wrote items. `offset` is then the new tail. When the method wrote nothing, `offset` is the tail that the fold reached.

## Failures

Each failure type is the union of the protocol errors and the faults that one method can fail with. The protocol errors are on [Errors](/docs/reference/core/errors), and the faults are on [Faults](/docs/reference/core/faults).

### `ReadFailure`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import type {
  DecodeFault,
  InvalidReadRequest,
  StreamGone,
  StreamNotFound,
  StreamsFault,
} from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
type ReadFailure = StreamNotFound | StreamGone | InvalidReadRequest | StreamsFault | DecodeFault;
// ---cut-after---
same<ReadFailure, Core.ReadFailure>(true);
```

`read`, `collect`, and `fold` fail with `ReadFailure`.

### `FollowFailure`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import type { NotSupported, ReadFailure } from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
type FollowFailure = ReadFailure | NotSupported;
// ---cut-after---
same<FollowFailure, Core.FollowFailure>(true);
```

`follow` fails with `FollowFailure`. It adds `NotSupported` to `ReadFailure`, because a remote host can refuse a live read. `session` fails with the same union minus `DecodeFault`, because `session` does not decode items.

### `AppendFailure`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import type { AppendCallOptions, AppendErrorFor, EncodeFault, StreamsFault } from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
type AppendFailure<O = AppendCallOptions> = AppendErrorFor<O> | StreamsFault | EncodeFault;
// ---cut-after---
same<AppendFailure, Core.AppendFailure>(true);
same<AppendFailure<{}>, Core.AppendFailure<{}>>(true);
same<AppendFailure<{ expectedOffset: string }>, Core.AppendFailure<{ expectedOffset: string }>>(
  true,
);
```

An `append` with options of type `O` fails with `AppendFailure<O>`. The union depends on the options through [`AppendErrorFor`](/docs/reference/core/errors#appenderrorfor). It includes `OffsetMismatch` only when `O` has `expectedOffset`, and it includes `StaleEpoch` and `ProducerGap` only when `O` has `producer`.

```ts
// ---cut-start---
import type { AppendFailure, OffsetMismatch } from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
type Plain = Extract<AppendFailure<{}>, OffsetMismatch>;
// never

type Conditional = Extract<AppendFailure<{ expectedOffset: string }>, OffsetMismatch>;
// OffsetMismatch
// ---cut-after---
same<Plain, never>(true);
same<Conditional, OffsetMismatch>(true);
```

If a host answers with a rejection that the options rule out, the host has a bug, and the append dies with a defect.
