---
title: Errors
description: Reference for the protocol errors in @streamsy/core. Each error is a tagged class, and you catch it by its tag.
---

```ts
import { OffsetMismatch, StaleEpoch, isProtocolError, type AppendErrorFor } from "@streamsy/core";
```

The stream operations fail with these errors when the protocol rejects a request. Each error is a `Schema.TaggedError`, so it is an `Error` with a `_tag` that you can `yield*` in `Effect.gen`. To handle one error, catch it by its tag:

```ts
// @filename: streams.ts
export * from "./notes-streams.ts";
// @filename: index.ts
// ---cut---
import { Effect } from "effect";
import { Notes } from "./streams.ts";

const write = Effect.flatMap(Notes, (notes) =>
  notes.append({}, [{ id: "n1", text: "hello" }]),
).pipe(Effect.catchTag("StreamClosed", (error) => Effect.succeed(error.offset)));
```

Each block below shows the `_tag` and the fields of one error. Every error also has `message`, `name`, and `stack`. The `id` field is a [`StreamId`](/docs/reference/core/ids-and-offsets#streamid), which is a branded `string`.

Failures of the store, the network, or the codec are faults, such as `StorageFault` and `EncodeFault`. They are on the [Faults](/docs/reference/core/faults) page.

## Error classes

### `StreamNotFound`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import type { StreamId } from "@streamsy/core";
import { same, type Fields } from "./reference-check.ts";
// ---cut-end---
interface StreamNotFound {
  readonly _tag: "StreamNotFound";
  readonly id: StreamId;
}
// ---cut-after---
same<StreamNotFound, Fields<Core.StreamNotFound>>(true);
```

An operation fails with `StreamNotFound` when no stream has the id `id`.

### `StreamGone`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";

import { same, type Fields } from "./reference-check.ts";

  readonly _tag: "StreamGone";
  readonly id: StreamId;

// ---cut-after---
same<StreamGone, Fields<Core.StreamGone>>(true);
```

An operation fails with `StreamGone` when the stream `id` existed and was deleted.

### `StreamClosed`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import type { StreamId } from "@streamsy/core";
import { same, type Fields } from "./reference-check.ts";
// ---cut-end---

  readonly _tag: "StreamClosed";
  readonly id: StreamId;
  readonly offset: string;
}
// ---cut-after---
same<StreamClosed, Fields<Core.StreamClosed>>(true);
```

An append fails with `StreamClosed` when the stream is closed. `offset` is the tail at which the stream was closed.

### `OffsetMismatch`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import type { StreamId } from "@streamsy/core";
import { same, type Fields } from "./reference-check.ts";
// ---cut-end---
interface OffsetMismatch {
  readonly _tag: "OffsetMismatch";
  readonly id: StreamId;
  readonly expected: string;
  readonly actual: string;
}
// ---cut-after---
same<OffsetMismatch, Fields<Core.OffsetMismatch>>(true);
```

An append fails with `OffsetMismatch` when the tail of the stream is not its `expectedOffset`. `expected` is the offset that the append sent, and `actual` is the current tail. The append writes nothing. See [Conditional writes](/docs/streams/write#conditional-writes).

### `AppendConflict`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import type { StreamId } from "@streamsy/core";
import { same, type Fields } from "./reference-check.ts";
// ---cut-end---
interface AppendConflict {
  readonly _tag: "AppendConflict";
  readonly id: StreamId;
}
// ---cut-after---
same<AppendConflict, Fields<Core.AppendConflict>>(true);
```

An append fails with `AppendConflict` in two cases: its content type differs from the content type of the stream, or its `Stream-Seq` does not sort after the previous one. `message` says which case applies.

### `StreamBusy`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import type { StreamId } from "@streamsy/core";
import { same, type Fields } from "./reference-check.ts";
// ---cut-end---
interface StreamBusy {
  readonly _tag: "StreamBusy";
  readonly id: StreamId;
}
// ---cut-after---
same<StreamBusy, Fields<Core.StreamBusy>>(true);
```

An append fails with `StreamBusy` when other writers keep committing to the stream first. The append plans its write again after each lost commit, and it gives up after 64 attempts. The request is safe to send again. Over HTTP, the server answers `StreamBusy` with a `503`.

### `StaleEpoch`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import type { StreamId } from "@streamsy/core";
import { same, type Fields } from "./reference-check.ts";
// ---cut-end---
interface StaleEpoch {
  readonly _tag: "StaleEpoch";
  readonly id: StreamId;
  readonly currentEpoch: number;
}
// ---cut-after---
same<StaleEpoch, Fields<Core.StaleEpoch>>(true);
```

An append fails with `StaleEpoch` when its producer epoch is lower than the last epoch that the stream accepted for the same `producerId`. `currentEpoch` is that last epoch. See [`Producer.Position`](/docs/reference/core/producer#producerposition).

### `ProducerGap`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import type { StreamId } from "@streamsy/core";
import { same, type Fields } from "./reference-check.ts";
// ---cut-end---
interface ProducerGap {
  readonly _tag: "ProducerGap";
  readonly id: StreamId;
  readonly expectedSeq: number;
  readonly receivedSeq: number;
}
// ---cut-after---
same<ProducerGap, Fields<Core.ProducerGap>>(true);
```

An append fails with `ProducerGap` when its `producerSeq` skips a number. `expectedSeq` is the next number that the server accepts, and `receivedSeq` is the number that the append sent.

### `InvalidEpochSeq`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import type { StreamId } from "@streamsy/core";
import { same, type Fields } from "./reference-check.ts";
// ---cut-end---
interface InvalidEpochSeq {
  readonly _tag: "InvalidEpochSeq";
  readonly id: StreamId;
}
// ---cut-after---
same<InvalidEpochSeq, Fields<Core.InvalidEpochSeq>>(true);
```

The protocol append fails with `InvalidEpochSeq` when the producer epoch or sequence is not valid, for example a new epoch that does not start at `producerSeq` 0. The `append` method of a stream class does not list this error in its type. When a host returns it, the append dies with a defect.

### `InvalidAppendRequest`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import type { StreamId } from "@streamsy/core";
import { same, type Fields } from "./reference-check.ts";
// ---cut-end---
interface InvalidAppendRequest {
  readonly _tag: "InvalidAppendRequest";
  readonly id: StreamId;
}
// ---cut-after---
same<InvalidAppendRequest, Fields<Core.InvalidAppendRequest>>(true);
```

The protocol append fails with `InvalidAppendRequest` when the request is not valid, for example an append with no items and no `close`. `message` says why. The `append` method of a stream class does not list this error in its type. When a host returns it, the append dies with a defect.

### `CreateConflict`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import type { StreamId } from "@streamsy/core";
import { same, type Fields } from "./reference-check.ts";
// ---cut-end---
interface CreateConflict {
  readonly _tag: "CreateConflict";
  readonly id: StreamId;
  readonly reason?:
    "config-mismatch" | "soft-deleted" | "fork-content-type" | "fork-source-soft-deleted";
}
// ---cut-after---
same<CreateConflict, Fields<Core.CreateConflict>>(true);
```

A `create` or a `fork` fails with `CreateConflict` when its options do not match the stream that already has the id. `reason` says why, and `message` describes the conflict. An HTTP response does not carry the reason, so the remote client leaves `reason` out.

### `ForkSourceNotFound`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";

import { same, type Fields } from "./reference-check.ts";

}
// ---cut-after---

```

A `fork` fails with `ForkSourceNotFound` when its source stream does not exist. `id` is the stream that the fork would create, and `source` is the missing source.

### `InvalidForkRequest`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import type { StreamId } from "@streamsy/core";
import { same, type Fields } from "./reference-check.ts";
// ---cut-end---

  readonly _tag: "InvalidForkRequest";
  readonly id: StreamId;
}
// ---cut-after---
same<InvalidForkRequest, Fields<Core.InvalidForkRequest>>(true);
```

A `fork` fails with `InvalidForkRequest` when its fork offset is not a valid offset, or when the offset is past the tail of the source. `message` says which case applies.

### `NotSupported`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import type { StreamId } from "@streamsy/core";
import { same, type Fields } from "./reference-check.ts";
// ---cut-end---
interface NotSupported {
  readonly _tag: "NotSupported";
  readonly id: StreamId;
  readonly feature: string;
}
// ---cut-after---
same<NotSupported, Fields<Core.NotSupported>>(true);
```

An operation fails with `NotSupported` when the host or the remote client does not support `feature`, for example `fork`, `producer`, or `expected-offset`. An append on the memory host or a storage host never fails with `NotSupported`.

A read fails with `InvalidReadRequest` when the request is not valid, for example when the offset has the wrong format. `message` says why.

### `CreateConflictReason`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
type CreateConflictReason =
  "config-mismatch" | "soft-deleted" | "fork-content-type" | "fork-source-soft-deleted";
// ---cut-after---
same<CreateConflictReason, Core.CreateConflictReason>(true);
```

`CreateConflictReason` is the type of `CreateConflict.reason`.

| Reason                     | Meaning                                                        |
| -------------------------- | -------------------------------------------------------------- |
| `config-mismatch`          | A stream with this id exists with another configuration        |
| `soft-deleted`             | The id belongs to a deleted stream                             |
| `fork-content-type`        | The fork asked for a content type that differs from the source |
| `fork-source-soft-deleted` | The source of the fork was deleted                             |

## Errors by operation

Each protocol operation fails with one of these unions. The methods of a stream class add faults to them, as listed under [Failures](/docs/reference/core/toolkit#failures).

### `HeadError`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import type { StreamGone, StreamNotFound } from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
type HeadError = StreamNotFound | StreamGone;
// ---cut-after---
same<HeadError, Core.HeadError>(true);
```

`head` fails with `HeadError`.

### `ReadError`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import type { InvalidReadRequest, StreamGone, StreamNotFound } from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
type ReadError = StreamNotFound | StreamGone | InvalidReadRequest;
// ---cut-after---
same<ReadError, Core.ReadError>(true);
```

`read` fails with `ReadError`.

### `ReadNextError`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import type { InvalidReadRequest, NotSupported, StreamGone, StreamNotFound } from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
type ReadNextError = StreamNotFound | StreamGone | InvalidReadRequest | NotSupported;
// ---cut-after---
same<ReadNextError, Core.ReadNextError>(true);
```

`readNext` fails with `ReadNextError`. `readNext` is the protocol read that can wait for new data, and it adds `NotSupported` to `ReadError`.

### `CreateError`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import type {
  CreateConflict,
  ForkSourceNotFound,
  InvalidForkRequest,
  NotSupported,
} from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
type CreateError = CreateConflict | ForkSourceNotFound | InvalidForkRequest | NotSupported;
// ---cut-after---
same<CreateError, Core.CreateError>(true);
```

`create` and `fork` fail with `CreateError`.

### `AppendBaseError`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import type {
  AppendConflict,
  NotSupported,
  StreamBusy,
  StreamClosed,
  StreamGone,
  StreamNotFound,
} from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
type AppendBaseError =
  StreamNotFound | StreamGone | StreamClosed | StreamBusy | AppendConflict | NotSupported;
// ---cut-after---
same<AppendBaseError, Core.AppendBaseError>(true);
```

An append can fail with any `AppendBaseError`, whatever its options.

### `AppendError`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import type {
  AppendBaseError,
  InvalidAppendRequest,
  InvalidEpochSeq,
  OffsetMismatch,
  ProducerGap,
  StaleEpoch,
} from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
type AppendError =
  | AppendBaseError
  | InvalidAppendRequest
  | OffsetMismatch
  | StaleEpoch
  | ProducerGap
  | InvalidEpochSeq;
// ---cut-after---
same<AppendError, Core.AppendError>(true);
```

`AppendError` lists every error that the protocol append can fail with.

### `AppendErrorFor`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import type {
  AppendBaseError,
  AppendErrorFor,
  OffsetMismatch,
  ProducerGap,
  Producer,
  StaleEpoch,
} from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
type NoOptions = AppendErrorFor<{}>;
// AppendBaseError

type Conditional = AppendErrorFor<{ expectedOffset: string }>;
// AppendBaseError | OffsetMismatch

type WithProducer = AppendErrorFor<{ producer: Producer.Position }>;
// AppendBaseError | StaleEpoch | ProducerGap
// ---cut-after---
same<NoOptions, AppendBaseError>(true);
same<Conditional, AppendBaseError | OffsetMismatch>(true);
same<WithProducer, AppendBaseError | StaleEpoch | ProducerGap>(true);
```

`AppendErrorFor<O>` lists the errors that an append with options of type `O` can fail with. It includes `OffsetMismatch` only when `O` has `expectedOffset`, and it includes `StaleEpoch` and `ProducerGap` only when `O` has `producer`. An optional property counts as set, so `AppendErrorFor<AppendCallOptions>` includes all three.

### `RemoveError`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import type { StreamBusy, StreamGone, StreamNotFound } from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
type RemoveError = StreamNotFound | StreamGone | StreamBusy;
// ---cut-after---
same<RemoveError, Core.RemoveError>(true);
```

`remove` fails with `RemoveError`.

### `ProtocolError`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import type {
  AppendError,
  CreateError,
  HeadError,
  ReadNextError,
  RemoveError,
} from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
type ProtocolError = HeadError | ReadNextError | CreateError | AppendError | RemoveError;
// ---cut-after---
same<ProtocolError, Core.ProtocolError>(true);
```

`ProtocolError` is the union of every protocol error.

## Guards

### `isProtocolError`

```ts
// ---cut-start---
import type * as Core from "@streamsy/core";
import { isProtocolError as real, type ProtocolError } from "@streamsy/core";
import { same } from "./reference-check.ts";
// ---cut-end---
declare function isProtocolError(error: { readonly _tag: string }): error is ProtocolError;
// ---cut-after---
same<typeof isProtocolError, typeof real>(true);
```

`isProtocolError` returns `true` when the `_tag` of `error` is the tag of a protocol error. The HTTP handlers use it to map every protocol error to its HTTP response in one place.
