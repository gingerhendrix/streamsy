---
title: Action outbox
description: Reference for the outbox exports in @streamsy/serve/action/outbox. The outbox stores each decision to deliver and its retry state.
---

```ts
import {
  makeMemoryOutboxBacking,
  outboxStore,
  outboxStoreLayer,
  OutboxStore,
  type OutboxBacking,
  type OutboxStoreService,
  type OutboxDraft,
  type OutboxEnqueueReport,
  type OutboxEntry,
  type OutboxEntryState,
} from "@streamsy/serve/action/outbox";
import type { OutboxUnavailable, DeadLetterReason } from "@streamsy/serve/action/errors";
import { Context, type Effect, type Layer, type Option } from "effect";
```

An action sink writes each decision to deliver into the outbox first. A separate [`drain`](/docs/reference/serve/action-runtime#drain) pass then reads the outbox and delivers the entries, so a process that stops before delivery loses no decision. See [Enqueue](/docs/projections/actions#enqueue).

## `makeMemoryOutboxBacking`

```ts
// ---cut-start---
import type * as Real from "@streamsy/serve/action/outbox";
import type { OutboxBacking } from "@streamsy/serve/action/outbox";
import { same } from "./reference-check.ts";
// ---cut-end---
declare function makeMemoryOutboxBacking(): OutboxBacking;
// ---cut-after---
same<typeof makeMemoryOutboxBacking, typeof Real.makeMemoryOutboxBacking>(true);
```

`makeMemoryOutboxBacking` returns an empty outbox in process memory. Each call returns a separate outbox with its own entries and idempotency keys. The entries are lost when the process ends.

Like the [SQL backing](/docs/reference/serve/action-sql), it absorbs a repeated sink and idempotency key, and returns entries in enqueue order. `markDelivered`, `reschedule`, or `deadLetter` with an unknown entry id dies with an `Error`.

## `OutboxBacking`

```ts
// ---cut-start---
import type * as Real from "@streamsy/serve/action/outbox";
import type { OutboxEntry, OutboxDraft, OutboxEnqueueReport } from "@streamsy/serve/action/outbox";
import type { OutboxUnavailable, DeadLetterReason } from "@streamsy/serve/action/errors";
import type { Effect, Option } from "effect";
import { same } from "./reference-check.ts";
// ---cut-end---
interface OutboxBacking {
  readonly enqueue: (
    drafts: readonly OutboxDraft[],
  ) => Effect.Effect<OutboxEnqueueReport, OutboxUnavailable, never>;
  readonly nextDue: (
    sink: string,
    partitionId: string | undefined,
    ordered?: boolean,
  ) => Effect.Effect<Option.Option<number>, OutboxUnavailable, never>;
  readonly claimDue: (
    sink: string,
    partitionId: string | undefined,
    nowMs: number,
    limit: number,
    ordered?: boolean,
  ) => Effect.Effect<readonly OutboxEntry[], OutboxUnavailable, never>;
  readonly markDelivered: (
    id: number,
    attempts: number,
    atMs: number,
  ) => Effect.Effect<void, OutboxUnavailable, never>;
  readonly reschedule: (
    id: number,
    attempts: number,
    nextAttemptAtMs: number,
    detail: string,
  ) => Effect.Effect<void, OutboxUnavailable, never>;
  readonly deadLetter: (
    id: number,
    attempts: number,
    reason: DeadLetterReason,
    detail: string,
    atMs: number,
  ) => Effect.Effect<void, OutboxUnavailable, never>;
  readonly list: (
    sink: string,
    partitionId: string | undefined,
  ) => Effect.Effect<readonly OutboxEntry[], OutboxUnavailable, never>;
}
// ---cut-after---
same<OutboxBacking, Real.OutboxBacking>(true);
```

`OutboxBacking` is the storage contract of an outbox. Every operation can fail with [`OutboxUnavailable`](/docs/reference/serve/action-errors#outboxunavailable).

| Method          | Rule                                                                                                                                                                                               |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `enqueue`       | Absorbs a draft whose sink and idempotency key already exist, even when that entry is settled. A new entry starts pending with zero attempts, and is due at `enqueuedAtMs`                         |
| `nextDue`       | Returns the earliest due time of the pending entries. With `ordered: true`, returns the due time of the oldest pending entry instead. Returns `Option.none()` when no entry is pending             |
| `claimDue`      | Returns up to `limit` pending entries in enqueue order. By default, leaves out entries due after `nowMs`. With `ordered: true`, includes them, so the caller can stop at the first future due time |
| `markDelivered` | Marks the entry delivered, records the given attempt count and settlement time, and clears `lastError`                                                                                             |
| `reschedule`    | Keeps the entry pending, and records the given attempt count, retry time, and error detail                                                                                                         |
| `deadLetter`    | Marks the entry dead, and records the given attempt count, reason, error detail, and settlement time                                                                                               |
| `list`          | Returns every entry of the sink in enqueue order, settled entries included                                                                                                                         |

For `nextDue`, `claimDue`, and `list`, an undefined `partitionId` selects every lane of the sink. `claimDue` does not change the state of an entry or take a durable lease. The runtime runs one `drain` at a time for each pair of service object and sink. It does not coordinate separate processes or separate service objects.

## `OutboxDraft`

```ts
// ---cut-start---
import type * as Real from "@streamsy/serve/action/outbox";
import { same } from "./reference-check.ts";
// ---cut-end---
interface OutboxDraft {
  readonly sink: string;
  readonly partitionId: string;
  readonly idempotencyKey: string;
  readonly payload: string;
  readonly enqueuedAtMs: number;
}
// ---cut-after---
same<OutboxDraft, Real.OutboxDraft>(true);
```

`OutboxDraft` is one decision to deliver, before the outbox gives it an entry id.

| Field            | Meaning                                                            |
| ---------------- | ------------------------------------------------------------------ |
| `sink`           | The sink name                                                      |
| `partitionId`    | The lane that `partitionBy` returned                               |
| `idempotencyKey` | The idempotency key, unique in the sink across all lanes           |
| `payload`        | The payload as JSON text                                           |
| `enqueuedAtMs`   | The enqueue time in milliseconds, which is also the first due time |

[`draftsFor`](/docs/reference/serve/action-runtime#draftsfor) builds drafts from a sink and its payloads. Enqueue the drafts in the same transaction as the fact that causes the action.

```ts

import type * as Real from "@streamsy/serve/action/outbox";

interface OutboxEnqueueReport {

}
// ---cut-after---

```

`OutboxEnqueueReport` counts the new entries in `enqueued`, and the drafts whose sink and idempotency key already exist in `absorbed`. An absorbed draft does not replace the stored payload or lane.

## `OutboxEntry`

```ts
// ---cut-start---
import type * as Real from "@streamsy/serve/action/outbox";
import type { OutboxEntryState } from "@streamsy/serve/action/outbox";
import type { DeadLetterReason } from "@streamsy/serve/action/errors";
import { same } from "./reference-check.ts";
// ---cut-end---
interface OutboxEntry {
  readonly id: number;
  readonly sink: string;
  readonly partitionId: string;
  readonly idempotencyKey: string;
  readonly payload: string;
  readonly state: OutboxEntryState;
  readonly attempts: number;
  readonly nextAttemptAtMs: number;
  readonly lastError: string | undefined;
  readonly deadLetterReason: DeadLetterReason | undefined;
  readonly enqueuedAtMs: number;
  readonly settledAtMs: number | undefined;
}
// ---cut-after---
same<OutboxEntry, Real.OutboxEntry>(true);
```

`OutboxEntry` is one stored delivery, with its retry or settlement state.

| Field              | Meaning                                                                     |
| ------------------ | --------------------------------------------------------------------------- |
| `id`               | The enqueue order. Each new entry gets a higher id                          |
| `sink`             | The sink name                                                               |
| `partitionId`      | The lane of the entry                                                       |
| `idempotencyKey`   | The idempotency key, unique in the sink                                     |
| `payload`          | The stored JSON text                                                        |
| `state`            | `pending`, `delivered`, or `dead`                                           |
| `attempts`         | The number of attempts made. 0 before the first attempt                     |
| `nextAttemptAtMs`  | The earliest time of the next attempt, in milliseconds                      |
| `lastError`        | The detail of the last failure, or `undefined`                              |
| `deadLetterReason` | The reason why the entry was dead-lettered, or `undefined`                  |
| `enqueuedAtMs`     | The enqueue time, in milliseconds                                           |
| `settledAtMs`      | The delivery or dead-letter time, or `undefined` while the entry is pending |

The outbox keeps delivered and dead entries, so it still absorbs a later enqueue with the same sink and idempotency key.

## `OutboxEntryState`

```ts
// ---cut-start---
import type * as Real from "@streamsy/serve/action/outbox";
import { same } from "./reference-check.ts";
// ---cut-end---
type OutboxEntryState = "pending" | "delivered" | "dead";
// ---cut-after---
same<OutboxEntryState, Real.OutboxEntryState>(true);
```

`OutboxEntryState` is `pending` until the entry is delivered or dead-lettered. `nextDue` and `claimDue` read only pending entries.
