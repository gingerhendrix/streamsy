title: Action runtime
description: Reference for the runtime exports in @streamsy/serve/action/runtime. They build outbox drafts and run bounded delivery passes over the outbox.
---

```ts
import {
  actionSinkHandler,
  draftsFor,
  drain,
  OutboxWakeup,
  DEFAULT_DRAIN_LIMIT,
  type ActionSinkDelivery,
  type ActionSinkHandler,
  type RefuseDelivery,
  type DrainOptions,
  type DrainReport,
} from "@streamsy/serve/action/runtime";
import type { ActionSinkRelation, CheckedActionSink } from "@streamsy/serve/action";
import type { ActionSinkDeliveryFailure, OutboxUnavailable } from "@streamsy/serve/action/errors";
import { OutboxStore, type OutboxDraft } from "@streamsy/serve/action/outbox";
import type { Wakeup } from "@streamsy/serve/cloudflare";
import type { Effect } from "effect";
```

The runtime builds outbox drafts from payloads, and delivers pending entries under the retry policy of the sink. See [Deliver](/docs/projections/actions#deliver).

## `actionSinkHandler`

```ts
// ---cut-start---
import type * as Real from "@streamsy/serve/action/runtime";
import type {
  ActionSinkDelivery,
  ActionSinkHandler,
  RefuseDelivery,
} from "@streamsy/serve/action/runtime";
import type { ActionSinkRelation, CheckedActionSink } from "@streamsy/serve/action";
import type { ActionSinkDeliveryFailure } from "@streamsy/serve/action/errors";
import type { Effect } from "effect";
import { same } from "./reference-check.ts";
// ---cut-end---
declare function actionSinkHandler<Payload, From extends ActionSinkRelation, Requirements = never>(
  sink: CheckedActionSink<Payload, From>,
  deliver: (
    delivery: ActionSinkDelivery<Payload>,
    refuse: RefuseDelivery,
  ) => Effect.Effect<void, ActionSinkDeliveryFailure, Requirements>,
): ActionSinkHandler<Payload, Requirements>;
// ---cut-after---
same<typeof actionSinkHandler, typeof Real.actionSinkHandler>(true);
```

`actionSinkHandler` builds an `ActionSinkHandler` from the `deliver` callback. For each delivery, it passes the callback a [`RefuseDelivery`](#refusedelivery) whose failures carry `sink.handler.name` and the idempotency key of the delivery. The services that the Effect of the callback requires become the `Requirements` of the handler.

When `deliver` throws before it returns its Effect, `drain` dies with that defect and does not record the attempt. When the returned Effect dies, `drain` records a retryable refusal instead.

## `draftsFor`

```ts
// ---cut-start---
import type * as Real from "@streamsy/serve/action/runtime";
import type { ActionSinkRelation, CheckedActionSink } from "@streamsy/serve/action";
import { type OutboxDraft } from "@streamsy/serve/action/outbox";
import { same } from "./reference-check.ts";
// ---cut-end---
declare function draftsFor<Payload, From extends ActionSinkRelation>(
  sink: CheckedActionSink<Payload, From>,
  payloads: readonly Payload[],
  enqueuedAtMs: number,
): readonly OutboxDraft[];
// ---cut-after---
same<typeof draftsFor, typeof Real.draftsFor>(true);
```

`draftsFor` returns one draft for each payload, in input order. It fills each draft with the results of the `partitionBy`, `idempotencyKey`, and `payload.encode` functions of the sink, and gives every draft the same `enqueuedAtMs`.

`draftsFor` writes nothing, so you can enqueue its drafts in your own transaction. When a sink function throws, `draftsFor` throws the same exception. It does not validate or deduplicate the payloads.

## `drain`

```ts
// ---cut-start---
import type * as Real from "@streamsy/serve/action/runtime";
import type { ActionSinkHandler, DrainOptions, DrainReport } from "@streamsy/serve/action/runtime";
import type { ActionSinkRelation, CheckedActionSink } from "@streamsy/serve/action";
import type { OutboxUnavailable } from "@streamsy/serve/action/errors";
import { OutboxStore } from "@streamsy/serve/action/outbox";
import type { Effect } from "effect";
import { same } from "./reference-check.ts";
// ---cut-end---
declare const drain: <Payload, From extends ActionSinkRelation, Requirements = never>(
  sink: CheckedActionSink<Payload, From>,
  handler: ActionSinkHandler<Payload, Requirements>,
  options?: DrainOptions,
) => Effect.Effect<DrainReport, OutboxUnavailable, OutboxStore | Requirements>;
// ---cut-after---
same<typeof drain, typeof Real.drain>(true);
```

`drain` runs one delivery pass. It claims up to `limit` pending entries that are due at the start of the pass, and delivers them one at a time in enqueue order. Before each attempt, it compares the due time of the entry with the clock again, and ends the pass at the first entry that is not due.

Passes over the same sink with the same store object share one permit, so they run one at a time, across all lanes. The permit is not reentrant, so a handler must not drain its own sink. Separate processes and separate store objects do not share the permit.

By default, an entry that waits for a retry does not hold back later entries that are due. With `ordered: true`, a reschedule ends the pass, and the oldest pending entry holds back every later entry in the scope until it is due. Without `partitionId`, the scope is every lane of the sink.

| Outcome                                  | Stored result                                                |
| ---------------------------------------- | ------------------------------------------------------------ |
| Handler succeeds                         | Delivered, with the attempt count and settlement time        |
| Handler fails with a permanent refusal   | Dead, with reason `permanent`                                |
| Retryable failure uses the final attempt | Dead, with reason `attempts-exhausted`                       |
| Retryable failure has attempts left      | Pending, due at the time of the failure plus `backoffAfter`  |
| JSON parse or payload decode throws      | Dead, with reason `payload-poison`. The handler does not run |

When the Effect of the handler dies, `drain` records a retryable refusal. When that Effect is interrupted, `drain` is interrupted too, and leaves the entry unchanged. When the outbox fails, `drain` fails with `OutboxUnavailable`.

Delivery is at least once. A process can stop after the external effect succeeds and before the outbox records success. The handler must accept a repeated idempotency key without repeating the external effect.

## `OutboxWakeup`

```ts
// ---cut-start---
import type * as Real from "@streamsy/serve/action/runtime";
import type { ActionSinkHandler, DrainOptions } from "@streamsy/serve/action/runtime";
import type { ActionSinkRelation, CheckedActionSink } from "@streamsy/serve/action";
import { OutboxStore } from "@streamsy/serve/action/outbox";
import type { Wakeup } from "@streamsy/serve/cloudflare";
import { same } from "./reference-check.ts";
// ---cut-end---
declare const OutboxWakeup: {
  make: <Payload, From extends ActionSinkRelation, R = never>(
    sink: CheckedActionSink<Payload, From>,
    handler: ActionSinkHandler<Payload, R>,
    options?: DrainOptions,
  ) => Wakeup<OutboxStore | R>;
};
// ---cut-after---
same<typeof OutboxWakeup, typeof Real.OutboxWakeup>(true);
```

`OutboxWakeup.make` returns a host [`Wakeup`](/docs/reference/serve/cloudflare#cloudflarewakeup) that reads the next due time with `nextDue` and runs `drain`. The wakeup name is `streamsy/outbox/<sink>`, or `streamsy/outbox/<sink>/<partition>` when `options.partitionId` is set. `make` URI-encodes the sink and the partition, so a sink named `a/b` cannot collide with a lane.

The wakeup passes `ordered` to `nextDue`. When `nextDue` fails, the wakeup fails with a retryable `StorageFault`. When a pass claims `limit` entries, the wakeup reports `more: true`, so the host does not back off a backlog.

## `ActionSinkDelivery`

```ts
// ---cut-start---
import type * as Real from "@streamsy/serve/action/runtime";
import { same } from "./reference-check.ts";
// ---cut-end---
interface ActionSinkDelivery<Payload> {
  readonly entryId: number;
  readonly sink: string;
  readonly partitionId: string;
  readonly idempotencyKey: string;
  readonly attempt: number;
  readonly payload: Payload;
}
// ---cut-after---
same<ActionSinkDelivery<{ readonly id: string }>, Real.ActionSinkDelivery<{ readonly id: string }>>(
  true,
);
```

`ActionSinkDelivery` is one attempt at one delivery, as the handler sees it.

| Field            | Meaning                                                                                       |
| ---------------- | --------------------------------------------------------------------------------------------- |
| `entryId`        | The id of the stored entry                                                                    |
| `sink`           | The sink name                                                                                 |
| `partitionId`    | The lane of the entry                                                                         |
| `idempotencyKey` | The idempotency key. The handler must not repeat the effect for a key that it accepted before |
| `attempt`        | The attempt number, starting at 1                                                             |
| `payload`        | The decoded payload                                                                           |

A retry has the same entry id and idempotency key as the first attempt.

## `ActionSinkHandler`

```ts
// ---cut-start---
import type * as Real from "@streamsy/serve/action/runtime";
import type { ActionSinkDelivery } from "@streamsy/serve/action/runtime";
import type { ActionSinkDeliveryFailure } from "@streamsy/serve/action/errors";
import type { Effect } from "effect";
import { same } from "./reference-check.ts";
// ---cut-end---
interface ActionSinkHandler<Payload, Requirements = never> {
  readonly deliver: (
    delivery: ActionSinkDelivery<Payload>,
  ) => Effect.Effect<void, ActionSinkDeliveryFailure, Requirements>;
}
// ---cut-after---
same<ActionSinkHandler<string>, Real.ActionSinkHandler<string>>(true);
same<
  ActionSinkHandler<number, { readonly dependency: "notifier" }>,
  Real.ActionSinkHandler<number, { readonly dependency: "notifier" }>
>(true);
```

`ActionSinkHandler` delivers one entry: `deliver` returns the Effect that performs the external effect. The host provides its `Requirements`. When the Effect succeeds, `drain` marks the entry delivered. The Effect must also succeed for a key that the handler accepted before.

## `RefuseDelivery`

```ts
// ---cut-start---
import type * as Real from "@streamsy/serve/action/runtime";
import type { ActionSinkDeliveryFailure } from "@streamsy/serve/action/errors";
import { same } from "./reference-check.ts";
// ---cut-end---
interface RefuseDelivery {
  readonly retryable: (detail: string) => ActionSinkDeliveryFailure;
  readonly permanent: (detail: string) => ActionSinkDeliveryFailure;
}
// ---cut-after---
same<RefuseDelivery, Real.RefuseDelivery>(true);
```

`RefuseDelivery` builds the failures that refuse the current delivery. `retryable(detail)` lets `drain` try again while attempts remain. `permanent(detail)` dead-letters the entry at once. Each function only returns the error. To refuse the delivery, fail with it or `yield*` it.

## `DrainOptions`

```ts
// ---cut-start---
import type * as Real from "@streamsy/serve/action/runtime";
import { same } from "./reference-check.ts";
// ---cut-end---
interface DrainOptions {
  readonly partitionId?: string;
  readonly limit?: number;
  readonly ordered?: boolean;
}
// ---cut-after---
same<DrainOptions, Real.DrainOptions>(true);
```

`DrainOptions` sets the lanes, the size, and the order of one pass.

| Field         | Default               | Meaning                                                                                                 |
| ------------- | --------------------- | ------------------------------------------------------------------------------------------------------- |
| `partitionId` | All lanes             | The one lane to drain                                                                                   |
| `limit`       | `DEFAULT_DRAIN_LIMIT` | The most entries that the pass claims                                                                   |
| `ordered`     | `false`               | `true` to deliver in strict enqueue order: an entry that waits for a retry holds back every later entry |

The runtime forwards `limit` to the backing without validating it.

## `DrainReport`

```ts
// ---cut-start---
import type * as Real from "@streamsy/serve/action/runtime";
import { same } from "./reference-check.ts";
// ---cut-end---
interface DrainReport {
  readonly sink: string;
  readonly claimed: number;
  readonly delivered: number;
  readonly retried: number;
  readonly deadLettered: number;
}
// ---cut-after---
same<DrainReport, Real.DrainReport>(true);
```

`DrainReport` counts the outcomes of one completed pass.

| Field          | Meaning                                                                                                                 |
| -------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `sink`         | The sink name                                                                                                           |
| `claimed`      | The entries that the pass attempted, payload failures included. A future entry that ends an ordered pass is not counted |
| `delivered`    | The entries delivered                                                                                                   |
| `retried`      | The entries rescheduled for another attempt                                                                             |
| `deadLettered` | The entries dead-lettered                                                                                               |

For a completed pass, `claimed` equals `delivered + retried + deadLettered`.

## `DEFAULT_DRAIN_LIMIT`

```ts
// ---cut-start---
import type * as Real from "@streamsy/serve/action/runtime";
import { same } from "./reference-check.ts";
// ---cut-end---
declare const DEFAULT_DRAIN_LIMIT = 100;
// ---cut-after---
same<typeof DEFAULT_DRAIN_LIMIT, typeof Real.DEFAULT_DRAIN_LIMIT>(true);
```

`DEFAULT_DRAIN_LIMIT` is the `limit` of a pass when `options.limit` is absent: 100 entries.
