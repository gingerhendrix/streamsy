---
title: Action runtime
description: Reference for the runtime exports in @streamsy/serve/action/runtime. They construct delivery drafts and run bounded outbox passes.
---

```ts
import {
  actionSinkHandler,
  draftsFor,
  drain,
  OutboxWakeup,
  DEFAULT_DRAIN_LIMIT,
  type ActionSinkDelivery,
  type ActionSinkHandler,
  type RefuseDelivery,
  type DrainOptions,
  type DrainReport,
} from "@streamsy/serve/action/runtime";
import type { ActionSinkRelation, CheckedActionSink } from "@streamsy/serve/action";
import type { ActionSinkDeliveryFailure, OutboxUnavailable } from "@streamsy/serve/action/errors";
import { OutboxStore, type OutboxDraft } from "@streamsy/serve/action/outbox";
import type { Wakeup } from "@streamsy/serve/cloudflare";
import type { Effect } from "effect";
```

The runtime turns payloads into outbox drafts and delivers pending entries under the sink's retry policy. See [Deliver](/docs/projections/actions#deliver).

## `actionSinkHandler`

```ts
// ---cut-start---
import type * as Real from "@streamsy/serve/action/runtime";
import type {
  ActionSinkDelivery,
  ActionSinkHandler,
  RefuseDelivery,
} from "@streamsy/serve/action/runtime";
import type { ActionSinkRelation, CheckedActionSink } from "@streamsy/serve/action";
import type { ActionSinkDeliveryFailure } from "@streamsy/serve/action/errors";
import type { Effect } from "effect";
import { same } from "./reference-check.ts";
// ---cut-end---
declare function actionSinkHandler<Payload, From extends ActionSinkRelation, Requirements = never>(
  sink: CheckedActionSink<Payload, From>,
  deliver: (
    delivery: ActionSinkDelivery<Payload>,
    refuse: RefuseDelivery,
  ) => Effect.Effect<void, ActionSinkDeliveryFailure, Requirements>,
): ActionSinkHandler<Payload, Requirements>;
// ---cut-after---
same<typeof actionSinkHandler, typeof Real.actionSinkHandler>(true);
```

`actionSinkHandler` binds the refusal helpers to `sink.handler.name` and the current delivery's idempotency key. The callback's Effect requirements remain requirements of the returned handler.

When the callback throws before returning its Effect, `drain` defects without recording the attempt. The runtime catches defects in the returned Effect.

## `draftsFor`

```ts
// ---cut-start---
import type * as Real from "@streamsy/serve/action/runtime";
import type { ActionSinkRelation, CheckedActionSink } from "@streamsy/serve/action";
import { type OutboxDraft } from "@streamsy/serve/action/outbox";
import { same } from "./reference-check.ts";
// ---cut-end---
declare function draftsFor<Payload, From extends ActionSinkRelation>(
  sink: CheckedActionSink<Payload, From>,
  payloads: readonly Payload[],
  enqueuedAtMs: number,
): readonly OutboxDraft[];
// ---cut-after---
same<typeof draftsFor, typeof Real.draftsFor>(true);
```

`draftsFor` maps each payload to a draft in input order. It calls the sink's `partitionBy`, `idempotencyKey`, and `payload.encode` functions and copies the supplied enqueue time.

`draftsFor` performs no storage write. When a declared function throws, that exception leaves the call synchronously. It does not validate or deduplicate the encoded payloads.

## `drain`

```ts
// ---cut-start---
import type * as Real from "@streamsy/serve/action/runtime";
import type { ActionSinkHandler, DrainOptions, DrainReport } from "@streamsy/serve/action/runtime";
import type { ActionSinkRelation, CheckedActionSink } from "@streamsy/serve/action";
import type { OutboxUnavailable } from "@streamsy/serve/action/errors";
import { OutboxStore } from "@streamsy/serve/action/outbox";
import type { Effect } from "effect";
import { same } from "./reference-check.ts";
// ---cut-end---
declare const drain: <Payload, From extends ActionSinkRelation, Requirements = never>(
  sink: CheckedActionSink<Payload, From>,
  handler: ActionSinkHandler<Payload, Requirements>,
  options?: DrainOptions,
) => Effect.Effect<DrainReport, OutboxUnavailable, OutboxStore | Requirements>;
// ---cut-after---
same<typeof drain, typeof Real.drain>(true);
```

`drain` attempts a bounded set of pending entries serially in enqueue order. It claims work using the clock at the start of the pass and checks each entry's deadline before attempting it.

Drains that share a store object and sink name share one permit, across all lanes. A handler must not drain its own sink because the permit is not reentrant. Separate processes and separate store objects do not share the permit.

By default, a retry scheduled into the future does not block later due entries. With `ordered: true`, a reschedule ends the pass, and the first future entry blocks later entries in the selected scope. When `partitionId` is absent, that scope includes all lanes.

| Outcome                                  | Stored result                                                                             |
| ---------------------------------------- | ----------------------------------------------------------------------------------------- |
| Handler succeeds                         | Delivered, with the attempt count and settlement time                                     |
| Handler fails with a permanent refusal   | Dead, with reason `permanent`                                                             |
| Retryable failure uses the final attempt | Dead, with reason `attempts-exhausted`                                                    |
| Retryable failure has attempts left      | Pending, with the next deadline computed from the clock after failure plus `backoffAfter` |
| JSON parse or payload decode throws      | Dead, with reason `payload-poison`. The handler does not run                              |

A defect in the handler's returned Effect becomes a retryable refusal. When that Effect is interrupted, `drain` interrupts and leaves the current entry unchanged. An outbox failure leaves through `OutboxUnavailable`.

Delivery is at least once. A process can stop after the external effect succeeds and before the outbox records success. The handler must accept a repeated idempotency key without repeating the external effect.

## `OutboxWakeup`

```ts
// ---cut-start---
import type * as Real from "@streamsy/serve/action/runtime";
import type { ActionSinkHandler, DrainOptions } from "@streamsy/serve/action/runtime";
import type { ActionSinkRelation, CheckedActionSink } from "@streamsy/serve/action";
import { OutboxStore } from "@streamsy/serve/action/outbox";
import type { Wakeup } from "@streamsy/serve/cloudflare";
import { same } from "./reference-check.ts";
// ---cut-end---
declare const OutboxWakeup: {
  make: <Payload, From extends ActionSinkRelation, R = never>(
    sink: CheckedActionSink<Payload, From>,
    handler: ActionSinkHandler<Payload, R>,
    options?: DrainOptions,
  ) => Wakeup<OutboxStore | R>;
};
// ---cut-after---
same<typeof OutboxWakeup, typeof Real.OutboxWakeup>(true);
```

`OutboxWakeup` adapts `nextDue` and `drain` to a host wakeup through its `make` function. Its name is `streamsy/outbox/<sink>`, with `/<partition>` appended when a partition is selected. Each component is URI-encoded.

The wakeup forwards `ordered` to `nextDue`. A deadline read failure becomes a retryable `StorageFault`. A pass reports `more: true` when `claimed` reaches the configured limit, so a full pass can continue without failure backoff.

## `ActionSinkDelivery`

```ts
// ---cut-start---
import type * as Real from "@streamsy/serve/action/runtime";
import { same } from "./reference-check.ts";
// ---cut-end---
interface ActionSinkDelivery<Payload> {
  readonly entryId: number;
  readonly sink: string;
  readonly partitionId: string;
  readonly idempotencyKey: string;
  readonly attempt: number;
  readonly payload: Payload;
}
// ---cut-after---
same<ActionSinkDelivery<{ readonly id: string }>, Real.ActionSinkDelivery<{ readonly id: string }>>(
  true,
);
```

`ActionSinkDelivery` describes one attempt as the handler sees it.

| Field            | Meaning                                            |
| ---------------- | -------------------------------------------------- |
| `entryId`        | Stored entry id                                    |
| `sink`           | Stored sink name                                   |
| `partitionId`    | Stored lane                                        |
| `idempotencyKey` | Durable identity that the handler must deduplicate |
| `attempt`        | One-based attempt number                           |
| `payload`        | Decoded payload                                    |

A repeated attempt keeps the entry id and idempotency key.

## `ActionSinkHandler`

```ts
// ---cut-start---
import type * as Real from "@streamsy/serve/action/runtime";
import type { ActionSinkDelivery } from "@streamsy/serve/action/runtime";
import type { ActionSinkDeliveryFailure } from "@streamsy/serve/action/errors";
import type { Effect } from "effect";
import { same } from "./reference-check.ts";
// ---cut-end---
interface ActionSinkHandler<Payload, Requirements = never> {
  readonly deliver: (
    delivery: ActionSinkDelivery<Payload>,
  ) => Effect.Effect<void, ActionSinkDeliveryFailure, Requirements>;
}
// ---cut-after---
same<ActionSinkHandler<string>, Real.ActionSinkHandler<string>>(true);
same<
  ActionSinkHandler<number, { readonly dependency: "notifier" }>,
  Real.ActionSinkHandler<number, { readonly dependency: "notifier" }>
>(true);
```

`ActionSinkHandler` supplies the Effect that performs one delivery. The host provides its `Requirements`. Success means the handler accepted the idempotency key, including a key that it accepted before.

## `RefuseDelivery`

```ts
// ---cut-start---
import type * as Real from "@streamsy/serve/action/runtime";
import type { ActionSinkDeliveryFailure } from "@streamsy/serve/action/errors";
import { same } from "./reference-check.ts";
// ---cut-end---
interface RefuseDelivery {
  readonly retryable: (detail: string) => ActionSinkDeliveryFailure;
  readonly permanent: (detail: string) => ActionSinkDeliveryFailure;
}
// ---cut-after---
same<RefuseDelivery, Real.RefuseDelivery>(true);
```

`RefuseDelivery` constructs failures for the current handler and delivery. `retryable(detail)` allows another attempt within the budget. `permanent(detail)` stops retries immediately. The callback must fail with or yield the returned error to refuse delivery.

## `DrainOptions`

```ts
// ---cut-start---
import type * as Real from "@streamsy/serve/action/runtime";
import { same } from "./reference-check.ts";
// ---cut-end---
interface DrainOptions {
  readonly partitionId?: string;
  readonly limit?: number;
  readonly ordered?: boolean;
}
// ---cut-after---
same<DrainOptions, Real.DrainOptions>(true);
```

`DrainOptions` selects the scope and bound of one pass.

| Field         | Default               | Meaning                                                           |
| ------------- | --------------------- | ----------------------------------------------------------------- |
| `partitionId` | All lanes             | Restricts the pass to one lane                                    |
| `limit`       | `DEFAULT_DRAIN_LIMIT` | Upper bound on entries claimed                                    |
| `ordered`     | `false`               | A future retry blocks later pending entries in the selected scope |

The runtime forwards `limit` to the backing without validating it.

## `DrainReport`

```ts
// ---cut-start---
import type * as Real from "@streamsy/serve/action/runtime";
import { same } from "./reference-check.ts";
// ---cut-end---
interface DrainReport {
  readonly sink: string;
  readonly claimed: number;
  readonly delivered: number;
  readonly retried: number;
  readonly deadLettered: number;
}
// ---cut-after---
same<DrainReport, Real.DrainReport>(true);
```

`DrainReport` counts the outcomes of one completed pass.

| Field          | Meaning                                                                                           |
| -------------- | ------------------------------------------------------------------------------------------------- |
| `sink`         | Sink name                                                                                         |
| `claimed`      | Entries attempted, including payload failures. Excludes a future entry that stops an ordered pass |
| `delivered`    | Successful handler attempts                                                                       |
| `retried`      | Failures rescheduled for another attempt                                                          |
| `deadLettered` | Entries settled as dead                                                                           |

For a completed pass, `claimed` equals `delivered + retried + deadLettered`.

## `DEFAULT_DRAIN_LIMIT`

```ts
// ---cut-start---
import type * as Real from "@streamsy/serve/action/runtime";
import { same } from "./reference-check.ts";
// ---cut-end---
declare const DEFAULT_DRAIN_LIMIT = 100;

```
