---
title: Action errors
description: Reference for the error exports in @streamsy/serve/action/errors. `OutboxUnavailable` is a storage failure, and `ActionSinkDeliveryFailure` is a handler refusal.
---

```ts
import {
  OutboxUnavailable,
  ActionSinkDeliveryFailure,
  ACTION_SINK_ERROR_TAGS,
  DEAD_LETTER_REASONS,
  type ActionSinkErrorTag,
  type DeadLetterReason,
  type ActionSinkDeliveryFailure as Failure,
} from "@streamsy/serve/action/errors";
```

When the outbox cannot be read or written, `drain` fails with `OutboxUnavailable`, and the host handles the error. When a handler refuses a delivery, `drain` records the refusal in the outbox, and then retries or dead-letters the entry. See [Deliver](/docs/projections/actions#deliver).

Each error class is a `Schema.TaggedError`, so it is an `Error` with a `_tag` that you can `yield*`. Each fence shows the fields of one class.

## `OutboxUnavailable`

```ts
// ---cut-start---
import type * as Real from "@streamsy/serve/action/errors";
import type { Fields } from "./reference-check.ts";
import { same } from "./reference-check.ts";
// ---cut-end---
interface OutboxUnavailable {
  readonly _tag: "OutboxUnavailable";
  readonly operation: string;
  readonly detail: string;
}
// ---cut-after---
same<OutboxUnavailable, Fields<Real.OutboxUnavailable>>(true);
```

An outbox operation fails with `OutboxUnavailable` when the backing cannot read or write the outbox. `operation` names the operation, and `detail` describes the failure. `drain` fails with this error. It is never the outcome of a delivery.

## `ActionSinkDeliveryFailure`

```ts
// ---cut-start---
import type * as Real from "@streamsy/serve/action/errors";
import type { ActionSinkDeliveryFailure as Failure } from "@streamsy/serve/action/errors";
import type { Fields } from "./reference-check.ts";
import { same } from "./reference-check.ts";
// ---cut-end---
interface ActionSinkDeliveryFailure {
  readonly _tag: "ActionSinkDeliveryFailure";
  readonly handler: string;
  readonly idempotencyKey: string;
  readonly detail: string;
  readonly retryable: boolean;
}

declare namespace ActionSinkDeliveryFailure {
  function retryable(handler: string, idempotencyKey: string, detail: string): Failure;
  function permanent(handler: string, idempotencyKey: string, detail: string): Failure;
}
// ---cut-after---
same<ActionSinkDeliveryFailure, Fields<Real.ActionSinkDeliveryFailure>>(true);
same<typeof ActionSinkDeliveryFailure.retryable, typeof Real.ActionSinkDeliveryFailure.retryable>(
  true,
);
same<typeof ActionSinkDeliveryFailure.permanent, typeof Real.ActionSinkDeliveryFailure.permanent>(
  true,
);
```

A handler fails with `ActionSinkDeliveryFailure` when it refuses one delivery. `handler` is the handler name, `idempotencyKey` is the key of the delivery, and `detail` describes the refusal.

`ActionSinkDeliveryFailure.retryable` returns a failure with `retryable: true`, and `ActionSinkDeliveryFailure.permanent` returns one with `retryable: false`. In the factory signatures, `Failure` is an alias of the exported class.

When `retryable` is `false`, `drain` dead-letters the entry with reason `permanent`. Otherwise, `drain` retries the entry until it has made `maxAttempts` attempts. `drain` records each refusal in the outbox, and never fails with this error.

## `DEAD_LETTER_REASONS`

```ts
// ---cut-start---
import type * as Real from "@streamsy/serve/action/errors";
import { same } from "./reference-check.ts";
// ---cut-end---
declare const DEAD_LETTER_REASONS: readonly ["attempts-exhausted", "permanent", "payload-poison"];
// ---cut-after---
same<typeof DEAD_LETTER_REASONS, typeof Real.DEAD_LETTER_REASONS>(true);
```

`DEAD_LETTER_REASONS` lists the reasons why `drain` stops retrying an entry and dead-letters it.

| Reason               | Meaning                                                              |
| -------------------- | -------------------------------------------------------------------- |
| `attempts-exhausted` | A retryable failure used the last allowed attempt                    |
| `permanent`          | The handler refused the delivery with `retryable: false`             |
| `payload-poison`     | `JSON.parse` or the `decode` of the sink threw on the stored payload |

When a permanent refusal is also the last allowed attempt, the reason is `permanent`. An entry whose payload does not decode dead-letters at once, as `payload-poison`.
