A runner takes the bound projection that [`declaration.at(params)`](/docs/reference/projection/declarations#declaration) returns. It reads each input after its checkpoint offset, runs the handler over the unit, and lets the Commit write the checkpoint. See [Running](/docs/projections/run) and [Read, decide, append](/docs/projections/state#read-decide-append).

The signatures use types that have no exported name, such as `Executable`. [Types with no exported name](#types-with-no-exported-name) shows each one. Use one writer for each projection key: one `follow` stream, one attached runner, or one `run` at a time. A second writer fails with a `ProjectionFault` with reason `token-conflict`.

## Runners

### `Projection.pass`

```ts
// ---cut-start---
import type { Effect, Layer, Option, Schedule, Scope, Stream } from "effect";
import type { AppendFailure, Decided, Storage, Streamsy } from "@streamsy/core";
import type * as Real from "@streamsy/projection";
import {
  Projection,
  type AttachOptions,
  type Attachable,
  type Commit,
  type CurrentProjection,
  type DecideSpec,
  type Entry,
  type FollowOptions,
  type Identity,
  type InputMap,
  type PassResult,
  type ProjectionFault,
  type ProjectionKey,
  type Progress,
  type RunOptions,
  type Slices,
  type Snapshot,
  type StateSchema,
  type Unit,
} from "@streamsy/projection";
import { same } from "./reference-check.ts";
// The bound projection that `pass`, `run`, `follow`, and `attach` take.
interface Executable<
  I extends InputMap,
  E,
  R,
  Q,
  Result,
  P = never,
  S = unknown,
  OR = never,
> extends Identity {
  readonly inputs: I;
  readonly state?: BoundState<S>;
  readonly streams?: Readonly<Record<string, Streamsy.Address<unknown, OR>>>;
  readonly commit: Commit.Commit<Result, P, Q>;
  readonly prepare?: (batch: Slices<I>, unit: Unit) => Effect.Effect<unknown, E, Q>;
  readonly process: (
    batch: Slices<I>,
    unit: Unit,
    encoded?: string,
    prepared?: unknown,
  ) => Effect.Effect<Result, E, R | P>;
}

// The state of a bound projection. `initial` has the params bound.
interface BoundState<A> {
  readonly schema: StateSchema<A>;
  readonly initial: () => A;
}

// The stream services of the inputs.
type InputServices<Inputs extends InputMap> = Inputs[keyof Inputs]["stream"]["Identifier"];

// The state type of a result: `undefined` for a projection with no `state:`.
type StateValue<S> = [S] extends [never] ? undefined : S;

// What `read` needs from a bound projection.
type Readable<Inputs extends InputMap, S, Q> = Identity & {
  readonly inputs: Inputs;
  readonly state?: BoundState<S>;
  readonly commit: Pick<Commit.Commit<never, never, Q>, "load">;
};
// ---cut-end---
declare function pass<Inputs extends InputMap, E, R, Q, Result, P, OR = never>(
  projection: Executable<Inputs, E, R, Q, Result, P, unknown, OR>,
): Effect.Effect<
  PassResult<Inputs>,
  E | ProjectionFault,
  Exclude<R, P> | Q | OR | InputServices<Inputs>
>;
// ---cut-after---
same<typeof pass, typeof Projection.pass>(true);
```

`pass` runs at most one unit and returns a [`PassResult`](/docs/reference/projection/units#passresult). It loads the checkpoint through the Commit, reads one page of each input in declaration order, runs the handler, and passes the unit to the Commit.

- When no input has items and no input reached a new close or removal, `pass` commits nothing. Its status is `source-closed` when every input is closed, and `caught-up` otherwise.
- When the checkpoint holds a pinned unit, `pass` reads the pinned ranges again and runs that unit first. A Commit that does not pin fails with reason `invalid-record`.
- When an input is gone, `pass` runs one final unit with `gone` on its slice, then forgets the binding. Its status is `source-closed`.
- A handler failure fails `pass` with the error of the handler. `pass` does not wrap it.
- The Effect requires the handler services `R` minus the services `P` that the Commit provides, and also the Commit services `Q`, the output services `OR`, and the services of the input streams.

`run` repeats [`pass`](#projectionpass) until a pass commits nothing, or until it has committed `options.limit` units. It returns a [`Progress`](/docs/reference/projection/units#progress) with the state and offsets that the last pass left, and decodes the state one time.

- With no `limit`, `run` continues until the inputs are caught up or closed.
- When `limit` is not a positive safe integer, `run` fails with a `ProjectionFault` with phase `load` and reason `invalid-options`.
- `run` does not retry a fault.
- After a gone input, the result holds the state that the final unit committed, although the runner then deletes the record.

```

`follow` returns a pull stream of cycles. Each cycle runs [`run`](#projectionrun) to caught up, closed, or `limit`, and each element is the [`Progress`](/docs/reference/projection/units#progress) of one cycle. While the stream runs, it is the writer of the projection key.

- The stream emits after the first cycle, even when it commits nothing. Then it emits after each cycle that commits a unit or reaches `limit`, and after the last cycle when every input is closed or an input is gone. Then it ends.
- After a caught-up cycle, `follow` waits for a change on any input, for at most `repairIntervalMs`. A wait that ends with no change emits nothing.
- The next cycle runs only when the consumer pulls. A slow consumer gets one element for all the input that arrived while it worked.
- `follow` retries a `ProjectionFault` whose `retryable` is `true`, and logs a warning for each retry. It uses `options.retry`, then [`ProjectionRetry`](/docs/reference/projection/faults#projectionretry). Other failures fail the stream.
- `follow` checks `limit` and `repairIntervalMs` at the first pull. A bad value fails the stream with reason `invalid-options`.

```

`attach` returns a Layer that runs a projection whenever a local commit writes one of its inputs. It takes the declaration, not a bound projection. Use it on long-lived hosts, such as Bun and Node. On a Cloudflare object, use [`ProjectionWakeup`](#projectionwakeup).

- The Layer subscribes to `Storage.committed` when it is built. Build it over the storage Layer, before the app writes.
- For each stream id that a commit writes, the `parse` method of the declaration returns the params, and the runner runs `Projection.run(projection.at(params), { limit })`.
- Each input must give every projection param. When one does not, `attach` throws a `RangeError`. A fixed address triggers only a projection with no params.
- `attach` throws a `RangeError` when `limit` or `batch` is not a positive safe integer.
- A failed pass, or a failed read of the marks, logs an error and runs again under `retry`. A binding that fails or reaches `limit` stays in the set of bindings with work.
- By default, the set lives in memory. After a crash between a commit and its run, the binding stays behind until its source gets its next write.
- With `durable: true`, a pending mark in storage covers that gap, and the Layer runs the bindings with due marks when it starts. A failed binding defers its own mark and does not fail the pass. See [`AttachOptions`](/docs/reference/projection/units#attachoptions).
- An input on another storage owner never commits here, so it never triggers a run.
- A binding whose source was removed before its first run is dropped, with a warning.

Do not also run an attached binding under `follow`.

// ---cut-end---
declare const ProjectionWakeup: {

    projection: Attachable<Executable<I, E, R, Q, Result, P, unknown, OR>>,
    options?: AttachOptions,
  ) => Effect.Effect<
    {
      name: string;
      next: Effect.Effect<Option.Option<number>, StorageFault>;
      // The in-memory and the durable pass each return `{ more: boolean }`,
      // so the declared type names it twice.

```

`ProjectionWakeup.attach` returns the wakeup of a projection for the `wakeups` of a Cloudflare object. It uses the same runner as [`attach`](#projectionattach), and the same rules apply, except that `durable` defaults to `true`. After an eviction or a deploy, the acquisition of the object reads the marks and arms the alarm. Acquire it in the scope of the object Layer, before any request writes. See [Projections on Cloudflare](/docs/servers/cloudflare/alarms#projections) on Cloudflare.

| Field      | Meaning                                                                                                                                              |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `name`     | `streamsy/projection/` followed by the URI-encoded projection id                                                                                     |
| `next`     | The current time while a binding has work in memory. Otherwise, in durable mode, the earliest due time of the marks. `None` when no binding has work |
| `run`      | The Effect that runs each binding with work. Its `more` is `true` when a binding still has due work after the run                                    |
| `retry`    | `options.retry`, or the `ProjectionRetry` schedule                                                                                                   |
| `deferred` | The number of bindings whose marks wait on their own backoff after a failure. It is always `0` when `durable` is `false`                             |

`read` returns the state and the offsets of one checkpoint record, so the state always matches the offsets. It loads the record through the Commit and reads no input.

- Before the first unit, the state is the declared initial value, and each offset is the start of its input.
- For a projection with no `state:`, the state is `undefined`.
- When the stored inputs differ from the declaration, `read` fails with reason `identity-mismatch`. When the stored state does not decode, it fails with reason `invalid-record`.

```

`current` loads one checkpoint and folds the input tail in memory, so the result includes every entry appended before the call. It takes no lock and writes no checkpoint and no outputs. It needs a projection with `state:`. See [`CurrentProjection`](/docs/reference/projection/declarations#currentprojection).

- `current` reads pages until a page has no items. A growing input can delay the result.
- A `mapAccum` or `mapAccumBatch` handler computes the state, and `current` drops the emitted items.
- `current` reads a pinned unit again from the committed offsets, as part of the tail.
- With no checkpoint, `current` folds each input from the start. The handler must give the same result for any split of the input into pages.

### `Projection.decide`

```ts

```

`decide` calls [`current`](#projectioncurrent), passes the snapshot to `spec.decide`, and appends the items that it returns to the input that `spec.input` names. The append uses the offset of that input in the snapshot as `expectedOffset`. See [`DecideSpec`](/docs/reference/projection/declarations#decidespec).

- When `spec.decide` returns no items, `decide` writes nothing and does not check the tail. `appended` is `false`, and `offset` is the offset that `current` read.
- After a write, `appended` is `true`, and `offset` is the new tail.
- When its own append fails with `OffsetMismatch`, `decide` folds and decides again, while `spec.retry` allows. The default is `Schedule.recurs(3)`, so one call makes at most four appends. When the schedule ends, `decide` fails with the last `OffsetMismatch`.
- `decide` retries no other failure. An `OffsetMismatch` that `spec.decide` raises fails the call.

The package declares the error type as a longer conditional type. That type also names `LostRace`, a private class that `decide` removes from its errors, so it reduces to the union above.

`forget` deletes the checkpoint record of a bound projection through the `remove` of its Commit. It deletes no stream.

- When the Commit has no `remove`, `forget` fails with phase `checkpoint` and reason `unsupported-composition`. Every built-in Commit has `remove`.
- Stop the follower of the key first, or use a new generation.
- For a projection with outputs, delete the output streams first. The producer sequences of the outputs start again after `forget`.
