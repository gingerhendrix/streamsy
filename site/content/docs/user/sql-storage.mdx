title: SQL storage
description: Persist Streamsy protocol state with Effect SQL on Bun SQLite or inside a Durable Object.
---

`@streamsy/storage` implements the core `Storage` tag with a SQLite-family Effect
`SqlClient` using SQLite 3.42 or newer. Its root entry imports no host driver package. The host entries create one
shared SqlClient/Reactivity graph and expose both `Storage` and `CommitBoundary`.

## Bun SQLite

```ts
import * as SqlStorage from "@streamsy/storage/bun";
import * as BunHost from "@streamsy/serve/bun";

const host = await BunHost.serve({
  layer: SqlStorage.layerProtocol({
    client: { filename: "./streamsy.sqlite" },
  }),
  port: 3000,
});

await host.stop();
```

The Bun entry sets the synchronous driver busy timeout to zero unless you
explicitly override it. A standalone storage-owned transaction makes 16 total
attempts with a fixed 25 ms yielding delay, so its default scheduled-delay ceiling
is 375 ms. The previous driver default waited up to five seconds inside
`bun:sqlite`, blocking Bun's event loop. An explicit nonzero `busyTimeout` adds
that blocking wait to every attempt and to the shutdown bound.

`transactionRetryAttempts` and `transactionRetryDelayMs` configure the storage
owner. The default was measured under a separate-process writer lock with an
unrelated HTTP p95 below 1 ms and maximum below 4 ms on the acceptance machine;
the fixed acceptance budgets were 100 ms and 250 ms respectively. Treat these as
functional contention evidence, not a general throughput benchmark.
The read-only format preflight, WAL preparation and migrations use that same
bounded yielding policy during scoped Layer acquisition.

## Durable Object SQLite

```ts
import * as SqlStorage from "@streamsy/storage/durable-object";

const layer = SqlStorage.layer({ client: { storage: ctx.storage } });
```

Pass the full Durable Object storage handle, not only `ctx.storage.sql`, because
the official driver needs the transaction API. This is a local storage Layer;
the local host, routing, placement and alarms are described in [Cloudflare
hosting](/docs/user/cloudflare-hosting). Hosted execution and release evidence
remain pending.

## One truthful commit boundary

Application SQL and protocol mutation can commit together only through
`CommitBoundary.withTransaction`. Nested boundary calls join their outer owner,
and wakes publish after the outermost commit. A boundary or direct storage
mutation inside a foreign raw `SqlClient.withTransaction` defects before its
body or storage SQL executes. Raw ambient transactions receive no commit-wake
guarantee.

A returned `Rejected` value is still a successful Effect value. The low-level
boundary therefore commits unless the caller turns that rejection into a private
failure and recovers it only after leaving the boundary:

```ts
import { Data, Effect, Predicate } from "effect";
import { Storage, type Mutation, type MutationOutcome } from "@streamsy/core";
import { CommitBoundary } from "@streamsy/storage";
import * as SqlClient from "effect/unstable/sql/SqlClient";

class Rejected extends Data.TaggedError("Rejected")<{
  readonly outcome: Extract<MutationOutcome, { _tag: "Rejected" }>;
}> {}

declare const mutation: Mutation;

const program = Effect.gen(function* () {
  const boundary = yield* CommitBoundary;
  const storage = yield* Storage;
  const sql = yield* SqlClient.SqlClient;
  return yield* boundary
    .withTransaction(
      Effect.gen(function* () {
        yield* sql.unsafe("INSERT INTO application_rows(id) VALUES (?)", ["example"]);
        const result = yield* storage.mutate(mutation);
        if (Predicate.isTagged(result, "Rejected")) return yield* new Rejected({ outcome: result });
        return result;
      }),
    )
    .pipe(Effect.catchTag("Rejected", ({ outcome }) => Effect.succeed(outcome)));
});
```

The `catchTag` is outside `withTransaction`, so rejection first rolls back both
application and protocol writes. The future fused Commit Layer will own this
policy; it is not part of this low-level boundary. The caller also owns any retry
of this fused transaction. Nested storage mutation never retries independently.
Commit or rollback failure remains a defect and is never automatically replayed,
because commit acknowledgement failure is an uncertain outcome.

`BunStorage.layer` exposes its one official client alongside Storage and the
boundary. The compiled [packages/storage/test/shared-transaction-usage.ts](https://github.com/gingerhendrix/streamsy/blob/effect-first-live-perimeter/packages/storage/test/shared-transaction-usage.ts)
opens a real file, builds and closes the Layer scope, and proves the rejection
rolls back the application row:

```ts
/* oxlint-disable effecttsgo/node-builtin-import, eslint/no-underscore-dangle -- Executable documentation owns a temporary SQLite path and checks the public tagged outcome. */
import { mkdtemp, rm } from "node:fs/promises";
import { tmpdir } from "node:os";
import { join } from "node:path";
import { Context, Data, Effect, Exit, Layer, Predicate, Scope } from "effect";
import {
  Storage,
  StreamId,
  ZERO_OFFSET,
  type Mutation,
  type MutationOutcome,
} from "@streamsy/core";
import { CommitBoundary } from "@streamsy/storage";
import * as BunStorage from "@streamsy/storage/bun";
import * as SqlClient from "effect/unstable/sql/SqlClient";

class Rejected extends Data.TaggedError("Rejected")<{
  readonly outcome: Extract<MutationOutcome, { readonly _tag: "Rejected" }>;
}> {}

const id = StreamId.make("compiled-shared-transaction");
const create: Mutation = {
  operations: [
    {
      _tag: "Create",
      record: {
        id,
        config: { contentType: "text/plain", createdAt: 0 },
        lifecycle: { closed: false, softDeleted: false },
        currentOffset: ZERO_OFFSET,
      },
      initialMessages: [],
    },
  ],
};

const directory = await mkdtemp(join(tmpdir(), "streamsy-sql-example-"));
const scope = await Effect.runPromise(Scope.make());
try {
  const context = await Effect.runPromise(
    Layer.buildWithScope(
      BunStorage.layer({ client: { filename: join(directory, "streamsy.sqlite") } }),
      scope,
    ),
  );
  const sql = Context.get(context, SqlClient.SqlClient);
  const result = await Effect.runPromise(
    Effect.gen(function* () {
      const storage = yield* Storage;
      const boundary = yield* CommitBoundary;
      yield* sql.unsafe("CREATE TABLE application_rows(id TEXT PRIMARY KEY)");
      yield* storage.mutate(create);
      const outcome = yield* boundary
        .withTransaction(
          Effect.gen(function* () {
            yield* sql.unsafe("INSERT INTO application_rows VALUES ('rolled-back')");
            const mutation = yield* storage.mutate(create);
            if (Predicate.isTagged(mutation, "Rejected"))
              return yield* new Rejected({ outcome: mutation });
            return mutation;
          }),
        )
        .pipe(Effect.catchTag("Rejected", ({ outcome: rejection }) => Effect.succeed(rejection)));
      const rows = yield* sql.unsafe<{ readonly id: string }>("SELECT id FROM application_rows");
      return { outcome, rows };
    }).pipe(Effect.provide(context)),
  );
  if (result.outcome._tag !== "Rejected" || result.rows.length !== 0)
    throw new Error("shared transaction did not roll back rejection");
} finally {
  await Effect.runPromise(Scope.close(scope, Exit.void));
  await rm(directory, { recursive: true, force: true });
}
```

Each `Storage.changes` subscription owns one capacity-1 payload-free dropping
queue. Registration happens before the initial authoritative SQL read. Local
commits wake the shared Reactivity graph; a scoped repair rereads every 1,000 ms
by default. That interval is the cross-process staleness bound and covers the
small interruption window between commit and local invalidation. Set a positive
finite `repairIntervalMs` when a different bound is required.

## Fresh-format files

Only fresh 0.4-format databases and supported upgrades of that format are
accepted. Pre-0.4 files and newer unknown versions are rejected without schema
mutation. The dedicated migrator records new-format versions in
`streamsy_storage_schema_version`. Streamsy does not import, reset or delete
unsupported files. See the
[0.4 migration note](https://github.com/gingerhendrix/streamsy/blob/effect-first-live-perimeter/docs/migration-0.4.md).
