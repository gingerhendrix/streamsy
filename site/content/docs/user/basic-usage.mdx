Use `@streamsy/core` and Effect 4.0.0-rc.112 at the server or toolkit boundary.
A `StreamRef` describes an id and Schema; it owns no resources.

## Create, append, read and follow

Compiled source: [packages/serve/test/basic-usage.ts](https://github.com/gingerhendrix/streamsy/blob/effect-first-live-perimeter/packages/serve/test/basic-usage.ts).

This complete program runs under the
serve package typecheck. The example handles create and append classifications
before reading; a successful Effect alone does not mean an append was accepted.

```ts
import { Effect, Schema, Stream } from "effect";
import { Streams, StreamRef } from "@streamsy/core";

const events = StreamRef.json("events", {
  schema: Schema.Struct({ text: Schema.String }),
});
const program = Effect.gen(function* () {
  const created = yield* Streams.create(events);
  if (created.status !== "created" && created.status !== "exists") return created;
  const appended = yield* Streams.append(events, [{ text: "hello" }]);
  if (appended.status !== "appended") return appended;
  const batches = yield* Streams.read(events).pipe(Stream.runCollect);
  const first = yield* Streams.follow(events).pipe(
    Streams.items,
    Stream.take(1),
    Stream.runCollect,
  );
  return { batches, first };
});
await Effect.runPromise(program.pipe(Effect.provide(Streams.layerMemory())));
```

`read` catches up in batches with a next offset. `follow` first catches up, then
waits for new batches; `Streams.items` flattens their items. Here `take(1)` bounds
the follow to the seeded item so the example terminates. A live consumer must
have an owning scope and an explicit shutdown policy.

The one provided memory Layer holds data for this program's lifetime. Reusing a
Layer description across separate runtime acquisitions does not share a store.
Use one application runtime and dispose it when the application stops.

## Serve with Bun

Compiled source: [packages/serve/test/host.ts](https://github.com/gingerhendrix/streamsy/blob/effect-first-live-perimeter/packages/serve/test/host.ts).

The Bun host owns its listener and HTTP edge.
This finite example requests a free local port, creates a stream over HTTP, checks
the response and closes the host. A running application keeps the host until shutdown.

```ts
import { Streams } from "@streamsy/core";
import * as BunHost from "@streamsy/serve/bun";

const host = await BunHost.serve({ layer: Streams.layerMemory(), port: 0 });
try {
  const response = await fetch(new URL("/streams/events", host.url), {
    method: "PUT",
    headers: { "content-type": "application/json" },
  });
  if (response.status !== 201) throw new Error(`Create failed: ${response.status}`);
} finally {
  await host.stop();
}
```

The host's Layer is a separate memory store from the program above. Browser
applications connect over HTTP using official Durable Streams packages.
See [the HN demo](/docs/demos/hackernews-newest-stream) for the complete browser path,
and [concepts](/docs/user/concepts#outcomes-and-faults) for failure handling. For
the local Durable Object host, see [Cloudflare hosting](/docs/user/cloudflare-hosting).
