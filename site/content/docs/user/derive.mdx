---
title: Derive
description: Pure stateful projections with one fused host-local commit.
---

`@streamsy/derive` projects one retained source into one dedicated sink. A pure
step computes next state and zero or more outputs. Each accepted boundary saves
output, state and source progress in one transaction.

The public surface includes `Source`, `Sink`, `Projection.make`,
`Projection.catchUp` and scoped `Projection.follow`. Host adapters support memory,
Bun SQLite and SQLite within the same Durable Object. The kernel is:

```text
restore → pull → pure step → fused commit
```

Use `@streamsy/derive/memory` for the complete memory Layer, or
`@streamsy/derive/sqlite` with the same owned SQL client and commit boundary as the
stream services. A new projection on a persistent host resumes from its stored
checkpoint. A filtered boundary still advances state and source progress.

Catch-up has explicit boundary, item and optional reported-byte limits. Follow
uses scoped waits and periodic bounded repair. Stable identity includes the
projection id, version, source, sink and fixed `v{version}` generation. Identity
or state decoding failures stop; they never reset stored progress automatically.

Retained source history and one host owner are required. Remote sinks, snapshots,
online generation activation, routing, fencing and causal serving coverage are
outside this foundation. There is no `syncedThrough` claim.

See the [package guide and compiled example](https://github.com/gingerhendrix/streamsy/tree/main/packages/derive)
for contracts, Layer composition and operational limits.
